# 模型证据投影作为唯一协议解析处规格

Status: ready-for-agent

## Problem Statement

同一条模型请求记录的消息数与工具数目前由两套互不相关的实现给出,而它们在同一屏上同时显示。模型请求详情顶部的概览格用模型请求记录自己的摘要派生逻辑,模型请求对话视图用共享模型证据投影,两者读的是同一份请求体,给出的数字却不同。

已核实的分歧覆盖五种真实请求形状中的四种:Anthropic 的顶层 system 与请求消息并存时,概览格报 1 条消息而分析页报 2 条;Responses 的 input 容器在概览格里被读成 0 条消息、0 个工具;AI SDK 以工具名作对象键声明工具定义时概览格报 0 个;旧式 function 声明同样报 0 个;Gemini 的 systemInstruction 与 contents 并存时概览格再次少算一条消息。摘要派生逻辑的注释本身就记录过同类缺陷复发过一次——第一次是只读 OpenAI 字段把 Gemini 请求误报成 0 条消息。

同一份协议知识还在另外两处被重复实现:模型请求采集器从请求体与规范化请求地址推断模型名称,而模型请求详情视图逐字复制了同一段推断,包括同一个正则。采集器在写入记录时就已经把模型名称固化进记录,所以视图那一份只对更早写入的记录有意义,而本仓库在首次公开发布前不保留这类兼容 fallback。

用户因此无法确信详情页顶部的数字描述的是模型实际收到的上下文;维护者每接入一种新协议形状都必须在三个 module 里分别修改,而只有其中一个 module 有协议测试。

## Solution

让共享模型证据投影成为唯一从请求体读取协议结构的 module,概览格的计数改为它的派生产物。

模型请求记录的读取投影不再自行解释协议:详情读取路径调用共享模型证据投影一次,从它的请求消息与工具定义直接得出计数,并把同一份投影转交给模型请求变量派生,使一次详情读取只运行一次投影。请求消息计数与工具定义计数因此与模型请求对话视图、模型请求轨迹使用完全相同的消息边界和工具展平规则,包括把 Gemini 的函数声明展平成独立工具定义。

原始请求体的字段数不是协议事实,它继续由模型请求记录自己提供,并明确标记为原始 JSON 事实而不是投影产物。模型名称同样继续是采集那一刻观察到的记录事实,不进入投影;模型请求详情视图那份重复推断直接删除,视图改读记录字段。

摘要不再随列表项下发。列表视图从不显示这些计数,却为每页最多两百条记录各派生一次然后丢弃;去掉后列表读取路径不再运行任何协议派生。

未观察与观察到零被明确区分。请求体未采集时不产生计数,概览格显示占位符而不是零;请求体已采集但不是对象时,投影确实运行且确实为零,概览格显示零,与模型请求对话视图那句"未识别请求体中的对话结构"口径一致。

## Implementation Decisions

### 类型与契约

- 删除模型请求摘要类型。它现在混装一个原始 JSON 事实与两个投影派生事实,名称掩盖了来源差异。
- 新增模型证据计数类型,只含请求消息计数与工具定义计数两个字段,字段名直接采用领域词汇「请求消息」与「工具定义」。
- 模型请求列表项去掉摘要字段。
- 模型请求详情新增两个可选字段:原始请求体字段数,与模型证据计数。两者都可缺省,缺省表示未观察。
- Console 侧的模型请求列表项与详情类型是纯交叉类型,形状变化自动跟随,无需单独修改。
- 摘要字段中的请求体可用标记直接删除:它零消费者,且模型请求记录本身已有请求体可用字段在服务真实判断。

### 三种请求体状态

| 请求体状态 | 原始请求体字段数 | 模型证据计数 | 概览格显示 |
| --- | --- | --- | --- |
| 未采集 | 缺省 | 缺省 | 三格均为占位符 |
| 已采集但不是对象 | 缺省 | 请求消息 0、工具定义 0 | 字段占位符,消息与工具为零 |
| 已采集且是对象 | 键数量 | 投影派生的真实数量 | 三格真实数字 |

未采集时不运行投影。非对象时运行投影,投影自身返回请求体不支持诊断,该诊断继续由模型请求对话视图消费,概览格不重复呈现诊断。

### 服务端读取路径

- 模型请求记录的读取投影删除自己的协议分支实现。
- 详情分支在请求体存在时调用共享模型证据投影一次,且只传入请求体——不传响应原文与响应 transport 格式。已核实模型请求变量派生只读投影的请求消息,详情路径上没有任何消费者需要响应侧投影,因此这一路径不再解析流式原文。
- 详情分支把同一份投影转交模型请求变量派生,由读取投影成为唯一决定是否运行投影的地方。
- 列表分支不再调用任何派生逻辑。
- 模型请求变量派生的 interface 收窄为运行时预设快照与模型证据投影两个入参,不再接收整条记录。原本由它内部执行的"无快照或无请求体则返回空"判断上移到调用方。
- 模型请求采集器保持不变。模型名称是采集那一刻观察到的记录事实,不是协议投影的产物;把它改为读时派生会迫使列表按模型过滤时运行全量投影,而列表过滤是外部测试控制器与界面都依赖的能力。

### 客户端

- 模型请求详情视图删除自己的模型名称推断,改读记录字段。采集器在写入时已保证新记录带有该值,依未发布阶段兼容策略不为更早记录保留 fallback。
- 概览格三格改读新字段,缺省时显示占位符。
- 概览格文案不变,不改为「请求消息」「工具定义」:本次改动修正确性,不动文案。
- 客户端不新增任何 module 承载"三态到显示文本"的转换。该转换只是一次缺省合并,抽成 module 后删除它只会把复杂度搬家而不是集中,属于 shallow module。
- 客户端工作区端口的假实现去掉摘要构造。

### 对外契约

- 测试控制端点的模型请求列表与详情工具原样返回读取投影结果,没有字段裁剪,因此上述形状变化对外可见。
- 依未发布阶段兼容策略直接变更,不加兼容层、不并行两套字段、不递增测试控制 API 版本。递增版本会给未来读者留下"曾存在外部契约"的错误信号。

## Testing Decisions

### 什么算好测试

只断言从 interface 观察得到的外部行为:给定一份请求体,读取路径给出哪些计数、哪些字段缺省。不断言实现内部调用了什么、调用了几次,也不断言源码文本。

尤其不接受把生产函数当 oracle:期望值必须是逐 fixture 硬编码的字面量,而不是与共享模型证据投影的数组长度作比较。后者与实现同源,退化为恒等断言,投影本身回退时会跟着一起错——本仓库已有同类反模式的先例。

### 主 seam

模型请求记录存储的读取入口(单条读取与分页读取)。这是覆盖本规格全部服务端行为的最高既有 seam:列表项不再携带计数、详情携带两个新字段、三种请求体状态各自的取值都能从这里观察。不新增 seam。

Prior art:现有模型请求记录测试已经通过该存储的读取入口断言摘要字段,本次改断言即可,不必下降到读取投影函数本身。

### 辅 seam

模型请求变量派生函数。仅用于证明 interface 收窄后行为不变。Prior art:现有模型请求变量测试已直接调用它。

### 协议形状回归表

复用现有模型协议 fixture 的五种请求形状(OpenAI Chat Completions、Responses、Anthropic Messages、Gemini generateContent、AI SDK),并补一个旧式 function 声明 fixture。每种形状断言固定的请求消息计数与工具定义计数字面量。这张表是本次修复的全部证据,不钉住它,同类缺陷会第三次复发。

### 三态测试

未采集、已采集非对象、已采集对象三种状态各一个用例,断言字段缺省与取零的区别。

### 客户端

不新增客户端行为测试。概览格三态没有可测 interface,而唯一可抽出的 module 是 shallow 的;依既有决策不引入 jsdom、happy-dom 或组件挂载测试,真实渲染由浏览器手工验证承担。

现有模型请求工作台测试中断言摘要字段路径的源码字符串断言需要同步修正,否则它们会因字段改名而假红。

### 验收

单元测试、类型检查与构建全绿,外加一次浏览器确认:概览格三格正常渲染;证据种类过滤器全开时概览格与模型请求对话视图数字一致;一条请求体不可用的记录显示占位符。

不做逐协议的浏览器验证:在真实环境凑出五种协议形状需要分别接上各家上游,协议矩阵由回归表承担。

## Out of Scope

- 概览格暴露模型证据投影的结构化诊断。诊断已由模型请求对话视图消费,新增一格属于界面范围扩张,应单独提出。
- 模型请求对话视图内部消息计数与工具计数口径不一致。该视图的消息数显示过滤后数量、工具数显示全量数量,病因是同一视图内两处口径不同,与本规格要修的"投影之外重复解析协议"不同,单列。
- 模型请求轨迹中零引用的状态文案函数。纯删除、零风险,但属于另一条候选,不混入本规格的改动。
- 模型证据投影按记录身份的记忆化。模型请求轨迹目前仍为每条记录各运行一次投影,自动刷新期间同时读取详情与轨迹会重复运行;本规格只把详情路径从两次降到一次,不引入缓存。
- 预设表达式观察值在服务端算完即返回。它同样属于"投影边缘"问题,但改的是另一条读取路径与另一个对外结果类型,单列。
- 采集器侧的模型名称推断。它是写时事实,本规格只删客户端那份重复。
- 概览格文案、图标与布局调整。

## Further Notes

- 本规格是既有架构决策的补齐而不是新决策:共享模型证据投影是唯一理解各家协议结构的 module 这一条已经记录在案,本次只是把三处漏迁的实现收回来。因此不新增架构决策记录,也不新增领域词汇——「请求消息」与「工具定义」已在领域词汇表中。
- 需要在共享模型证据投影的唯一对外入口注释里,把模型名称与原始 JSON 字段数补进"不参与协议识别"的清单。这两项是故意留在投影之外的边界,将来会被重新提起。
- 摘要形状变化会触及九个测试文件中的记录构造。其中多数是列表项构造,按本规格直接删除摘要字段即可,属于减法而非改写。
- 分支与提交:依仓库规则不自行创建分支、不自行提交,改动留在当前工作区等待确认。
