# 01 — 收窄模型请求变量派生的 interface,详情读取只运行一次投影

**What to build:** 模型请求详情的读取路径成为唯一决定是否运行共享模型证据投影的地方,并且一次详情读取只运行一次投影、不解析响应原文。

模型请求变量派生目前自己调用共享模型证据投影,并为此接收整条模型请求记录——包括请求体、响应原文与响应 transport 格式三个它并不解释的字段。它实际只读投影的请求消息。把它的 interface 收窄为运行时预设快照与一份已算好的模型证据投影两个入参;"没有运行时预设快照或没有请求体就没有变量"这条判断上移到调用方。

模型请求记录的读取投影在详情分支里运行投影一次,并且只传入请求体。已核实详情路径上没有任何消费者需要响应侧投影,因此这条路径不再为无人使用的响应事件解析流式原文。

对外可观察行为零变化:模型请求变量仍然正确关联到请求消息,预设表达式的观察值不受影响。这张票是后续「概览格计数改由共享模型证据投影派生」的 prefactor——完成后投影已经在读取路径手上,那张票只需读两个长度。
