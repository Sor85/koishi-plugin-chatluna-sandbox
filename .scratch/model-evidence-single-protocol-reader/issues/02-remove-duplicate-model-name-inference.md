# 02 — 删除模型请求详情视图里重复的模型名称推断

**What to build:** 模型请求详情页的模型名称只有一处实现——模型请求采集器在写入记录时观察到的那个值。

模型请求详情视图目前自己又推断了一遍模型名称:先读请求体的模型字段与 Gemini 的模型版本字段,再从规范化请求地址上用正则回退提取。这段逻辑与采集器里的那一份逐字相同,包括同一个从请求地址路径提取模型标识的正则。采集器在记录写入时就已经把结果固化进模型请求记录,所以视图那一份只对更早写入的记录有意义,而本仓库在首次公开发布前不为这类情况保留 fallback。

删掉视图那份推断,改读记录字段。模型名称属于采集那一刻观察到的记录事实,不进入共享模型证据投影——把它改为读时派生会迫使按模型过滤列表时运行全量投影,而列表过滤是模型请求工作台与外部测试控制器都依赖的能力。

用户观察到的显示行为不变:记录带有模型名称时显示该名称,没有时显示未识别。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 模型请求详情视图不再包含任何从请求体或请求地址推断模型名称的逻辑
- [ ] 详情页模型名称改读模型请求记录字段,缺省时显示未识别
- [ ] 模型请求采集器侧的推断保持不变
- [ ] 现有模型请求工作台测试中断言该推断存在的源码字符串断言同步移除
- [ ] 单元测试、类型检查与构建全绿
- [ ] 浏览器确认:打开一条已有模型请求详情,模型名称显示与改动前一致
