# 03 — 概览格计数改由共享模型证据投影派生

**What to build:** 模型请求详情顶部概览格显示的消息数与工具数,与模型请求对话视图描述的是同一份证据。

概览格目前由模型请求记录自己的摘要派生逻辑供数,它只认部分协议容器。已核实五种真实请求形状中有四种与模型请求对话视图给出不同数字:Anthropic 顶层 system 与请求消息并存时少算一条;Responses 的 input 容器被读成零条消息、零个工具;AI SDK 以工具名作对象键声明工具定义时读成零个;旧式 function 声明同样读成零个;Gemini 的 systemInstruction 与 contents 并存时少算一条。两个数字同时显示在一屏上。

改为由共享模型证据投影派生请求消息计数与工具定义计数,包括把 Gemini 的函数声明展平成独立工具定义。摘要类型整体删除,不保留空壳。原始请求体的字段数继续由模型请求记录提供,并明确标记为原始 JSON 事实而不是投影产物;摘要里那个请求体可用标记直接删除——它零消费者,记录本身已有请求体可用字段承担真实判断。

计数不再随列表项下发。列表视图从不显示它们,却为每页最多两百条记录各派生一次然后丢弃;去掉后列表读取路径不运行任何协议派生。

未观察与观察到零被明确区分:

| 请求体状态 | 原始请求体字段数 | 请求消息计数 | 工具定义计数 |
| --- | --- | --- | --- |
| 未采集 | 缺省 | 缺省 | 缺省 |
| 已采集但不是对象 | 缺省 | 0 | 0 |
| 已采集且是对象 | 键数量 | 真实数量 | 真实数量 |

概览格对缺省显示占位符而不是零。非对象一态显示零是诚实的——投影确实运行过且结果为空,这与模型请求对话视图那句"未识别请求体中的对话结构"口径一致。

概览格计数不随证据种类过滤器变化:它陈述这条记录的事实,不是当前视图的子集。概览格文案与布局不变。

测试控制端点的模型请求列表与详情工具原样返回读取投影结果,因此上述形状变化对外可见。依未发布阶段兼容策略直接变更,不加兼容层、不并行两套字段、不递增测试控制 API 版本。

**Blocked by:** 01 — 收窄模型请求变量派生的 interface,详情读取只运行一次投影

**Status:** ready-for-agent

- [ ] 原始请求体字段数作为独立字段提供,不与投影派生的计数混装在同一个对象里

- [ ] 模型请求列表项不再携带任何计数;列表读取路径不运行协议派生

- [ ] 概览格三格在缺省时显示占位符,在非对象一态显示零
