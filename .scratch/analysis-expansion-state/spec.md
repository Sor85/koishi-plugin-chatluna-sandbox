# 展开态与原文态成为第四个 module，分析视图只剩渲染

Status: ready-for-agent

## Problem Statement

模型请求分析视图里，「哪张卡折叠、哪段看原文、哪一处展开」这一组状态由十个反应式引用直接住在组件里。没有 module 拥有它们，因此只能连着组件一起测。

这个视图旁边已经有三个 module 各自拥有一个概念：证据定位拥有「最终停在哪」，证据导航拥有「从哪来、怎么回去」，模型请求分析投影拥有「证据分组与统计」。前两个在领域词汇里都有定义，各自还有一条架构决定记录理由。展开态是第四个概念，没有主人。

后果是两条会静默坏掉的规则今天只写在注释里：

- **原文一旦挂载就留着。** 切某条消息看原文会为它构造整棵 JSON 树，切回格式化内容时树留在 DOM 里，因此树内的展开状态不丢；而从未被切开的消息不会为它构造整棵树。这条由两个 watcher 累加两个集合来表达。改坏了要么切回去时丢掉展开态，要么每条消息都急切建树、读取代价随请求体线性上升。
- **搜索命中时的展开用集合替换而不是逐条展开。** 逐条展开会为每一条命中复制一次整个集合。这条成本结构写在实现里，没有任何断言。

还有一段十四行的手写复位：切换到另一条模型请求记录时逐项清掉十个状态。漏掉一项的表现是上一条记录的展开态残留到下一条，不报错。

## Solution

把这十个状态与它们的转换规则收成第四个 module：无 DOM、无渲染依赖，可以直接驱动。

组件里那份证据定位 adapter 退成纯转发——它的八项操作从「内联闭包直接改引用」变成「转调 module」。定位器继续拥有展开决策与它自己那两项状态，新 module 只拥有展开态。

用户看不到任何变化。折叠、展开、看原文、搜索命中后的展开、切换记录后的复位，全部与今天一字不差。

治理之后：那五条规则第一次能不起组件就测；「点了展开却没展开」「跳过来之后原文没展开」这类问题只看一处；分析视图变薄，改布局与样式时更容易找到自己要动的那一段。

## User Stories

1. As a 沙盒用户, I want 折叠与展开一张证据卡的行为一字不变, so that 一次内部整理不需要我重新验收界面
2. As a 沙盒用户, I want 切某条消息看原始 JSON 再切回格式化内容时，树内已经展开的层级还在, so that 我不必重新一层层点开
3. As a 沙盒用户, I want 从未看过原文的消息不为它急切构造整棵树, so that 打开一条大请求的分析不变慢
4. As a 沙盒用户, I want 切换响应原文与展开历史变量原文的行为一字不变, so that 我读证据的习惯不受影响
5. As a 沙盒用户, I want 搜索命中时相关的卡片与工具自动展开, so that 我不必手动找命中在哪
6. As a 沙盒用户, I want 搜索一个很长的请求体时不变卡, so that 输入不掉帧
7. As a 沙盒用户, I want 折叠导航分组的行为一字不变, so that 左侧导航仍按我的习惯工作
8. As a 沙盒用户, I want 切换到另一条模型请求记录后展开态全部回到初始, so that 我不会看到上一条记录残留的展开状态
9. As a 沙盒用户, I want 从别处跳过来定位一条证据时，那张卡被展开、必要时切到原文, so that 我一眼就能看到要看的东西
10. As a 沙盒用户, I want 定位后的高亮与当前命中仍然由定位器管, so that 跳转与返回的体验不变
11. As a 沙盒用户, I want 卡片标题上双击选词、拖选复制、工具摘要拖选这些细节不变, so that 我复制证据文本时不会误触折叠
12. As a 插件维护者, I want 展开态有一个 module 拥有它, so that 它不再只能连着组件一起测
13. As a 插件维护者, I want 这个 module 无 DOM 依赖, so that 五条规则可以用普通单元测试驱动
14. As a 插件维护者, I want 「原文一旦挂载就留着」有断言, so that 丢展开态这类回归能被测出来
15. As a 插件维护者, I want 「从未切开的消息不进已挂载集合」有断言, so that 读取代价那一半也被压住
16. As a 插件维护者, I want 「搜索命中用集合替换而不是逐条展开」有断言, so that 成本结构不只写在注释里
17. As a 插件维护者, I want 「切原文时顺带展开那张卡」有断言, so that 跳过来之后原文没展开这类问题有红灯
18. As a 插件维护者, I want 「切换记录时十项全部复位」成为一条可断言的事实, so that 漏掉一项不再靠人点出来
19. As a 插件维护者, I want 定位器那两项状态留在定位器, so that 它的复位不被拆到两个主人手里
20. As a 插件维护者, I want 证据定位 adapter 的 seam 形状一行不改, so that 已有的那条架构决定不被动
21. As a 插件维护者, I want 不借机合并证据定位与证据导航, so that 两条各自记录了理由的决定不被推翻
22. As a 插件维护者, I want JSON 树缓存留在组件里, so that 渲染缓存不被当成视图状态搬走
23. As a 插件维护者, I want 指针与选区守卫留在组件里, so that DOM 细节不进无 DOM 的 module
24. As a 插件维护者, I want 两条断言豁免从未治理挪到已消化, so that 治理进度反映真实状态
25. As a 插件维护者, I want 第三条豁免的负责人改指向真正能消化它的候选, so that 下一轮不会有人白花一次
26. As a 插件维护者, I want 界面渲染在治理前后逐像素一致, so that 「行为没变」不是一句口头承诺
27. As a 插件维护者, I want 服务端一行不改并且可以用 diff 证明, so that 这一轮确实只发生在客户端

## Implementation Decisions

### 搬十个状态，不是十二个

- 新 module 拥有的正是组件那段复位块里清掉的十项：响应原文、消息原文、两个「已挂载」集合、历史变量原文、折叠卡片、展开工具、强制展开文本、折叠导航分组、当前导航目标。
- 另外两项——定位高亮与当前命中——**留在证据定位器**。它们不在组件的复位清单里，起初看像是漏掉，核过之后确认不是：定位器的复位自己就会清掉这两项。它们的整个生命周期（写入与复位）都是定位器的，搬进新 module 会把定位器的复位拆到两个主人手里。
- 换句话说，这条线今天已经画在正确的位置，只是没被表达成 module。报告里「十二个引用都归新 module」这条判断不成立。

### module 拥有状态，定位器继续拥有决策

- 证据定位那条既有决定不动：adapter 仍是唯一的 DOM、渲染状态与计时出口，测量仍只交出元素顶、滚动容器顶与当前滚动量三个数字，滚动容器的选择规则仍留在视图侧。
- 变的只有 adapter 里八项操作的实现：展开卡片、展开工具、读写消息原文、读写响应原文、读写强制展开文本、从「内联闭包直接改引用」变成「转调 module」。seam 的形状与实现数量都不变。
- 定位器拥有「展开决策」（什么时候该展开、什么时候该切原文），新 module 拥有「展开态」。决策与状态分离，不是把定位器的一半搬走。

### 无 DOM，与已有的三个邻居同形

- 新 module 不触碰 DOM、不需要任何环境，普通单元测试即可驱动。这与「有状态但与 DOM 无关的行为住在反应式 module 里」这条既有决定同形，新 module 是它的第四个实例而不是一条新决定。
- 因此不写新的架构决定记录，也不给领域词汇加新词：展开态与原文态是界面状态而不是领域概念。

### 明确不合并证据定位与证据导航

- 领域词汇把两者分开，各自还有一条架构决定记录理由：导航拥有「从哪来、何时到、怎么回去」，定位拥有「最终停在哪」，两者通过一个带序号的定位请求相接。
- 新 module 是第四个概念，不是三者的合并。DOM 展开与测量继续走现有的定位 adapter。

### 留在组件里的东西

- **指针与选区守卫**三处：卡片标题第二次按下时阻止浏览器按单词选中但保留单击折叠与拖选复制；工具摘要按位移区分拖选与折叠；标题上有选区或点到按钮时不折叠。它们读窗口选区与事件目标，属于 DOM 细节。
- **导航跟踪与滚动**：可见性跟踪、滚动容器与目标元素的解析、滚动到目标。
- **JSON 树缓存**：它是一个普通 Map 加「会话投影变化时整体失效」，不是反应式状态，失效条件也与展开态无关——它是渲染缓存而不是视图状态。
- 搜索命中后的跳转仍留在组件（它要滚动），但「哪些卡片与工具因命中而展开」这一半是纯状态转换，进 module。

### 复位是一条关于全部十项的事实

- 切换到另一条模型请求记录时，十项全部回到初始。今天这是十四行手写赋值，漏掉一项不报错。
- 收进 module 之后它变成一次调用，并且是一条可断言的事实。组件那一侧仍然负责调用定位器的复位与把滚动容器归零——那两件事不属于展开态。

### 断言豁免与棘轮

- 两条从「未治理」挪到「已消化」那一组，棘轮相应减二（棘轮不数已消化那一组）。
- 第三条的负责人改指向一条新的待开候选「模型请求工作台外壳行为下沉」。它的二十三处源码断言里**零处**涉及这十个状态——它断言的是外层工作台组件，本轮下沉消化不了它。留着现在的负责人会让下一轮有人照着做一遍才发现，白花一次。

## Testing Decisions

好的测试断言外部可观察的行为，而不是实现写法。本仓库的判据已经写下来了：肯定式实现细节断言在等价重构时变红、在真实回归时沉默。本规格不新增任何一条这样的断言。

**净新增 seam 数：一个。** 目的是让五条今天只写在注释里、或只以源码断言形式存在的规则变得可驱动。

### 主测试面

- **新 module 自身的 interface（新增 seam）**。纯反应式、不触碰 DOM、不需要任何环境，普通单元测试即可驱动。先例是这个视图旁边那三个 module 各自的测试——证据定位（数字化的假 adapter）、证据导航、模型请求分析投影。
- **模型请求分析投影的既有 seam**。这一族已有的行为断言（导航分组、搜索文本、统计）一字不改地继续通过，是回归网。
- **读取代价的既有 seam**。已有一份针对读取放大的测试，其中两处涉及「已挂载」这组状态；下沉后那条规则改由 module 的断言执行，读取代价那一份保留它的成本断言。
- **架构守卫（既有 seam）**。断言豁免清单与棘轮在这里，本轮要改三条条目。

### 要补的断言

- 切原文时顺带展开那张卡。
- 原文一旦挂载就登记为已挂载；切回格式化内容后仍在已挂载集合里。
- 从未切开的消息不进已挂载集合（读取代价那一半）。
- 搜索命中时展开卡片与工具，且用集合替换而不是逐条展开。
- 切换记录时十项全部复位。
- 折叠导航分组这一条简单转换。

### 不新增的断言

- 不为「哪十项归 module」写形状断言：那是肯定式实现细节断言，等价重构时变红。它由复位那条行为断言从外部证明。
- 不为定位器 adapter 的八项转发写断言：转发本身没有行为，定位行为由既有的定位测试执行。

### 纯结构性的证明

- **DOM 快照**。这一轮的可观察结果是渲染而不是模型——分析视图是组件，没有可导出的模型。采样点覆盖十种交互：初始渲染、折叠一张卡、展开一个工具、切某条消息看原文、再切回格式化、切响应原文、展开历史变量原文、搜索命中后的展开态、折叠一个导航分组、切换到另一条记录（验复位）。
- 按项目的浏览器兼容规则，**Chromium 与 Firefox 各跑一次**。
- **完整测试、类型检查与构建通过。**
- **`git diff --stat` 里不出现服务端源码路径。** 本轮服务端一行不改。
- 每张票各跑一次。基线作为票的证据留在本 feature 目录下；浏览器会话与临时目录按仓库规则在验收后清理。

### 别处变红的处置

改组件会让读它源码的断言变红。逐条区分真红与假红——标识符变化跟着改是假红，行为口径或成本结构变化是真红，停下来查——并在票的 Comments 里逐条记处置。**不重判前几轮已经判定保留的断言**，改之前先读那条块注释。

## Out of Scope

- **把定位高亮与当前命中搬进新 module。** 它们的写入与复位都是定位器的，搬走会把定位器的复位拆到两个主人手里。
- **合并证据定位与证据导航。** 两条各自记录了理由的决定，本轮无权推翻。
- **JSON 树缓存。** 渲染缓存而不是视图状态。
- **指针与选区守卫、导航跟踪与滚动。** DOM 细节留在组件。
- **外层模型请求工作台的行为。** 它的断言豁免本轮只改负责人，不做下沉。
- **分析视图的样式、布局、文案与交互。** 本轮没有行为变化，一处例外都没有。
- **服务端的任何改动。**
- **引入组件挂载测试。** 已记录在案的决定。

## Further Notes

- 最值得做的不是少十个引用，而是两条今天只写在注释里的规则变成可断言的事实。两条都改坏了不报错：一条表现为切回格式化内容时树内展开态丢了，一条表现为打开大请求的分析变慢——前者是功能退化，后者是成本退化，都没有红灯。
- 第二值得的是那段十四行手写复位。它是「漏掉一项不报错」的典型：漏掉的表现是上一条记录的展开态残留到下一条，而十项里任何一项都可能被漏。收进 module 之后它是一条断言。
- 核查时最重要的一个发现是**该搬的是十个而不是十二个**，而这条线今天已经画对了：组件复位块里那十项正是该搬的，不在清单里的两项正是定位器自己会复位的。报告的分组把定位器的状态也算了进来；照它做会削弱一条明确不该动的 seam。
- 「豁免可消化两条而不是三条」也是核查的结果。第三条的负责人指向本候选，但它断言的是外层工作台组件，二十三处源码断言里零处涉及这十个状态。改一条负责人本身是收益。
- 这一轮的证明手段回到 DOM 快照。前几轮服务端的轮次都能用导出比对，客户端上一轮拆端口时用的是工作台模型——但分析视图没有模型，它的对外事实就是渲染结果。
