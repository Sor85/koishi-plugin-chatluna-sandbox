## Sourced facts

### 1. Preset editing and persistence

#### ChatLuna core presets

- `PresetService.resolvePresetDir()` stores user presets under `data/chathub/presets`. `loadAllPreset()` reads `.txt` and `.yml` files, parses each with `loadPreset()`, retains the source path, and `watchPreset()` hot-reloads file changes. Defaults are copied from the packaged resources directory when needed. ([`packages/core/src/preset.ts`: `PresetService.loadAllPreset`, `watchPreset`, `resolvePresetDir`, `_copyDefaultPresets`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/preset.ts))
- The parsed `PresetTemplate` keeps both structured fields and the original YAML text in `rawText`; it contains `triggerKeyword`, typed LangChain `messages`, optional `formatUserPromptString`, lore books, author note, knowledge, config, and runtime `path`. ([`packages/core/src/llm-core/prompt/preset_prompt_parse.ts`: `loadYamlPreset`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/llm-core/prompt/preset_prompt_parse.ts), [`packages/core/src/llm-core/prompt/type.ts`: `PresetTemplate`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/llm-core/prompt/type.ts))
- The built-in editing surface is command/file based, not a general Console editor:
  - `chatluna.preset.add` creates YAML with one system prompt and writes `<name>.yml`. ([`packages/core/src/commands/preset.ts`: `apply`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/commands/preset.ts), [`packages/core/src/middlewares/preset/add_preset.ts`: `apply`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/middlewares/preset/add_preset.ts))
  - `chatluna.preset.set` only supports presets with one message; it parses `rawText`, replaces `prompts[0].content`, then rewrites the same file. ([`packages/core/src/middlewares/preset/set_preset.ts`: `apply`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/middlewares/preset/set_preset.ts))
  - `clone` and `delete` write/remove YAML files. The inspected clone implementation reads `newPreset.value.rawText` after checking that the new preset does not exist, which appears inconsistent with its intended `oldPreset` source. ([`packages/core/src/middlewares/preset/clone_preset.ts`: `apply`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/middlewares/preset/clone_preset.ts), [`packages/core/src/middlewares/preset/delete_preset.ts`: `apply`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/middlewares/preset/delete_preset.ts))
- Conversation persistence stores the selected preset **name**, not a preset snapshot: `ConversationRecord.preset` is a string and invocation validates it against the currently loaded `PresetService`. ([`packages/core/src/types.ts`: `ConversationRecord`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/types.ts), [`packages/core/src/services/conversation.ts`: `ConversationService.requireInvocationPreset`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/services/conversation.ts))

#### Character presets and runtime character data

- Character presets are separate YAML files under `data/chathub/character/presets`. `Preset.loadAllPreset()` reads `.yml`, attaches `path`, updates the dynamic `character-preset` schema, and emits `chatluna_character/preset_updated`; `watchPreset()` reloads on filesystem changes. No generic preset write/edit API is present in this service. ([`src/preset.ts`: `Preset.loadAllPreset`, `watchPreset`, `resolvePresetDir`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/preset.ts))
- Character YAML is parsed into `{ name, nick_name, input, system, mute_keyword, status }`. Both `input` and `system` retain a `rawString` and provide a `format()` closure that delegates to ChatLuna's prompt renderer. ([`src/preset.ts`: `loadPreset`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/preset.ts), [`src/types.ts`: `PresetTemplate`, `ChatLunaCharacterPromptTemplate`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/types.ts))
- The selected character preset is exposed through dynamic Koishi config fields such as `preset: Schema.dynamic('character-preset')`; the preset bodies remain filesystem data. ([`src/config.ts`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/config.ts))
- Session character state is persisted separately in database table `chathub_character_variable`, keyed by `sessionKey`; current persisted fields are status, history-clear time, status-message IDs, and update time. `MessageService` loads these rows at startup. ([`src/service/variable_store.ts`: `VariableStore`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/service/variable_store.ts), [`src/service/message.ts`: `MessageService` constructor](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/service/message.ts))
- Character exposes immutable-ish preset snapshots to integrations through `chatluna_character/before-chat` and `after-chat`: snapshot fields include preset name/status/nicknames, raw input/system strings, mute keywords, and path. The after event additionally exposes the already formatted `persistedHumanMessage`, the latest response, completion messages, and status. ([`src/plugins/chat.ts`: `snapshotPreset`, `prepareMessages`, after-chat emission](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/plugins/chat.ts), [`src/types.ts`: `CharacterBeforeChatEventPayload`, `CharacterAfterChatEventPayload`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/types.ts))

### 2. Variable syntax and interpolation semantics

- Current syntax is expression syntax inside single braces: `{variable}`. It also supports member access, array indexes, function calls, arithmetic/comparison/logical/ternary expressions, and `{if}`, `{for}`, `{while}`, and `{repeat}` blocks. Literal braces are escaped as `{{` and `}}`. ([`packages/shared-prompt-renderer/src/lexer.ts`: `tokenize`, `TemplateLexer`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/src/lexer.ts), [`packages/shared-prompt-renderer/README.md`: syntax and migration table](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/README.md))
- The old function syntax `{func:arg1::arg2}` is explicitly unsupported; function calls use `{func(arg1, arg2)}`. ([`packages/shared-prompt-renderer/README.md`: “从旧语法迁移”](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/README.md))
- `ChatLunaPromptRenderer.render()` merges registered static variables with call variables, then merges variable-provider output at top-level rendering. Explicit call variables override static variables; provider variables are merged afterward and therefore override same-named explicit/static values. It returns both expanded `text` and the detected variable names. ([`packages/shared-prompt-renderer/src/renderer.ts`: `ChatLunaPromptRenderer.render`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/src/renderer.ts), [`packages/shared-prompt-renderer/src/utils.ts`: `renderInternal`, `getAllVariables`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/src/utils.ts))
- A missing identifier or missing member evaluates to `''`; expression-rendering errors are caught and also render as `''`. Function-valued variables are invoked, and registered functions may be used with or without parentheses. ([`packages/shared-prompt-renderer/src/evaluator.ts`: `evaluateExpression`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/src/evaluator.ts), [`packages/shared-prompt-renderer/src/utils.ts`: `renderToken`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-prompt-renderer/src/utils.ts))
- ChatLuna supplies built-in functions (`date`, `weekday`, `random`, `pick`, etc.) and allows plugins to register variable/function providers. For example, the variable extension registers lunar variables and `latest_message(...)`. ([`packages/core/src/services/prompt_renderer.ts`: `ChatLunaPromptRenderService`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/services/prompt_renderer.ts), [`packages/extension-variable/src/plugins/lunar.ts`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/extension-variable/src/plugins/lunar.ts), [`packages/extension-variable/src/plugins/group.ts`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/extension-variable/src/plugins/group.ts))
- Core per-request variables include `prompt` plus identity/session data such as `name`, `user`, `user_id`, `group_id`, `date`, `time`, and `built`. Character input explicitly passes `history_new`, `history_last`, `time`, `status`, `trigger_reason`, `prompt`, `sessionType`, and `built`. ([`packages/core/src/middlewares/conversation/request_conversation.ts`: request preparation](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/middlewares/conversation/request_conversation.ts), [`packages/core/src/utils/string.ts`: `getSystemPromptVariables`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/utils/string.ts), [`chatluna-character/src/plugins/chat.ts`: `prepareMessages`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/plugins/chat.ts))
- Upstream resource files demonstrate the actual syntax: core `catgirl.yml` uses `{name}`, `{sender}`, `{sender_id}`, and `{prompt}`; character presets use `{time}`, `{history_new}`, `{status}`, and function syntax such as `{long_memory('guild')}`. ([`packages/core/resources/presets/catgirl.yml`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/resources/presets/catgirl.yml), [`resources/presets/default-tool-call.yml`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/resources/presets/default-tool-call.yml))

### 3. Where expansion occurs and what the model finally receives

#### ChatLuna core

- Preset YAML is first parsed into LangChain messages without expansion. During prompt assembly, `createSystemPromptsMiddleware()` calls `renderPresetTemplate(preset, variables, ...)`, which expands every preset message and constructs new LangChain messages containing `content.text`. ([`packages/core/src/llm-core/prompt/preset_prompt_parse.ts`: `loadYamlPreset`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/llm-core/prompt/preset_prompt_parse.ts), [`packages/core/src/llm-core/prompt/system_prompts.ts`: `createSystemPromptsMiddleware`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/llm-core/prompt/system_prompts.ts), [`packages/core/src/services/prompt_renderer.ts`: `renderPresetTemplate`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/services/prompt_renderer.ts))
- The chain formats the complete prompt before calling the model (`prompt.formatPromptValue(...)` followed by `llm.generatePrompt(...)`). ([`packages/core/src/llm-core/chain/base.ts`: `ChatLunaLLMChain._call`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/core/src/llm-core/chain/base.ts))
- The shared OpenAI adapter then builds HTTP `messages` from `params.input`, i.e. those already formatted LangChain messages, and posts the resulting body to `chat/completions`. Thus request capture at the fetch/HTTP boundary sees expanded values rather than raw `{variable}` templates (except deliberately escaped or unresolved text). ([`packages/shared-adapter/src/requester.ts`: `buildChatCompletionParams`, `completionStream`](https://github.com/ChatLunaLab/chatluna/blob/69732edfffe57e7ab8656b09c05c264a8bb54eb9/packages/shared-adapter/src/requester.ts))

#### Character

- `prepareMessages()` expands both character `system` and `input` before creating the final `SystemMessage` and `HumanMessage`; it then builds `completionMessages`. ([`src/plugins/chat.ts`: `prepareMessages`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/plugins/chat.ts))
- In direct mode, those `completionMessages` are passed straight to `model.invoke(messages, ...)`. In agent mode, the already expanded system content becomes `instructions`, while already expanded history/last messages are passed to the agent chain. ([`src/plugins/chat.ts`: `streamModelResponse`, `streamAgentResponseContents`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/plugins/chat.ts))
- Character escapes braces in inserted recent/history/trigger strings before rendering, preventing user/history text that happens to contain `{...}` from being interpreted as a second-level template. ([`src/plugins/chat.ts`: `prepareMessages`](https://github.com/ChatLunaLab/chatluna-character/blob/48b5e66968c605c6f56de38875d381eea92a9706/src/plugins/chat.ts))

## Integration implications for this sandbox (recommendations)

These are recommendations derived from the facts above, not claims about upstream behavior.

1. **Treat upstream files as the source of preset truth.** A sandbox editor should read/write the two actual directories (`data/chathub/presets` and `data/chathub/character/presets`) rather than create a parallel database representation. Preserve unknown YAML fields and ordering/comments where practical; core presets in particular have a richer schema than a single text area.
2. **Model core and character presets as different document types.** Core presets are a list of role messages plus optional user-format/lore/config fields; character presets have distinct raw `system` and `input` templates plus character metadata. Do not force both into one lossy form.
3. **Validate with the upstream grammar, not simple regex replacement.** At minimum support single-brace expressions, control blocks, function calls, and doubled-brace escaping. Warn that missing variables/errors collapse to empty strings upstream. If the sandbox cannot invoke ChatLuna's renderer directly, label previews as approximate.
4. **Show both source and observed expansion.** The authoritative “what the model received” proof is the sandbox's existing model-request record at the HTTP boundary; its request body should already contain expanded values. A preset editor preview should link to the latest matching model-request evidence instead of claiming that a locally rendered preview is definitive.
5. **Correlate character source with runtime evidence via events where useful.** `chatluna_character/before-chat` provides raw preset snapshots, while `after-chat` provides the formatted persisted human message and completion state. These are useful metadata/evidence hooks, but the final HTTP request remains authoritative because agent tooling and prompt assembly can further shape the request.
6. **Keep selected-preset references separate from preset content.** ChatLuna conversations/configs retain preset names, while content lives in watched files. Renaming/deleting needs referential checks and an explicit reassignment policy; avoid persisting duplicated snapshots as the live source.
7. **Use atomic, path-safe writes and let upstream watchers reload.** Restrict filenames to the preset roots, write via temp-file-plus-rename, and surface parse/reload errors. Do not reproduce the inspected clone middleware's apparent `newPreset.value.rawText` inconsistency.
8. **Do not interpolate inserted untrusted text twice.** Follow character's brace-escaping pattern when constructing previews or test expansions from chat/history strings, so a message containing `{name}` is displayed as data rather than executed as template syntax.
