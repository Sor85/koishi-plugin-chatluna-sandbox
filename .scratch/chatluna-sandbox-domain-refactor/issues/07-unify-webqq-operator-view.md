# 07 — 统一 WebQQ 当前操作者视角

**What to build:** 让 WebQQ 只依赖一个当前操作者参与者 ID，并从该身份推导全部列表、权限和消息表现。普通用户和机器人切换后应获得完全一致的工作台行为，同时保持现有 WebQQ 视觉、布局、动画、菜单和响应式交互不变。

**Blocked by:** 04 — 实现消息单份存储与机器人事件投递；06 — 收紧 Console RPC 与未来 MCP 控制合同

**Status:** ready-for-human

- [x] WebQQ 只保存 `currentOperatorId`，不读取或迁移旧当前用户字段，也不存在普通用户代理状态
- [x] 切换到普通用户或机器人后，最近、好友、群组、通知和当前会话都按该参与者的关系与成员资格刷新
- [x] 用户和机器人操作者拥有一致的群权限判断、右键菜单、好友申请与群申请处理行为
- [x] 当前操作者发送的消息始终位于右侧并使用强调色，对端消息始终位于左侧
- [x] 普通用户、机器人和群组头像样式只由参与者或会话种类决定，不因当前操作者种类发生泄漏
- [x] 操作者切换、会话选择、聊天输入、右侧信息栏和 ChatLuna 状态在 Chrome 与 Firefox 中保持现有布局和动画

## Answer

- WebQQ 当前操作者保持为唯一的 `currentOperatorId`；当前聊天、目录、通知、权限与发送身份均由该参与者 ID 推导，不保留普通用户代理状态
- 移除侧栏和消息右键菜单对机器人操作者的隐藏分支。机器人现在与普通用户一样可以主动发送好友申请、申请入群、设置好友备注和删除好友；机器人收到申请时仍通过自身 OneBot action 审批
- 停用机器人仍可作为当前操作者观察页面，但所有好友操作会被服务端拒绝，与既有群操作禁用语义一致
- 环境创建弹窗把当前操作者类型从普通用户收紧为统一参与者，机器人可继续作为新群群主
- 活动逻辑会话的 ChatLuna 状态现已传入消息列表；每个机器人状态按 `botParticipantId + conversationId` 渲染思考点和输入/输出 Token，消息方向始终与当前操作者比较决定
- 头像种类继续只由参与者或会话种类决定；消息列表与侧栏不再依据当前操作者是否为机器人改变头像、强调色或菜单
- Standards 审查 0 项问题；Spec 审查 0 项问题。当前会话禁止派生子代理，因此由主线程按同样两个维度核对
- 验证通过：`yarn test`（30 个文件、120 个测试）、`yarn typecheck`、`yarn build`、`git diff --check`；Ego Browser 在 `http://127.0.0.1:5140/chatluna-sandbox` 验证机器人切换、好友目录和右键菜单，页面无控制台错误
