# 02 — 删除源码断言并按主题拆分测试用例

**What to build:** 对模型请求工作台做等价重构时,测试不再假红。把三处相同的恢复赋值合并成一个函数、改变状态默认值的表达方式、调整组件目录结构、更换图标——这些都不会再让测试变红,而真实行为回归仍然被守住。测试失败时能定位到具体主题,不再是三百多条断言共用同一个用例名。

该测试的第一个用例目前有三百四十八条断言,全部打在读进来的源码文本与样式文本上,横跨导航、筛选、列表、详情、错误诊断与样式六个主题。其中一百零二条把实现写法写进契约:断言某条赋值语句恰好出现两次、断言响应式引用的字面初始化写法、断言从哪个路径导入组件、断言用了哪个图标组件名、断言内联的手势阈值与缩放常量。这类断言在任何等价重构时变红,却对真实行为回归保持沉默。

删除一百二十七条:十六条已有真正执行代码的行为测试覆盖同一事实、一百零二条肯定式实现细节断言、九条与别处重复或只断言图标组件名。剩余二百二十一条保留并按主题拆成多个测试用例。

保留与删除的判据是成本结构而不是断言形式。样式文本断言与用户文案断言不锁死实现写法,改一个变量名不会让它们变红,它们的问题是覆盖弱而不是有害;在不引入组件挂载测试的前提下,用户文案断言是唯一能守住界面文案的手段。否定式的已删除实现守卫只在有人把已删实现加回来时才变红,那正是需要的行为——其中一部分是模型证据投影唯一化与证据导航统一两条工作刚刚加入的。描述可见 DOM 结构与元素顺序的断言约束的是用户能看到的排列,保留。

删除依据是一份已完成的逐条分类:十六条可删断言各自附有覆盖它的行为测试文件与行号,一百零二条实现细节断言各自附有它本该由什么 interface 承担。实施时按该分类逐条处理,不重新判断。

本票不改动任何生产代码,界面行为与文案完全不变。

**Blocked by:** None — can start immediately
