# 01 — 架构守卫从白名单制改为规则制

**What to build:** 新增的客户端 Vue 单文件组件默认受两条架构规则约束,而不是像现在这样默认豁免;发送 Koishi RPC 的函数只允许出现在客户端工作区端口适配器里,该规则对 TypeScript 文件一并生效。

现有守卫是一份七个文件的白名单,白名单外的文件不受任何约束,规则随文件数增长自动失效。已核实七个文件上有九条真实违规,守卫一处都看不见,其中测试空间生命周期编排的七处直连端点与 MCP 活动同步的一处直连端点,连暴露机会都没有——守卫完全不扫描 TypeScript 文件。更微妙的是主页面:它调用从完整工作区快照派生机器人目录的函数,守卫放过它只因为该文件里没出现快照的类型名,规则靠拼写巧合成立。

不读取完整工作区快照这条规则改为全量扫描客户端 Vue 单文件组件,谓词加强到能识别「从完整快照派生区域数据」这一行为本身。已核实该谓词组合恰好命中四处真违规,且不误报某处把同名局部变量展开进搜索条件参数的用法——若把谓词放宽到属性访问就会把它误抓进来,那会让豁免清单混入误报。

不直接调用 Koishi RPC 这条规则的表述从「UI 模块不要调用发送函数」改为「发送函数只允许出现在工作区端口适配器里」。这条可静态判定、无需白名单、且天然覆盖 TypeScript 文件。

九条已知违规登记为显式豁免,每条写明理由并指定负责消化它的后续工作:四条完整快照违规归属区域投影下沉,五条 RPC 违规归属扩展工作区端口。已核实端口接口里测试空间、凭证与媒体三类方法零命中,因此它们是端口覆盖不全而不是绕过端口。豁免清单与守卫断言放在同一处,理由与负责人均为必填,债务因此有主。

本票不改动任何生产代码,九条违规都不在本票内修复。

## Comments

守卫落在 `tests/webqq-architecture.test.ts`，规则以数据形式声明：每条规则带名称、适用扩展名与谓词函数，谓词跑遍 `client` 下全部匹配文件。

- 完整快照规则扫全部 `.vue`，三条谓词分别认完整快照类型名 `SandboxSnapshot`、派生调用 `getSandboxBots` / `getSandboxUsers`、以及属性形式 `props.snapshot` / `model.snapshot`。已实测该组合恰好命中四个文件，且不误报 `client/webqq-chat-pane.vue:476` 把同名局部变量展开进搜索条件参数的 `...snapshot`。
- RPC 规则同时扫 `.ts` 与 `.vue`，除工作区端口适配器 `client/webqq/koishi-workspace-port.ts` 外任何 `send(` 调用都算违规。类型声明文件（`.d.ts`）不参与扫描：`client/koishi-client-shim.d.ts` 里的 48 处 `send` 是被声明的重载签名，不是调用。实测五个文件共十七处违规，与规格核实的数字一致。
- 九条豁免以 `{ file, rule, reason, owner }` 结构登记，`owner` 收敛到两个常量：区域投影下沉与扩展工作区端口。另有两条断言守着清单本身——理由与负责人非空且负责人在已知后续工作里；逐条移除豁免后对应文件必须重新报错，这条同时排除了陈旧条目。
- 失败信息形如 `client/xxx.vue 违反「规则名」：证据`，定位不需要读断言实现。已用临时注入验证：往 `client/webqq-sidebar.vue` 和 `client/webqq/scroll-restore.ts` 各插一处违规后两条规则都报错并指名文件，随后已还原。

与规格的一处事实修正：规格称媒体读取「端口接口里零命中」，实测 `client/webqq/workspace-port.ts:66` 已有 `getMediaContent`。真实原因是端口的媒体读取经 `scoped()` 按当前工作区隐式定域，而空间缩略图要按显式 `spaceId` 读任意测试空间的头像媒体，端口缺的是这个形状。豁免理由按实测事实写。

旧白名单里 `koishiWorkspacePort|workspaceController|ctx.console` 那一段随白名单一并删除。删前已核实它是空断言：`ctx.console` 在 `client` 下零命中，`workspaceController` 只出现在 `client/page.vue`（装配处）与 `client/webqq/workspace-shell.ts`（形参），都不在原白名单的七个文件里。

架构决策记录：`docs/adr/0073-assert-interfaces-and-guard-by-rule.md`，含「数量断言不构成覆盖」一段（引 MCP 工具覆盖那条工作：四十个工具里十五个从未被调用，被一处总数断言掩盖）。

验证：`yarn vitest run tests/webqq-architecture.test.ts` 5 passed；`yarn test` 128 files / 843 tests 全绿；`yarn typecheck` 无输出；`yarn build` 成功。生产代码零改动。
