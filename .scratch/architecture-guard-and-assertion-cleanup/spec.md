# 架构守卫规则化与源码断言清理规格

Status: resolved

## Problem Statement

WebQQ 工作台的架构守卫目前是一份七个文件的白名单。它声称验证两条约束——UI 模块不读取完整工作区快照、UI 模块不直接调用 Koishi RPC——但白名单外的文件默认不受任何约束,于是规则随文件数增长自动失效。

已核实的后果是七处真实违规,守卫一处都看不见:空间缩略图同时收取完整工作区快照并直连媒体读取端点;AI 测试空间总览收取完整快照;环境管理页读取完整快照并直连 MCP 能力目录端点;测试空间生命周期编排直连七个端点;MCP 活动同步与 MCP 凭证管理各自直连端点。更微妙的是主页面:它调用从完整快照派生机器人目录的函数,守卫放过它只因为该文件里没有出现快照的类型名——规则靠拼写巧合成立。守卫对客户端的 TypeScript 文件完全不扫描,所以其中两处违规连暴露的机会都没有。

模型请求工作台的测试则走到了另一个极端。它的第一个测试用例里有三百四十八条断言,全部打在读进来的源码文本与样式文本上。其中一百零二条把实现写法写进契约:断言某条赋值语句恰好出现两次、断言某个响应式引用的字面初始化写法、断言从哪个路径导入按钮组件、断言用了哪个图标组件名。这类断言在任何等价重构时都会变红,却对真实行为回归保持沉默——本次评审在同一区域找到的多处口径漂移,它一条都没抓住。它们因此成为后续重构的主要阻力。

三百四十八条断言还挤在同一个测试用例里,横跨导航、筛选、列表、详情、错误诊断与样式六个主题。任何一条失败都只报同一个用例名,无法定位。

## Solution

把守卫从白名单制换成规则制,并把最有害的那部分源码断言删掉。

不读取完整工作区快照这条规则改为全量扫描客户端的 Vue 单文件组件,谓词加强到能识别「从完整快照派生区域数据」这一行为本身,而不只是快照的类型名。不直接调用 Koishi RPC 这条规则换成一条可静态判定的强规则:发送 RPC 的函数只允许出现在客户端工作区端口适配器里,对 TypeScript 文件与 Vue 单文件组件一并生效。新增文件因此默认受约束。

七个文件上的九条已知违规登记为显式豁免。每条豁免必须写明理由,并指定负责消化它的后续工作:四条完整快照违规归属区域投影下沉,五条 RPC 违规归属扩展工作区端口。豁免清单与守卫断言放在同一处,改代码的人立刻看到;有了负责人字段,它们从白名单里的隐形放行变成有主的债务。

模型请求工作台测试删掉一百二十七条断言:十六条已有真正执行代码的行为测试覆盖、一百零二条把实现写法写进契约、九条与别处重复或只断言图标组件名。剩下的二百二十一条保留并按主题拆成多个测试用例,失败时能定位。

保留与删除的判据是成本结构而不是断言形式。样式文本断言与用户文案断言不锁死实现写法,改一个变量名不会让它们变红,它们的问题是覆盖弱而不是有害。否定式的已删除实现守卫——断言某个旧符号不再存在——只在有人把已删实现加回来时才变红,那正是需要的。真正要消灭的是肯定式实现细节断言:它在任何等价重构时变红,却不验证任何行为。

## User Stories

## Implementation Decisions

### 守卫的两条规则

不读取完整工作区快照:全量扫描客户端 Vue 单文件组件。谓词为完整快照类型名、两个从完整快照派生参与者目录的函数名、以及以属性形式读取快照的两种既有写法。已核实这组谓词恰好命中四处真违规,且不误报把局部变量展开进搜索条件参数的用法——后者的变量名相同但不是工作区快照,若放宽到属性访问会把它误抓进来。

不直接调用 Koishi RPC:表述从「UI 模块不要调用发送函数」改为「发送函数只允许出现在客户端工作区端口适配器里」。这条对 TypeScript 文件与 Vue 单文件组件一并生效,无需白名单,新增文件自动受约束。已核实当前仅端口适配器一个文件是合法持有者,另有五个文件共十七处调用属于违规。

### 豁免清单

清单与守卫断言放在同一个测试文件内。每条豁免包含文件、违反的规则、理由、以及负责消化它的后续工作。理由与负责人均为必填。

四条完整快照豁免归属区域投影下沉:空间缩略图按定义需要完整快照来绘制整个工作区;AI 测试空间总览只是把快照透传给缩略图;环境管理页读取参与者与群组做目录展示,需要的是区域视图模型;主页面从完整快照派生机器人目录,那是控制模块的职责而不是装配。

五条 RPC 豁免归属扩展工作区端口:测试空间生命周期、MCP 凭证、MCP 活动、MCP 能力目录、媒体读取五类能力当前都不在端口覆盖范围内。已核实端口接口里这三类方法零命中,因此它们是覆盖不全而不是绕过端口。

### 断言的保留与删除

判据是成本结构而不是断言形式。

删除:已有真正执行代码的行为测试覆盖同一事实的十六条;把实现写法写进契约的一百零二条肯定式断言;与别处重复或只断言图标组件名的九条。

保留:样式文本断言;描述可见 DOM 结构与元素顺序的断言;否定式的已删除实现守卫;用户文案与展示语义断言。

否定式守卫与肯定式细节断言的成本结构相反:前者只在有人把已删除的实现加回来时才变红,那正是需要的行为;后者在任何等价重构时变红,却不验证任何行为。用户文案断言不锁死实现写法,它的问题是覆盖弱而不是有害;在不引入组件挂载测试的前提下,它是唯一能守住界面文案的手段。

### 测试用例拆分

剩余断言按主题拆成多个测试用例,主题包括页面入口与装配、列表筛选与排序、详情概览与元信息、错误诊断、请求体与响应视图、轨迹与组成图、JSON 树交互、样式。每个用例名说清它断言的是什么。

### 生产代码

本规格不改动任何生产代码,不改动任何领域词汇。四处完整快照违规与五处 RPC 违规都不在本规格内修复,它们登记为带负责人的豁免。

### 架构决策记录

新增一条架构决策记录,内容包括:守卫采用规则制而非白名单制;测试应当断言 interface 而不是源码文本;样式文本断言与用户文案断言是明确的例外,因为在不引入组件挂载测试的前提下没有替代手段;否定式的已删除实现守卫是第二类例外,因为它的成本只在旧实现被重新引入时发生;架构守卫自身读取源码不属于被禁止的模式,因为它的断言对象本来就是源码结构;豁免必须带理由与负责人。

领域词汇不变。

## Testing Decisions

### 什么算好测试

只断言从 interface 观察得到的外部行为。源码文本断言仅在三种情况下可接受:断言对象本身就是源码结构(架构守卫);断言对象本身就是样式文本;以及在没有组件挂载测试的前提下守住用户可见文案与已删除实现。

### 守卫 seam

既有的架构守卫测试文件,规则形状改造,不新增 seam。它同时是本规格守卫部分的实现与测试——被断言对象是客户端源码是否遵守两条规则,读取源码是唯一可行方式。

验证守卫本身有效的方式是:改造后它必须报出九条已知违规对应的文件,并且在豁免清单生效后全部通过;把任一豁免条目临时移除,对应文件必须重新报错。

### 断言清理部分

不新增测试。这部分是纯减法与重组,它的正确性由「删除后全部测试仍然通过、类型检查与构建全绿」证明。

删除依据来自一份已完成的逐条分类:十六条可删断言各自附有覆盖它的行为测试文件与行号;一百零二条实现细节断言各自附有它本该由什么 interface 承担。实施时按该分类逐条处理,不重新判断。

### 副产物:没有 interface 的行为清单

一百零二条实现细节断言的「本该由什么 interface 承担」汇总起来,就是模型请求区域至今没有可执行 interface 的行为清单,其中包括:请求组成图的滚轮、拖拽与缩放手势及其锚点补偿与点击抑制;剪贴板复制与其降级路径;请求体下载的文件名与内容;请求头展开状态与树模型;JSON 行的手势与拖动阈值判定;JSON 字符串展开与图片预览状态;轨迹账本的排序与请求折叠;详情页签与轨迹模式的状态转换;概览格三态的呈现;模型名称的唯一来源;刷新策略在手动开关与进行中请求两种条件下的组合。

该清单不在本规格内消化,但应记入后续工作的输入。

### 验收

单元测试、类型检查与构建全绿。不做浏览器验证:生产代码零改动,行为不可能变化;被删除的断言本来也不验证行为,只锁死写法。

## Out of Scope

- 修复九条豁免对应的违规。四条完整快照违规归属区域投影下沉,五条 RPC 违规归属扩展工作区端口,均单列。
- 扩展工作区端口以覆盖测试空间生命周期、MCP 凭证、MCP 活动、MCP 能力目录与媒体读取。
- 为副产物清单里的行为抽出 interface。那需要先决定每个 module 的形状,属于另一条候选。
- 其余二十七个含源码断言的测试文件。其中环境管理组件测试的断言是环境管理表单深化那条候选唯一的当前行为记录,现在删除会让那张票失去参照;聊天区域与预设工作台的断言同理,需要先有对应候选把 interface 抽出来,否则是净损失。
- 引入组件挂载测试、jsdom 或 happy-dom。
- 模型请求区域的任何界面、文案、样式与行为调整。
- 领域词汇调整。

## Further Notes

- 三百四十八条断言的逐条分类由子代理完成并已核对:十六条已覆盖、七十一条样式文本、七十四条 DOM 结构与顺序、一百三十五条实现细节、五十二条用户文案与展示语义。其中一百三十五条实现细节里约三十三条是否定式的已删除实现守卫,按成本结构判据保留。
- 只删除已有行为测试覆盖的那十六条,断言总数从三百四十八降到三百三十二,几乎没有收益。真正的量在实现细节断言。这一点在规划期一度被低估,分类结果纠正了它。
- 部分否定式守卫是模型证据投影唯一化与证据导航统一那两条候选刚刚加入的,用于断言旧实现已被删除。它们与证据导航统一测试文件里的四条源码断言性质相同,而那四条是该候选规格明确要求的。
- 分支与提交:依仓库规则不自行创建分支、不自行提交。
