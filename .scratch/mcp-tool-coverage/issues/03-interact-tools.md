# 03 — 交互类两个工具

**What to build:** 执行群操作与等待 ChatLuna 状态两个工具被真正调用。

执行群操作覆盖入群、邀请、退群、群管理与戳一戳。它属于交互能力范围,走机器人动作或用户交互的领域路径,因此要断言的不只是调用成功,还有操作确实改变了模拟 QQ 环境的相应事实,以及权限不足时被明确拒绝。

等待 ChatLuna 状态从事件游标开始等待,匹配到状态后返回。现有 ChatLuna 状态测试已有驱动状态广播的辅助函数,可直接复用来触发状态。要断言的是:从游标之前的旧状态不会被误认为当前结果、匹配条件生效、超时时返回未匹配而不是抛错。

调用全部经测试控制服务的工具调用入口。等待类工具在该入口上走独立的频率与并发分类,这条分类因此也被覆盖。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 执行群操作的工具被真正调用,入群、邀请、退群、群管理与戳一戳各自的效果被断言
- [ ] 执行群操作时权限不足的情形被明确拒绝
- [ ] 执行群操作确实改变模拟 QQ 环境的相应事实,而不只是返回成功
- [ ] 等待 ChatLuna 状态的工具被真正调用,匹配到状态后返回该状态
- [ ] 游标之前的旧状态不会被误认为当前等待结果
- [ ] 等待的匹配条件生效,不匹配的状态不会提前结束等待
- [ ] 等待超时时返回未匹配结果而不是抛出错误
- [ ] 复用现有 ChatLuna 状态测试的状态广播辅助函数触发状态
- [ ] 全部调用经测试控制服务的工具调用入口
- [ ] 过程中若发现生产缺陷,在本票内修复并逐条记录改了什么行为
- [ ] 单元测试、类型检查与构建全绿
