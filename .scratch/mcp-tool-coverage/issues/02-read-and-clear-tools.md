# 02 — 读取类与清理类七个工具

**What to build:** 七个从未被任何测试调用过的工具各自被真正调用:分页列出当前操作者可见会话、读取单个会话及其消息、列出待处理好友与群申请、读取实现配置的能力覆盖、导出版本化场景、清理 OneBot 调试记录、清理测试调用记录。

其中前五个读取类工具此前出现在一份工具名清单断言里。那比完全不出现更危险——清单让它们看起来已被覆盖,而清单只证明名字存在。

调用全部经测试控制服务的工具调用入口,不下降到控制服务或调试记录存储各自的方法。绕过该入口会漏掉能力范围检查、限流分类、调用记录写入,以及非结构化错误被归一为领域错误码这条行为。

读取类工具要断言的不只是「调用成功」,还有它们的可见性语义:会话列表与会话详情按当前操作者的可见性返回,待处理申请反映当前场景的真实状态,能力覆盖矩阵随实现配置与能力覆盖变化。清理类工具要断言清理后记录确实为空,且返回的清理数量与清理前的记录数一致。

## Comments

七个工具的用例都在 `tests/mcp-tool-coverage.test.ts`，全部经 `service.callTool`。

各自断言的语义：

- `list_conversations`：默认场景里 10001 只看到自己的私聊与群聊，换成 10002 后返回的是 10002 的私聊；`limit`/`offset` 分页与 `nextOffset` 的出现与消失一并断言。
- `get_conversation`：返回的消息集合正好等于该会话引用的消息，读取他人私聊按 `conversation_not_found` 拒绝。
- `list_pending_requests`：从空列表出发，好友申请与入群申请各产出一条，处理掉好友申请后它从列表消失。
- `get_capability_matrix`：napcat 与 llbot 的条目集合不同、省略 `implementation` 按 napcat 解析；用 `set-capabilities` 禁用一项能力后只有该项变成 `supported:false` 并带禁用理由，其余条目与基线逐条一致。
- `export_scene`：`testApiVersion` 为 1、`exportedAt` 可解析、`scene` 与当前快照相等。
- `clear_onebot_debug_records`：两条真实 OneBot action 记录被清空，返回数量与清理前一致。
- `clear_mcp_call_records`：调用记录在工具执行完成之后写入，因此读取自身不出现在它返回的页里，而清理返回的数量覆盖清理调用之前的全部记录（含上一次读取留下的那条）；清理后库里只剩清理调用自身的记录。用例按这个真实时序断言，而不是断言「清理后为空」。

未发现本票范围内的生产缺陷。
