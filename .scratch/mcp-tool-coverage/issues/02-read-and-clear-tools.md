# 02 — 读取类与清理类七个工具

**What to build:** 七个从未被任何测试调用过的工具各自被真正调用:分页列出当前操作者可见会话、读取单个会话及其消息、列出待处理好友与群申请、读取实现配置的能力覆盖、导出版本化场景、清理 OneBot 调试记录、清理测试调用记录。

其中前五个读取类工具此前出现在一份工具名清单断言里。那比完全不出现更危险——清单让它们看起来已被覆盖,而清单只证明名字存在。

调用全部经测试控制服务的工具调用入口,不下降到控制服务或调试记录存储各自的方法。绕过该入口会漏掉能力范围检查、限流分类、调用记录写入,以及非结构化错误被归一为领域错误码这条行为。

读取类工具要断言的不只是「调用成功」,还有它们的可见性语义:会话列表与会话详情按当前操作者的可见性返回,待处理申请反映当前场景的真实状态,能力覆盖矩阵随实现配置与能力覆盖变化。清理类工具要断言清理后记录确实为空,且返回的清理数量与清理前的记录数一致。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 分页列出可见会话的工具被真正调用,返回的会话集合符合当前操作者的可见性规则
- [ ] 读取单个会话的工具被真正调用,返回该会话及其消息
- [ ] 列出待处理申请的工具被真正调用,返回当前场景的真实待处理好友与群申请
- [ ] 读取能力覆盖矩阵的工具被真正调用,结果随实现配置与能力覆盖变化
- [ ] 导出版本化场景的工具被真正调用,返回可用于导入的版本化场景
- [ ] 清理 OneBot 调试记录的工具被真正调用,清理后记录为空且返回数量与清理前一致
- [ ] 清理测试调用记录的工具被真正调用,清理后记录为空且返回数量与清理前一致
- [ ] 全部调用经测试控制服务的工具调用入口,不下降到领域服务各自的方法
- [ ] 断言不止于调用成功,覆盖各自的可见性或清理语义
- [ ] 过程中若发现生产缺陷,在本票内修复并逐条记录改了什么行为
- [ ] 单元测试、类型检查与构建全绿
