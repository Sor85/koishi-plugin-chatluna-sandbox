# 01 — 工具清单断言与 HTTP 错误信封

**What to build:** 端点提供哪些工具、每个工具属于哪个能力范围,成为测试直接陈述的事实。工具被误删、被误加、被改名、能力范围写错四种情况都会让测试变红——现在只有工具总数变化才会红。

三处断言工具总数的用例换成完整工具清单断言,内容包括每个工具的名字与能力范围,数量因此隐含。现有那份只列出部分工具名的清单合并进来,不再单独存在。清单断言同时是自文档化的:读测试就能看到测试控制端点提供哪些工具。

同时让 HTTP 传输层第一次真正调用一次工具。现有 HTTP 测试建立了真实 MCP 客户端,但只列举工具与资源,因此错误信封整体零断言;生成信封时读取的场景版本方法,唯一调用者就是这个未被验证的信封。本票经真实客户端调用一个超出凭证能力范围的工具,断言错误标记为真,且错误码、消息、追踪标识与场景版本就位。

重试等待时间不在本票内验证。它需要构造限流场景,属于凭证配额那条工作已经承诺的判据;本票验证信封的结构,那条验证限流的语义。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 三处工具总数断言换成完整工具清单断言,覆盖每个工具的名字与能力范围
- [ ] 工具被改名会让测试变红
- [ ] 工具的能力范围写错会让测试变红
- [ ] 工具被误删或误加会让测试变红
- [ ] 现有那份部分工具名清单合并进完整清单断言,不再单独存在
- [ ] HTTP 传输层至少有一次经真实 MCP 客户端发起的真正工具调用
- [ ] 超出凭证能力范围的调用在 HTTP 层返回错误信封,断言错误标记为真
- [ ] 错误信封的错误码、消息、追踪标识与场景版本被断言
- [ ] 生成错误信封时读取的场景版本方法因此第一次被测试经过
- [ ] 重试等待时间不在本票内断言
- [ ] 过程中若发现生产缺陷,在本票内修复并逐条记录改了什么行为
- [ ] 单元测试、类型检查与构建全绿
