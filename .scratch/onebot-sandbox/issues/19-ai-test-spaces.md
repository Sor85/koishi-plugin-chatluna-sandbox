# 19 — 在 WebQQ 中提供 AI 测试空间

**What to build:** 基础 MCP 能力完成后，外部测试控制器可以为每次测试创建一个空白且隔离的 AI 测试空间，自主创建普通用户、虚拟 OneBot 机器人、群组和关系，并通过真实交互验证插件行为。用户可以从 WebQQ 最左侧主导航进入实时缩略工作台总览，观察、接管、归还、复盘或删除空间。

**Blocked by:** 18 — 完善 MCP 限流、错误与脱敏调试记录

**Status:** blocked

- [ ] 每次测试创建独立空间并返回 `spaceId`，一个凭证可以创建多个空间
- [ ] 新空间从空白沙盒场景开始，所有 MCP 空间操作显式携带 `spaceId`
- [ ] 同一空间同一时间只允许一个 AI 控制者，用户接管时暂停 MCP 修改操作
- [ ] 空间完成后默认保留场景、消息、事件和调试记录，AI 可以删除自己创建的空间，但工具提示要求仅在用户明确要求时清理
- [ ] 主模拟 QQ 环境不接受 AI 测试空间的数据写入，主场景与空间共享同一领域模型和全局持久化策略
- [ ] 活动空间机器人 ID 在主场景和所有活动空间中全局唯一；完成空间停止机器人运行时，重新激活时重新检查冲突
- [ ] WebQQ 最左侧主导航增加 AI 测试空间入口，不新增 Koishi 插件导航入口
- [ ] 空间总览将主模拟 QQ 环境作为不可删除的固定首卡，AI 空间按创建时间从旧到新排列，“＋”卡片固定在最后
- [ ] 每张空间卡片实时渲染不可直接操作的 WebQQ 缩略视图，视口外卡片可以延迟挂载
- [ ] AI 正在控制的空间使用不改变尺寸的流光跑马灯边框，减少动态效果偏好下退化为静态强调边框
- [ ] 点击卡片通过 Firefox 与 Chrome 兼容的 FLIP 动画放大进入完整 WebQQ，返回总览时缩回原卡片位置
- [ ] 总览展示所有未删除空间，并支持全部、运行中、已接管、已完成和已失败筛选
- [ ] 用户进入空间默认只读观察，接管后获得完整 WebQQ 操作能力，归还后 AI 可以重新取得控制权
- [ ] 完成和失败空间可以只读复盘或重新激活，重新激活后恢复机器人运行时
- [ ] MCP 事件结果使用 `recipientBotId` 区分同一消息向不同机器人产生的事件投递
