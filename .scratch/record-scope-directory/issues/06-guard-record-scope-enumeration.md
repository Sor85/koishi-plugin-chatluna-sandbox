# 06 — 架构守卫钉住只有记录域目录能枚举记录域

**What to build:** 照抄旧枚举写法的下一次会在测试里报出来，而不是靠代码评审。

新增一条规则制守卫：枚举 AI 测试空间与按标识取控制服务出现在同一段表达式里即报，记录域目录自身是规则的持有者。谓词按写法形状判定，不按文件名列白名单——白名单只约束名单内的文件，会随文件数增长自动失效。

两类合法写法不得误报：纯粹列出空间清单给用户或外部测试控制器看（Console 的空间列表端点与测试控制端点的列表工具），以及带显式空间标识的单空间解析。前者只取清单不取控制服务，后者不枚举，两者都不该命中。守卫自身要有断言证明它认得出违规写法、也不误报这两类。

豁免清单保持为空：前面几张票之后不应存在需要登记的违规。清单与它的三条守卫断言按仓库现有形状保留，下一次真有取舍时再登记。

必须最后做——任何一处未迁移的调用点都会让这条守卫红。

## Comments

- 规则加入 `tests/server-architecture.test.ts` 既有的规则表，describe 改名为「服务端架构守卫」。
- 谓词按写法形状判定：从每处 `X.listSpaces()` 出发只跟着清单仍在流动的那条路——链式数组方法取那对括号，`for…of` 取紧随其后的循环体——再在这段范围里找控制服务取值（`getControl`/`resolveControl`/`requireReadable`/`requireAiControl`/`requireUserControl`）。因此同一个文件里的单空间解析不受影响，清单方法自身的声明也不会被当成枚举。
- 只匹配成员调用，所以 `listSpaces(): T[] {` 这样的声明不命中。
