# 02 — 调试记录的联邦读取改走记录域目录

**What to build:** 调试记录页在不指定范围时的联邦列表、联邦详情与一键清理三条路都经由记录域目录，用户看不到任何变化。

联邦列表不再自己枚举 AI 测试空间，也不再内联一份分页合并；排序、截断、是否还有更多、最早游标与容量累加全部来自记录域目录。调试记录的序号是每个记录域各自独立的计数，跨记录域比较没有意义，因此这条路不声明续页游标——联邦页继续没有精确游标，精确分页仍要求显式指定空间。

联邦详情改用按顺序查找。原先用 try/catch 遍历，一个记录域的持久化故障会被当成未命中静默跳过、最后抛出主环境那个错误；改动后未命中返回空值，故障照原样抛出。这是本票唯一的行为变化，且是修正。

一键清理改用逐个记录域执行后汇总数量。「清理不要求先接管空间」是权限策略，继续留在调用点显式书写，不进记录域目录。

每条记录的来源标注形状不变——记录域目录只提供标识、名字与是否主环境，投影成 Console 出参的形状留在调用点。

模型请求那条路本票不动，两种记录会暂时一新一旧。

## Comments

- `registerConsole` 入口包一份记录域目录（`src/console.ts`），三个可选服务的判空在此吸收一次。
- 联邦列表改用 `federate`，第二排序键声明为 `sequence`，不声明续页游标，因此联邦页仍然没有 `nextCursor`。内联的那份分页合并整段删除。
- 联邦详情改用 `findFirst`。为把「未命中」与「故障」分开，`SandboxControlService` 新增 `findOneBotDebugRecord`（未命中返回 undefined），`getOneBotDebugRecord` 改为在它之上抛错；try/catch 遍历删除。
- 一键清理改用 `forEachScene` 后累加，「清理不要求先接管空间」的理由仍写在调用点。
- 来源标注由调用点的 `sceneSource` 投影，出参形状逐字不变；两种记录共用这一处投影，因为 `SandboxModelRequestSource` 是 `SandboxEntitySource` 的超集。
- 既有两个 Console 调试记录用例一字未改。
