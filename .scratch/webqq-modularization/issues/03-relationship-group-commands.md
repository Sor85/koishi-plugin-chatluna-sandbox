# 03 — 迁移好友、群组与申请命令

**What to build:** 让好友、群组、成员和关系申请操作统一通过工作区控制模块执行，使所有 WebQQ 区域在操作成功后同步观察同一份状态。

**Blocked by:** 02 — 建立工作区端口与控制模块核心

**Status:** ready-for-human

- [x] 好友申请、删除好友和修改好友备注通过工作区控制模块执行
- [x] 入群申请、邀请入群、退出群组和处理关系申请通过工作区控制模块执行
- [x] 戳一戳、踢人、设置管理员、转让群主、修改群名称和群名片通过工作区控制模块执行
- [x] 成功命令原子替换工作区状态并同步更新四个区域模型
- [x] 失败命令保留旧状态并向调用区域抛出规范化错误
- [x] 现有权限判断、菜单项目、菜单位置和事件行为与基准一致
- [x] 新增控制模块命令测试并保留现有好友、群组、通知和权限测试
- [x] Ego Browser 验证关系与群组操作路径且控制台无异常

## Answer

好友、群组和关系申请操作已统一由工作区控制模块补全当前操作者并调用类型化端口，页面不再直接发送 `friend-action` 或 `group-action` RPC。命令成功后仅通过一次工作区替换同步四个区域模型；命令失败和申请不存在时返回统一的 `WorkspaceControllerError`，且保留旧区域模型。

控制模块测试覆盖好友与群组命令的操作者注入、失败原子性、申请类型分派和成功后的四区域同修订。Ego Browser 实际执行并恢复了好友备注和群名称修改路径，验证记录保存在 `.scratch/webqq-modularization/evidence/03-relationship-group-commands/verification.json`；PNG 截图仅保存在本地，不进入提交。
