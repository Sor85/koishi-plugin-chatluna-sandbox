# 模型请求分析页预设变量列表

## Problem Statement

预设编辑器已经把模板中的值表达式高亮，例如 `{time}`、`{weather}`、`{blackListList("nene")}` 和 `{long_memory("guild")}`，并能把单个表达式关联到模型实际收到的请求消息范围。模型请求分析页目前没有从同一运行时预设快照展示这些表达式，复盘人员无法集中查看该预设在本次请求中引用了哪些变量及其展开值。

## Solution

模型请求详情读取已有运行时预设快照，解析其中与预设编辑器相同的值表达式，并复用预设证据匹配算法，把每个表达式映射到本次模型请求消息中的唯一文本范围。详情派生模型请求变量列表，不新增 `before-chat` 变量对象，不持久化第二份变量状态。

分析页左侧在 Tool 与 Response 之间增加 `Variables` 分组，按预设源码顺序列出表达式名；点击后定位右侧对应变量卡片。右侧在 Messages 与 Response 之间增加变量卡片，卡片显示表达式名、来源预设和本次请求中的观察值。

## Decisions

- 变量集合以运行时预设快照中的值表达式为准，与预设编辑器高亮范围一致。
- 控制标签不属于变量列表。
- 函数调用表达式保留完整表达式文本作为变量名，例如 `long_memory("guild")`。
- 变量值只从模型实际收到的请求消息证据范围读取，不从 `before-chat` 对象、插件状态或字符串全局搜索读取。
- 重复表达式按预设源码顺序和 occurrence 分别展示。
- 未执行分支、歧义范围或陈旧模板可以保留变量卡片与明确状态，但不得伪造变量值。
- 变量是模型请求详情读取时派生视图，不进入模型请求持久记录或列表 RPC。
- Triage: ready-for-agent

## Acceptance Criteria

1. 核心和 Character 运行时预设快照都能派生值表达式列表。
2. 左侧显示 `Variables` 分组和变量表达式名，点击可定位右侧卡片。
3. 右侧每个变量一张卡片，展示唯一观察到的展开值。
4. 控制标签不进入变量列表，重复表达式保持源码顺序。
5. 未观察或歧义表达式显示明确状态且不伪造值。
6. 搜索覆盖变量名、值和来源预设。
7. 相关测试、类型检查和客户端构建通过。
