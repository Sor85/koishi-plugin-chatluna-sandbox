# 03 — 渲染历史消息变量预览

Status: resolved

## What to build

模型请求分析页对 `history_new` 和 `history_last` 两个模型请求变量默认展示结构化消息预览，而不是要求复盘人员直接阅读完整 XML。预览从严谨 XML 消息流中提取每条消息的 `name`、`id`、`timestamp` 和消息内容，将元数据作为前置徽标、正文紧随其后；存在 `quote` 引用时，按 WebQQ 消息页的引用层级和视觉语义展示被引用消息。

原始观察值仍是模型请求证据，不得被格式化结果替代或改写；XML 无法可靠解析时必须安全退回原始文本。

## Acceptance criteria

- [x] `history_new` 与 `history_last` 默认显示逐条消息预览
- [x] 每条预览提取并展示 `name`、`id`、`timestamp` 和消息正文
- [x] 元数据使用紧凑徽标显示在正文前
- [x] `quote` 引用在对应消息内按消息页面的引用效果展示
- [x] 原始 XML 仍可查看，且格式化预览不改变模型请求证据
- [x] 非目标变量与不可解析 XML 保持现有安全展示行为
- [x] 解析、引用和渲染相关测试通过

## Comments

用户提供的参考图使用前置类型徽标加单行正文；本实现延续现有模型请求变量卡片与 WebQQ 引用样式，不引入新的消息事实或持久化状态。

实现使用 `fast-xml-parser` 严格校验完整消息序列，只在客户端派生预览。用户消息保持左侧 `name → id → timestamp`，Bot 消息按权威 `botId` 镜像为右侧 `timestamp → id → name`，正文限制最大宽度。Playwright 已检查桌面与窄屏的引用、换行和横向溢出。

带 `messageId` 且请求归属信息完整的消息提供悬停跳转：用户按钮位于正文末尾，Bot 按钮位于元数据行头部。点击后按空间、Bot 操作者和逻辑会话切换到消息页面，按需加载更早历史并滚动高亮目标消息；缺少任一权威标识时不显示按钮。
