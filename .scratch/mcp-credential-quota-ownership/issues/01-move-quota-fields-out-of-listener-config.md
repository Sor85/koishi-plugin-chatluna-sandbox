# 01 — 把测试凭证配额字段从监听器配置移出

**What to build:** 读测试控制端点的 HTTP 监听器时,它的配置只描述传输——监听地址、端口、路径、TLS 证书、来源与 Origin 白名单、启用开关。不再声明四档调用频率上限与三档并发上限,因为那是测试凭证的配额,由测试控制服务执行。

已逐字段核实:监听器配置声明的十七个字段里,七个配额字段在监听器实现中**只有声明行,零处使用**;其余十个传输字段全部在用。配额真正的执行位置在测试控制服务的额度消耗与并发包装两处。读监听器的人会因此误以为限流发生在 HTTP 层。

测试控制服务的选项里已经有这七个同名字段,插件启用时也已经把用户配置逐个交给服务。所以这张票不搬运任何行为,只是把七个从不被读取的声明从监听器配置上摘掉。摘掉后插件启用处显式构造监听器需要的传输配置对象,而不是把整份 MCP 用户配置整体传进去——否则类型上收窄了,读代码的人看到整份配置传入仍会以为监听器需要全部字段,而"误导读者"正是这张票要修的东西。

用户可见的 Koishi 配置项不变,分组也不变:四档频率与三档并发仍然是合理的插件配置项,依 ADR-0025 只能由插件全局配置调整。运行时行为零变化。

依据 ADR-0025(按测试凭证分别限制频率与并发)与 ADR-0030(监听器只提供 MCP Streamable HTTP)。本票是让代码符合这两条既有决策,不新增架构决策记录。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 监听器配置不再声明四档调用频率上限与三档并发上限
- [ ] 监听器配置保留并继续使用全部十个传输字段:启用开关、监听地址、端口、路径、来源白名单、Origin 白名单、允许不安全远程、TLS 证书路径与私钥路径
- [ ] 测试控制服务的选项保持原样,配额执行位置不变
