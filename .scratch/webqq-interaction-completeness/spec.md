# WebQQ 交互完整性规格

Status: ready-for-agent

## Problem Statement

OneBot Sandbox 已经能够在领域层保存消息表情回应、执行账号资料 action、归档 ChatLuna 思考并撤回消息，但 WebQQ 尚未完整呈现这些事实：群消息回应不可见也不可由当前操作者操作；账号资料模型过窄，个性签名被 `set_qq_profile` 静默忽略，也没有统一个人信息卡；撤回仍使用旧事件灰条模型，导致思考内容可能脱离原消息残留；发送控件在一次发送后丢失焦点，并用禁止光标表达禁用状态。

## Solution

补齐群消息表情回应的展示和操作入口；建立类型化 OneBot 账号资料并提供统一个人信息卡；按结构化撤回生命周期实现可切换的“保留删除线/隐藏并显示事件”两种 WebQQ 呈现；修复发送结束后的焦点恢复并移除发送区域禁止光标。所有功能继续遵守当前操作者和操作通道约束，NapCat 与 LLOneBot 的能力差异不得被 WebUI 抹平。

## Implementation Decisions

- 群消息表情回应参考 `koishi-plugin-onebot-webqq` 的 TIM chip 样式，展示表情、回应者头像和总数。
- 消息右键菜单提供“贴表情”，使用本地完整 OneBot/QFace 目录、常用区和搜索；点击已有 chip 切换当前操作者自己的回应。
- 普通用户直接执行用户交互，虚拟 OneBot 机器人必须走 `set_msg_emoji_like`；私聊不提供表情回应。
- 撤回消息保留已有回应但禁止继续修改。
- 账号资料使用类型化可选字段，账号、好友、群成员和机器人运行资料保持独立。
- 所有参与者头像入口都能右键查看个人信息卡；卡片显示场景中已有的全部资料并标明字段范围。
- 个性签名显示在私聊右侧信息面板和个人信息卡，不占聊天头部副标题。
- `set_qq_profile` 严格模拟实现差异：两端支持昵称与签名，只有 NapCat 支持性别修改。
- `webQQMarkRecalledMessages` 默认开启且只影响 WebQQ 展示；底层始终保留撤回前内容和附属状态。
- 开启时原消息显示撤回线，思考保持正常可读但整体弱化；关闭时隐藏原消息与思考并显示撤回事件。
- 普通 OneBot 查询不能读取撤回原文，MCP 和环境管理可读取带撤回状态的权威记录。
- 发送中维持单请求锁；请求结束后仅在原会话和原输入控件仍有效时恢复焦点。
- 发送区域所有禁用控件移除 `cursor: not-allowed`，继续使用 disabled 和透明度表达状态。

## Acceptance Criteria

- 群消息已有回应可见，当前操作者可以通过右键选择器新增回应并点击 chip 取消自己的回应。
- 用户操作和机器人 action 产生相同的场景回应事实；撤回消息上的回应只读。
- `personal_note` 可通过支持的 `set_qq_profile` 写入、持久化并由对应 OneBot 查询读回。
- 个人信息卡可从消息、私聊头部、好友列表和群成员列表头像打开。
- 默认撤回模式保留原气泡、媒体、思考和回应，并显示撤回视觉；关闭后只显示撤回事件。
- 切换撤回配置不会丢失原始数据；OneBot `get_msg` 不能泄露撤回原文。
- 成功和失败发送结束后输入框恢复焦点；切换会话后旧请求不得抢焦点。
- Chrome 与 Firefox 均支持表情选择器、个人卡、撤回呈现和连续输入。
