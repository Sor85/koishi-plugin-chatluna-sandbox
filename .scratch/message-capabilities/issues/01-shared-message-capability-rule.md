# 01 — 共享判据与三处收紧

**What to build:** 「一条消息在某个会话里对某个操作者能做什么」成为一个可以被问的判据，服务端按它拒绝，三处与真实环境不符的宽松因此闭合。

新增 `src/message-capabilities.ts`：纯函数，入参是消息、它所在的逻辑会话、操作者与群聊时的群组，出参是撤回、贴表情、回复、创建分支、合并转发多选五项能力位。继承前缀在会话实例视图里的只读约束是其中一部分，不另开一处判断。

服务端的写入路径改为先问它：撤回的群角色阶梯从 `assertCanManageMember` 与客户端两份收成一份，错误文案保持不变——它们是外部测试控制器已经在断言的用户可见事实。三处分歧按真实环境的样子收紧：事件消息不能贴表情、不能作为分叉点，已撤回消息不能被引用。三条都是把服务端收到客户端本来的严格程度，因此界面行为不变。

判据共享，强制仍在服务端：客户端的答案只用来渲染菜单，永远可以被绕过。

**Blocked by:** 无

**Status:** ready-for-agent

- [ ] 五项能力位各自的允许与拒绝都由判据模块的测试逐条覆盖
- [ ] 给一条事件消息贴表情被拒绝，经 Console 端点同样被拒绝
- [ ] 从一条事件消息分叉被拒绝
- [ ] 引用一条已撤回的消息被拒绝
- [ ] 撤回的群角色阶梯只有一处实现，收敛后行为与错误文案不变
- [ ] 合并转发对事件与已撤回消息的既有拒绝行为不变
