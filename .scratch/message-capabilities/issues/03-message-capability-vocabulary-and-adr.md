# 03 — 消息能力术语与 ADR

**What to build:** 把「消息能力」写进仓库的领域记录，并交代判据共享而强制留在服务端这个取舍。

领域词汇新增「消息能力」条目：一条消息在某个逻辑会话里对某个操作者可执行的动作集合，由消息的生命周期状态、事件属性、会话归属与群角色共同决定；同时列出应避免的替代叫法（权限、可用动作、菜单项、消息状态）。

新增一条 ADR，覆盖三个决定：判据共享成一份而两边都问它（分开判会静默漂移，本轮实测出三处已经漂了）；强制仍在服务端、客户端的答案只用来渲染菜单（客户端答案永远可被绕过，这条不因判据共享而改变）；能力位不算进快照载荷（判据共享后客户端自己就能算，没有理由让每条消息在 RPC 上多带几个布尔值）。

顺带交代三处收紧的方向依据：真实 QQ 里系统提示不是可操作的消息，已撤回消息也不能被引用；沙盒表现出真实环境不存在的状态时，对它做出的断言就证明不了任何事。

## Comments

### 实现记录

- `CONTEXT.md` 新增「消息能力」条目，紧跟「消息生命周期状态」，`_Avoid_` 列出消息权限、可用动作、菜单项、消息状态四个应避免的叫法。
- 新增 `docs/adr/0078-share-one-message-capability-rule.md`，覆盖三个决定：判据共享成一份而两边都问它、强制仍在服务端而客户端答案只用于渲染、能力位不进快照载荷。三处收紧的方向依据（真实 QQ 里系统提示不是可操作的消息、已撤回消息不能被引用）写在第二段。
- **与既有 ADR 的关系已明确标注，未静默覆盖**：ADR-0077 里「只读约束的是用户在分支视图里的操作入口」在本文里落成两个能力位，那条决定本身不变；ADR-0073 的肯定式接线断言例外因判定可观察而不再需要，本文说明了这一点。
- ADR 里额外交代了一处规格没写的取舍：事件消息的「回复」位不收紧。收紧范围以实测出的分歧为界，而事件消息在 WebQQ 里不渲染右键菜单，客户端从未对它推导过回复位，因此没有第二份口径可漂；沙盒把事件存成带 ID 的消息，插件仍按普通消息寻址它。
