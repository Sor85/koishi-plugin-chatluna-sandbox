# 消息能力判定收成一处

Status: resolved

## Problem Statement

「这条消息现在能做什么」在沙盒里被判两遍：服务端在写入路径上强制它，客户端为了决定右键菜单显示哪几项又各自推导一遍，两者之间没有任何东西把它们绑在一起。

三处已经分开了，都是客户端比服务端严：客户端在事件消息上不显示「贴表情」，而服务端会给一条戳一戳事件挂上表情回应；客户端在事件消息上不显示「创建分支」，而服务端接受从事件消息分叉；客户端在已撤回消息上不显示「回复」，而服务端接受引用一条已撤回的消息。三条都能经 Console 端点直接达到，不必路过菜单——挡住它们的只有客户端那份推导。

方向反了也一样糟：真实 QQ 里没有「给系统提示贴表情」这回事，也不能引用一条已经撤回的消息。沙盒的全部价值在于对它做出的断言能反映真实环境，而这三处正在让沙盒表现出真实环境不存在的状态。

撤回是第四种情形：群主与管理员能撤谁的消息，这套角色阶梯在服务端和客户端各写了一遍，今天答案一致，但没有任何测试要求它们保持一致。改任一边都不会有人变红。

判定住在 `.vue` 里还有一个连带后果：它从组件外观察不到，因此 03 与 05 两张票都只能退回源码文本断言，而 ADR-0073 明确说那类断言在等价重构时变红、在真实回归时沉默。两张票各自把这笔债记在自己的「留给后续票的观察」里，指向的就是本规格。

## Solution

一条消息在某个会话里对某个操作者能做什么，成为一个可以被问的判据，问一次，两边都用它：服务端在写入路径上按它拒绝，客户端把它的答案渲染成菜单。

用户能感觉到的变化很小，因为客户端本来就是严的那一边：菜单和今天一样。变的是它不再是唯一的防线——同一条规则从 Console 端点、外部测试控制器和未来的 MCP 工具进来时同样成立，沙盒因此不再凭入口的不同给出两种答案。

被测插件与外部测试控制器会看到三处收紧：给事件消息贴表情、从事件消息分叉、引用一条已撤回的消息，现在都按真实环境的样子被拒绝。

## User Stories

1. As a 沙盒用户, I want 右键菜单里出现的动作都真的做得到, so that 我不必靠试错分辨哪些会失败
2. As a 沙盒用户, I want 菜单和今天一样, so that 这次改动不用我重新学一遍界面
3. As a 插件维护者, I want 给一条戳一戳事件贴表情被拒绝, so that 沙盒不表现出真实 QQ 不存在的状态
4. As a 插件维护者, I want 从一条事件消息分叉被拒绝, so that 分支的起点总是一句真的说过的话
5. As a 插件维护者, I want 引用一条已撤回的消息被拒绝, so that 撤回不会经引用旁路重新露出原文
6. As a 插件维护者, I want 经 Console 端点绕过界面时同样被拒绝, so that 挡住它的不再只是菜单
7. As a 插件维护者, I want 撤回的群角色阶梯只有一处实现, so that 改动它不会留下另一处旧答案
8. As a 插件维护者, I want 「这条消息能做什么」有一个可以从外部问的答案, so that 右键权限能用行为断言而不是源码文本守住
9. As a 插件维护者, I want 客户端不再自己推导消息能力, so that 下一个改菜单的人不会又开出第二份判据
10. As a 插件维护者, I want 「消息能力」作为领域术语写进领域词汇, so that 它不会被叫成权限、可用动作或菜单项
11. As a 插件维护者, I want 一条 ADR 说明判据为什么共享而强制仍在服务端, so that 后来人不会把它读成「客户端说了算」

## Implementation Decisions

### 判据的形状与住处

- 新增 `src/message-capabilities.ts`，纯函数，不持有场景：入参是一条消息、它所在的逻辑会话、操作者，以及群聊时的群组；出参是一组布尔位。形态与 `conversation-resolution.ts` 一致——一组接收沙盒场景与实体的函数，不是持有状态的类。
- 放在 `src/` 而不是 `client/`：客户端已经直接引用 `src/types.ts` 与 `src/conversation-resolution.ts`，这是仓库既有的共享方式。放到 `client/` 会让服务端反向依赖客户端目录。
- **判据共享，强制仍在服务端。** 客户端拿到的答案只用来渲染菜单，不作为许可；服务端的写入路径照旧自己问一遍再拒绝。客户端的答案永远可以被绕过，这条不因为判据共享而改变。
- 能力位覆盖五项，正好是客户端今天在推导的那五项：撤回、贴表情（含切换已有回应）、回复、创建分支、合并转发多选。「跳转到对应请求」不是能力而是有没有证据可跳，不并入。
- 继承前缀的只读约束进入同一组能力位：它已经是「这条消息在这个会话里能做什么」的一部分，03 号票把它散在三个函数里，本规格把三处收成一处读取。

### 三处分歧的收紧方向

- 事件消息不能贴表情、不能作为分叉点：真实 QQ 里系统提示不是一条可操作的消息。服务端补上这两条判定。
- 已撤回消息不能被引用：撤回是生命周期状态（ADR-0049），引用它等于给原文开一条旁路。机器人表面早已按这条办——`toUniversalMessage` 在引用目标已撤回时不给 `quote`；本规格让写入路径与它一致。
- 三条都按「客户端本来的严格程度」收紧，因此界面行为不变，变的是别的入口。合并转发那条本来就一致，不动。

### 客户端

- `messageList` 投影为每条消息给出能力位，`.vue` 里的 `canRecallMessage`、`canReactToMessage`、`isReactionReadonly`、`isMessageSelectable` 退化成读取投影结果。判定因此从组件里搬到工作台外壳的投影里，能从 `chatPaneModel` 的 interface 上观察到。
- 03 与 05 留下的源码文本守卫换成对投影的行为断言。三个写入入口（右键撤回、右键贴表情、气泡下方已有回应条）仍要逐个覆盖：它们读同一份能力位，但少接一个仍然是一条绕路。
- 新增一条客户端架构守卫规则：客户端源码不得自己推导消息能力。按 ADR-0073 的规则制写谓词，跑遍客户端全部源码，`webqq/message-capabilities` 这类读取投影的路径不算违反。

### 服务端

- 撤回的群角色阶梯从 `assertCanManageMember` 与客户端两份，收成共享判据一份：`recallVisibleMessage` 改为先问能力位，拿到否再按现有文案抛错。错误文案不变——它们是外部测试控制器已经在断言的用户可见事实。
- 群成员菜单与好友菜单的权限不并入。它们回答的是「一个成员能对另一个成员做什么」，与「一条消息能做什么」不是同一个问题，且各自已有纯模块与测试。

### 文档

- 领域词汇新增「消息能力」：一条消息在某个逻辑会话里对某个操作者可执行的动作集合，由消息的生命周期状态、事件属性、会话归属与群角色共同决定。
- 新增一条 ADR：判据共享、强制留在服务端、客户端答案只用于渲染；并说明为什么不把能力位算进快照载荷。

## Testing Decisions

好的测试从 interface 观察外部行为。按 ADR-0073，源码文本断言只在架构守卫、样式与用户可见文案三类例外中使用；本规格的目标之一正是把 03 与 05 留下的肯定式接线断言换掉，因此不得新增同类断言。

**本规格不新增 seam。** 共享判据是一个纯函数模块，与 `message-cluster.ts`、`fork-boundary.ts` 同形；其余变更都落在既有的控制服务与客户端投影两个 seam 上。

### 测试面

1. **共享判据的 interface（纯模块，主要测试面）**——先例是 `group-menu` 与 `fork-boundary` 的测试。覆盖五项能力各自的允许与拒绝：自己的消息可撤回、群主可撤成员、管理员不可撤管理员或群主、普通成员不可撤别人、事件消息不可贴表情也不可分叉、已撤回消息不可回复也不可再贴表情、继承前缀在实例视图里不可撤回也不可贴表情。
2. **控制服务的公开方法（既有 seam）**——覆盖三处收紧各自被拒且文案与既有一致，以及撤回的角色阶梯在收成一处后行为不变。
3. **客户端投影（既有 seam）**——先例是会话树测试。覆盖：`messageList` 为每条消息给出能力位、继承前缀的位与自有消息不同、群角色变化后位随之变化。
4. **客户端架构守卫（规则制）**——谓词自测加全量扫描，与既有两条规则同处登记。

## Out of Scope

- **把能力位算进快照载荷**。判据共享后客户端自己就能算，没有理由让每条消息在 RPC 上多带几个布尔值。
- **群成员菜单与好友菜单的权限**。
- **引入组件挂载测试**。`.vue` 模板里剩下的 `v-if` 仍然只能靠投影侧的行为断言加用户可见文案守住。
- **能力位对应的 MCP 工具**。MCP 目前没有撤回与表情回应工具，本规格不新增。
- **机器人操作者绕行自身 OneBot action 这条通道**。它由操作通道决定，不是消息能力。

## Further Notes

- 三处分歧是实测出来的，不是读代码猜的：给戳一戳事件贴表情会成功并留下回应事实，从事件消息分叉会成功建出实例，引用已撤回消息会成功写入回复。实现时应先用这三条断言把现状钉红，再收紧。
- 「客户端不再自己推导」与「客户端答案不作为许可」两句不矛盾：前者说的是判据只有一份，后者说的是那份判据在客户端的运行结果不构成授权。服务端照旧自己问一遍。
