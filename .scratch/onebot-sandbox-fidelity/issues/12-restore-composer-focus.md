# 12 — 恢复发送控件焦点并移除禁止光标

**What to build:** 保持现有单请求发送锁，在消息发送成功或失败后可靠恢复原输入控件焦点，并统一移除发送区域禁用控件的禁止光标，使用户可以连续键盘输入和发送。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] textarea 使用稳定的输入控件引用，并在发送成功后的下一次渲染完成后恢复焦点
- [ ] 发送失败后同样恢复焦点，用户可以立即修改内容并重试
- [ ] 连续执行“输入—回车—输入—回车”无需再次使用鼠标点击输入框
- [ ] 发送期间继续禁用重复提交，不引入发送队列或同一 composer 的并发发送
- [ ] 只有原 conversation、原操作者和原 composer 实例仍然有效时才恢复焦点
- [ ] 发送期间切换会话后，旧请求完成不会把焦点抢回旧输入框
- [ ] 发送期间切换当前操作者后，旧请求不会影响新身份的输入控件
- [ ] 组件卸载或页面离开后，请求完成不会访问失效元素或产生运行时错误
- [ ] textarea、附件、表情和发送按钮禁用时均不显示 `not-allowed` 光标
- [ ] disabled 语义、可访问性状态和透明度仍清楚表达不可操作状态
- [ ] 通过 WebQQ 工作区 seam 覆盖成功、失败、连续发送、会话切换、操作者切换和卸载
- [ ] 使用 Ego Browser 验证 Chrome、Firefox 和键盘连续发送，并清理浏览器临时文件
- [ ] 运行针对性测试、项目测试、类型检查和完整构建并全部通过
