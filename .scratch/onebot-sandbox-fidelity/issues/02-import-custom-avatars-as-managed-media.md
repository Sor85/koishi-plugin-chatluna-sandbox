# 02 — 将自定义头像导入受管媒体

**What to build:** 将机器人、普通用户和群组的自定义头像统一导入 Sandbox 媒体存储，使各种输入格式都变成可显示、可持久化的媒体引用，并修复重启后头像看似恢复默认的问题。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] URL、Data URL、`base64://` 和上传文件头像均在写入场景前导入媒体存储
- [ ] 场景只保存媒体引用，不保存外部 URL、Data URL、`base64://` 正文或原始二进制
- [ ] 机器人通过真实 `set_qq_avatar` action 修改自身头像，并产生正确的动作记录
- [ ] 普通用户和群组头像可通过环境管理、MCP 场景准备和场景导入设置，不新增虚假 OneBot action
- [ ] 导入后的头像可以被 WebQQ 正确显示，并在页面刷新和插件重启后保持不变
- [ ] 场景导入导出可以稳定往返自定义头像引用而不内嵌媒体正文
- [ ] 现有持久化字符串头像执行一次性规范化导入，规范化完成后不保留双格式读取路径
- [ ] 无效或无法读取的头像输入返回明确错误，且不破坏实体原有头像
- [ ] 通过沙盒领域 seam 验证各输入形式、协议 action、持久化恢复和 WebQQ 可见性
- [ ] 运行针对性测试、项目测试、类型检查和完整构建并全部通过
