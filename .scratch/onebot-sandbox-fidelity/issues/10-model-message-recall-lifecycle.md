# 10 — 将撤回建模为消息生命周期

**What to build:** 把消息撤回从覆盖正文的系统事件改为原消息的结构化生命周期状态，保留测试所需权威事实，同时维持真实 OneBot 不可读取撤回原文的语义，并修复 ChatLuna 晚到归档错位。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 活跃和已撤回消息使用明确的生命周期状态，已撤回状态记录操作者和撤回时间
- [ ] poke 等系统事件继续使用事件模型，不再与撤回共用一个事件联合
- [ ] 撤回保持原消息身份和会话位置，并在权威场景中保留正文、媒体、回复关系、表情回应和 ChatLuna 信息
- [ ] 普通 OneBot `get_msg` 和机器人查询无法读取已撤回消息原文
- [ ] MCP 与环境管理可以读取带生命周期状态的权威记录，用于测试复盘
- [ ] 撤回发出结构化 `message.recalled` 事件，同时继续发出 `scene.changed`
- [ ] 已撤回消息拒绝新增或取消表情回应，但保留撤回前已有回应
- [ ] ChatLuna 归档使用目标回复消息的精确身份，不因目标已撤回而向前匹配更早机器人消息
- [ ] 撤回早于 ChatLuna 归档完成时，思考只归属于原目标消息或保持未归档，不得错误迁移
- [ ] 场景持久化、导入导出和重启恢复保留消息生命周期及权威内容
- [ ] 现有旧撤回事件表示被直接替换，不保留未发布双模型 fallback
- [ ] 通过沙盒领域 seam 和 MCP seam 覆盖协议可见性、事件、回应锁定、持久化和归档竞态
- [ ] 运行针对性测试、项目测试、类型检查和完整构建并全部通过
