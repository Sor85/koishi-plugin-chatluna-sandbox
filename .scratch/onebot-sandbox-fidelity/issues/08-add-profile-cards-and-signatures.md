# 08 — 增加个人信息卡与私聊个性签名

**What to build:** 让 WebQQ 能从所有参与者头像入口打开统一的只读个人信息卡，并在私聊信息面板中显示个性签名，使场景中的类型化资料成为可见、可区分的测试事实。

**Blocked by:** 07 — 建立类型化 OneBot 账号资料

**Status:** resolved

- [x] 消息头像、私聊头部头像、好友列表头像和群成员列表头像均提供“查看资料”右键操作
- [x] 当前操作者、普通用户和机器人自己的头像均可打开资料卡
- [x] 个人信息卡显示头像、昵称、个性签名以及场景中该参与者全部可用资料
- [x] 卡片将字段明确分组为账号、好友、群成员和机器人运行范围，不混淆同名字段
- [x] 卡片是只读测试观察视图，不增加资料编辑功能，也不按当前操作者视角隐藏字段
- [x] 私聊右侧信息面板显示对方个性签名，聊天头部副标题保持现状且不重复显示
- [x] 新右键操作与已有回复、戳一戳、好友和群管理操作共存，不覆盖原菜单行为
- [x] 缺少可选资料时卡片保持清晰紧凑，不显示误导性的伪造数据
- [x] 浮层在明暗主题下使用明确主题变量，不出现异常黑边、透明按钮或不可读文本
- [x] 通过 WebQQ 工作区 seam 测试所有头像入口、资料分组、签名位置和空字段呈现
- [ ] 使用 Ego Browser 验证 Chrome、Firefox、桌面和窄屏，并清理浏览器临时文件
- [x] 运行针对性测试、项目测试、类型检查和完整构建并全部通过

说明：本会话未接入 Ego Browser / 浏览器自动化工具，浏览器矩阵验证项暂未执行；主题变量与入口/分组已由 seam 测试覆盖。
