# 11 — 实现可切换的撤回消息呈现

**What to build:** 为 WebQQ 增加默认开启的撤回消息保留模式，使用户可在测试证据视图与普通 QQ 撤回事件视图之间切换，而不改变权威数据或 OneBot 行为。

**Blocked by:** 09 — 补齐群消息表情回应交互；10 — 将撤回建模为消息生命周期

**Status:** ready-for-agent

- [ ] 提供默认开启的 `webQQMarkRecalledMessages` 配置，并在配置界面清楚说明其仅影响 WebQQ 展示
- [ ] 开启时保留原消息气泡和会话位置，文本显示删除线，图片及其他媒体显示撤回线
- [ ] 开启时消息整体弱化并显示“已撤回”，但不会被误认为仍可交互的活跃消息
- [ ] 开启时 ChatLuna 思考继续归属于原消息并保持可读，同时随消息整体降低强调
- [ ] 开启时撤回前已有表情回应继续显示，但所有回应入口和 chip 切换均为只读
- [ ] 关闭时隐藏原气泡、ChatLuna 思考和表情回应，仅显示结构化撤回事件
- [ ] 在两个模式之间切换不会修改或销毁权威正文、媒体、回复、回应和思考数据
- [ ] 重新开启配置后，之前隐藏的撤回消息和诊断信息立即恢复
- [ ] 普通 OneBot 对撤回原文的不可见性不受 WebQQ 配置影响
- [ ] 通过 WebQQ 工作区 seam 测试文本、媒体、思考、回应、事件模式和无损切换
- [ ] 使用 Ego Browser 验证 Chrome、Firefox、桌面、窄屏和明暗主题，并清理浏览器临时文件
- [ ] 运行针对性测试、项目测试、类型检查和完整构建并全部通过
