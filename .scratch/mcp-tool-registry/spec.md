# 一个工具的全部事实住在注册表的一条条目上

Status: ready-for-agent

## Problem Statement

测试控制端点对外提供 40 个工具。要加第 41 个，得在五个地方各写一次，而只有一处漏了会响。

一个工具的事实今天这样分布：名字、权限范围与说明在一张表里；参数 schema 在另一张同键的表里；它属于哪一类配额、要不要占并发闸门，写成调用治理里两句内联的字符串判定（工具名是不是以某个前缀开头、是不是某个特定名字、权限范围是不是只读）；它要不要幂等、要不要确认令牌，靠分派链里那一支包不包某个包装器来表达；它算不算写操作——这决定按显式空间标识解析时走不走门禁——写成**一句九项否定条件**。

分派本身是一条 43 个分支的条件链，106 行。漏掉一支的表现是：工具出现在 `tools/list` 里，AI 客户端发现它并调用，拿回「工具不存在」。

两张同键表的连接写法是「按名字取，取不到就给一个空 schema」。**键打错会静默产出一个空 schema**，而 schema 是 AI 消费者唯一能学到参数契约的地方——`tools/list` 之外没有别处。

配额分类与并发分类各写一句，逐项比对后只有一处不同：只读类不占并发闸门。这两句在两个不同的表达式里各自维护同一份工具分类。

## Solution

把一个工具的全部事实收成注册表上的一条条目：名字、权限范围、说明、参数 schema、配额与并发分类、算不算写操作、要不要幂等、要不要确认令牌，以及它的执行体。

加一个工具从「在五处各写一次」变成「注册一条」。调用治理随之变成一条直线：查注册表、校权限范围、扣配额、过并发闸门、按标记包幂等或确认令牌、执行、写测试调用记录、归一化错误。

对外一字不变。工具清单、每个工具的参数 schema、能力目录、按权限范围过滤的结果、稳定错误码、测试调用记录的形状全部逐字相同；MCP 表述与 HTTP 测试接口继续落到同一次工具调用上。

## User Stories

1. As a 外部测试控制器使用者, I want 工具清单与每个工具的参数 schema 一字不变, so that 我的客户端不必重新学参数契约
2. As a 外部测试控制器使用者, I want 按凭证权限范围过滤的工具清单结果不变, so that 我的凭证能力没有变化
3. As a 外部测试控制器使用者, I want 能力目录的完整输出不变, so that 我据以生成调用代码的那份自述仍然有效
4. As a 外部测试控制器使用者, I want 稳定错误码与错误信封不变, so that 我的重试与判定逻辑不必改
5. As a 外部测试控制器使用者, I want 失败信封里的 traceId 仍然能取回那次调用的记录, so that 我仍能复盘一次失败
6. As a 外部测试控制器使用者, I want MCP 表述与 HTTP 测试接口的权限、配额、幂等、确认令牌与调用记录仍然完全相同, so that 我换一种表述不必重新验证额度
7. As a 外部测试控制器使用者, I want 幂等键的说明仍然反映实际配置的窗口与条数, so that 我知道同键重放多久之内有效
8. As a 外部测试控制器使用者, I want 每个工具仍然自动带上调用标注参数, so that 我仍能按一轮编排回溯全部调用
9. As a 外部测试控制器使用者, I want 破坏性操作仍然要求版本绑定的一次性确认令牌, so that 我不会误抹掉一个环境

12. As a 外部测试控制器使用者, I want 清理类工具仍然要求显式指定范围, so that 一个凭证不会一次抹掉全部证据

14. As a 沙盒用户, I want 测试调用记录列表、详情与清理结果不变, so that 我仍能在界面上复盘一轮编排
15. As a 插件维护者, I want 加一个工具只需注册一条, so that 不会漏掉五处里的任何一处
16. As a 插件维护者, I want 「声明了工具但没有分派」这种状态不可表达, so that 不会出现清单里有、调用时说不存在的工具
17. As a 插件维护者, I want 参数 schema 与工具名之间不再有按键连接, so that 键打错不会静默产出一个空 schema
18. As a 插件维护者, I want 配额分类与并发分类只写一次, so that 两句表达式不会各自维护同一份分类
19. As a 插件维护者, I want 「算不算写操作」是条目上的一个显式字段, so that 那句九项否定条件不再藏着两个与配额分类不一致的工具
20. As a 插件维护者, I want 幂等与确认令牌是条目上的两个显式标记, so that 一个工具要不要它们不必靠读分派链推断
21. As a 插件维护者, I want 调用治理读起来是一条直线, so that 排查「这次调用为什么被限流／为什么要确认令牌」只看一处
22. As a 插件维护者, I want 一次工具调用仍然只有一个外部编排入口, so that 两种协议表述不会各自长出一份治理

25. As a 插件维护者, I want 每个工具仍然自动获得调用标注参数的声明, so that 「新增工具自动带上它」仍然是默认行为

30. As a 插件维护者, I want 事件等待与凭证持久化本轮不动, so that 一次收拢的范围可以被证明
31. As a 插件维护者, I want 这道归属被写进 ADR, so that 下一个人知道工具的事实该写在哪里

## Implementation Decisions

### 只做工具注册表，调用治理变窄是它的结果

- 报告提了三个内部 module（调用治理、工具注册表、事件等待）加一个凭证持久化 adapter。本轮只做注册表。
- 依据是报告自己写下的验收标准：只把长条件链搬家不算加深。一次工具调用的外部编排入口今天已经是唯一的，只有三十行；把它挪进另一个文件不会让它更深。真正让治理变窄的是把工具元数据搬走——之后它剩下的是一条直线：查注册表、校权限范围、扣配额、过并发闸门、按标记包幂等或确认令牌、执行、写测试调用记录、归一化错误并回填场景版本。
- 事件等待（游标、静默期等待、纪元轮转）与凭证持久化各自自洽、与注册表无依赖，留作后续候选。本轮已经要动 40 个工具、五处元数据与一份对外契约。

### 一条条目九个字段

- 名字、权限范围、说明、参数 schema、配额与并发分类、是否按写操作解析空间、是否幂等、是否需要确认令牌、执行体。
- **配额分类与并发分类是同一个字段。** 两者今天各写一句，逐项比对后只有一处不同：只读类不占并发闸门。因此条目上放一个分类，「只读不占并发」变成治理里的一行，而不是每个工具的第二个字段。
- **「算不算写操作」不能从分类推导。** 清理调试记录与清理模型请求记录的权限范围是调试类（分类为只读），但它们按写操作解析显式空间。这正是那句九项否定条件藏住的东西，所以它是独立字段。
- **幂等与确认令牌是两个独立标记。** 十一个工具要幂等，四个要确认令牌，上传媒体与准备确认令牌两个都不要。今天没有工具同时命中两者，因此组合顺序在治理里定死一次并注明「今天不可观察」，而不是合成一个三态枚举去表达一种不存在的状态。

### 注册表是模块级常量，执行体是自由函数

- 注册表必须是模块级常量。幂等键的说明文案由实例配置决定（窗口时长与保留条数），今天靠读取时注入——所有对外读取工具声明的路径都经同一处，声明因此不可能与实际配置漂移。注册表变成实例构造的东西就要重写这条保证。
- 执行体是自由函数，签名收一份窄的调用运行时（取已解析的控制服务、追加事件、当前游标、要求测试空间、要求未归属记录库等）。不用方法名字符串——那会让类型检查失效。

### 两张同键表合成一张，参数 schema 内联到条目上

- 今天工具声明与参数 schema 是两张按名字连接的表，连接写法是「按名字取，取不到就给一个空 schema」。**键打错会静默产出空 schema**，而 schema 是 AI 消费者唯一能学到参数契约的地方。内联之后这个连接不存在了，也就没有静默失败的余地。
- 代价是注册表本身会到八九百行（其中参数 schema 约 358 行）。但它是一张表而不是逻辑，「一个工具一处」正是本轮要的结果。
- 两条注入原样保留：给每个工具补调用标注参数的那一步（逐个工具书写既冗余又必然漏，统一注入让「新增工具自动带上它」成为默认行为），以及读取时把幂等窗口文案写进对应参数说明的那一步。

### 一次工具调用仍然只有一个外部编排入口

- 两种协议表述继续落到同一次调用上。两个协议适配器今天都只把工具名原样透传，不做任何工具名判定——本轮不改这一点。
- ADR-0081 的硬约束因此照旧成立：两种表述落到同一次工具调用上的权限、配额、幂等、确认令牌与测试调用记录不存在第二份实现。**治理不得下沉到某一个表述里。**

### 守卫无例外

- 新增一条规则：服务端源码里工具名不得与字符串字面量比较。谓词按标识符名判定——工具名标识符与字面量的相等或不等比较，以及在这类标识符上调前缀判定并传字面量。
- 不用宽松的「某个名字等于字面量」形状：那个形状在模型证据那一族里有一处合法命中，会变成误报。
- 规则跑遍服务端源码、不列文件白名单。迁完后**零违规、零豁免，也不需要持有者**——注册表条目里工具名是属性值而不是比较，谓词命不中它。

### 展开—迁移—收缩，只分两批

- 40 个工具，只读与调试各 10 个、交互 9 个、管理 11 个，因此两批正好各 20 个。
- 第一批取只读与调试：这一半不涉及幂等与确认令牌，但清理类工具恰好会用到「算不算写操作」这个字段，因此条目形状能在容易的一半上先证明出来。第二批上交互与管理，那是幂等与破坏性确认所在。
- 迁移期间保留一段回落分派（先查注册表，查不到落回旧条件链），约五行临时脚手架，在第二批里连旧链一起删掉。两批各自都能绿。

## Testing Decisions

好的测试断言外部可观察的行为，而不是实现写法。本仓库的判据已经写下来了：肯定式实现细节断言在等价重构时变红、在真实回归时沉默。本规格不新增任何一条这样的断言。

**净新增 seam 数：零。** 本轮全部事实都落在既有 seam 上。这是这份清单里条件最好的一轮——对外契约已经被两份**独立书写**的测试从外部钉住了。

### 主测试面

- **一次工具调用的那个入口（既有 seam，最高的那个）**。既有的一个测试构造辅助把「控制服务 ＋ AI 测试空间 ＋ 测试控制服务 ＋ 凭证」搭起来，16 个测试文件约 130 个用例全部经这一个入口驱动。它的注释就写着为什么：凭证校验、权限范围检查、限流分类、并发包装、幂等与调用记录一并被覆盖，下降到领域服务各自的方法会漏掉这些行为。这一族一字不改地继续通过，就是本轮的回归网。
- **两份对外契约测试（既有 seam，主证据）**。一份是测试侧独立书写的工具目录，另一份逐工具断言顶层参数名集合。后者的注释明确写着「不从实现导入——从实现导入只能证明实现等于自己，字段被误删、误加、改名都不会变红」，断言对象取自公开的能力目录接口而不是源码文本。**两份都不改一字。**
- **服务端架构守卫（既有 seam）**。新规则与它的正反自测在这里。

### 不新增的断言

- 不为注册表本身写「条目形状正确」这类断言：那是肯定式实现细节断言，等价重构时变红。条目是否正确由两份契约测试与那 130 个用例从外部证明。
- 不为「每个声明的工具都可分派」单独写一条断言：注册表落地后这个状态不可表达——条目自带执行体，没有条目就没有工具。这条从「需要断言的规则」变成「不可能发生的状态」，是本轮的收益之一而不是待补的覆盖。

### 纯结构性的证明

- **两份契约测试一字不改地通过。** 主证据，且它不来自实现。
- **stash 基线比对能力目录的完整输出与 40 个工具的参数 schema 完整 JSON**，逐字节相同。
- **完整测试、类型检查与构建通过。**
- **`git diff --stat` 里没有客户端路径。** 本轮客户端一行不改。不开浏览器。
- 每张票各跑一次。基线作为票的证据留在本 feature 目录下。

### 别处变红的处置

改测试控制服务会让读它源码或按私有方法名断言的测试变红。逐条区分真红与假红——标识符变化跟着改是假红，行为口径或成本结构变化是真红，停下来查——并在票的 Comments 里逐条记处置。**不重判前几轮已经判定保留的断言。**

## Out of Scope

- **事件等待成为 module。** 游标、静默期等待、纪元轮转是一组自洽的东西，与注册表无依赖，单独成候选。
- **凭证持久化成为 adapter。** 同上，与注册表无依赖。
- **把调用治理搬进单独的文件。** 报告自己的验收标准说只搬家不算加深；治理变窄是注册表落地后的结果，不是一个独立动作。
- **收窄测试控制服务的公开成员表。** 核过之后两组消费方（凭证与调用记录管理面、两个协议表述的调用面）的交集是空的，这是一条真实的候选，但它要先决定管理面归谁，与本轮无关。
- **公开但只有测试在用的那个游标读取成员。** 归上面那条候选。
- **两个协议适配器。** 它们今天只把工具名原样透传，本轮一行不改。
- **工具的参数校验口径。** 传输层按既有决定只把 schema 当文档暴露、不做参数校验，校验责任留在执行体内部，本轮不改。
- **界面、文案、样式与交互的任何调整。** 本轮没有行为变化，一处例外都没有。

## Further Notes

- 最值得做的不是少一条 43 分支的链，而是「声明了工具但没有分派」这个状态变得不可表达。它今天的失败形态是：工具出现在清单里，AI 客户端发现它并调用，拿回「工具不存在」——发现得晚且发现者是消费者。
- 第二值得的是那个按名字连接的 schema 表。键打错会静默产出一个空 schema，而 schema 是 AI 消费者唯一能学到参数契约的地方。这一类「查不到就给个默认值」的连接是静默失败的典型来源，内联之后连接本身消失。
- 配额分类与并发分类只有一处不同这件事，是把五处元数据摊到一起之后才看得见的。同理，「算不算写操作」与配额分类**不一致**的那两个清理类工具，今天藏在一句九项否定条件里——把它写成字段是本轮唯一一处让隐含事实变显式的地方，其余都是搬迁。
- 本轮不需要浏览器，也不需要为纯结构性另造证据：对外契约已经有两份不来自实现的测试钉着。这是前几轮反复想要而没有的条件。
- 领域词汇核一遍，预期无需新词——「测试控制端点」「测试调用记录」「AI 测试空间」「稳定错误码」都已在册。
- 新增一条 ADR：一个工具的全部事实住在注册表的一条条目上；一次工具调用仍只有一个外部编排入口，两种表述的治理不存在第二份实现；配额与并发同字段而「算不算写操作」独立；幂等与确认令牌是两个独立标记。写明不推翻 ADR-0081（两种表述并列且治理只有一份）、ADR-0027（三类错误的归一化）、ADR-0020（测试端点保持显式范围）、ADR-0028（测试 API 版本推进）。
