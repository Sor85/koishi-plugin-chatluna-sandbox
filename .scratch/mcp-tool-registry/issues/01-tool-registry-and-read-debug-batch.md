# 01 — 工具注册表落地，只读与调试两类先迁过去

**What to build:** 外部测试控制器看到的工具清单、参数 schema、能力目录与错误信封一字不变，但其中二十个工具的全部事实已经住在注册表的一条条目上，调用治理读的是条目字段而不是内联的字符串判定。

条目九个字段：名字、权限范围、说明、参数 schema、配额与并发分类、是否按写操作解析空间、是否幂等、是否需要确认令牌、执行体。**配额分类与并发分类是同一个字段**——两者今天各写一句，逐项比对后只有一处不同（只读类不占并发闸门），那一处变成治理里的一行。**「算不算写操作」是独立字段，不能从分类推导**：清理调试记录与清理模型请求记录的权限范围是调试类（分类为只读），却按写操作解析显式空间——这正是那句九项否定条件藏住的东西。

参数 schema 内联到条目上，两张按名字连接的表合成一张。今天的连接写法是「按名字取，取不到就给一个空 schema」——**键打错会静默产出空 schema**，而 schema 是 AI 消费者唯一能学到参数契约的地方。内联之后这个连接不存在了。

注册表是**模块级常量**，执行体是自由函数收一份窄的调用运行时。注册表不能变成实例构造的东西：幂等键的说明文案由实例配置决定，今天靠读取时统一注入，所有对外读取工具声明的路径都经同一处，声明因此不可能与实际配置漂移。

本批取只读与调试各 10 个共 20 个：这一半不涉及幂等与确认令牌，但清理类工具恰好用到「算不算写操作」这个字段，因此条目形状能在容易的一半上先证明出来。其余 20 个暂由一段回落分派（先查注册表，查不到落回旧条件链）继续走旧路，约五行临时脚手架。

**Blocked by:** None — can start immediately.

## Comments

**两批合成一次，回落分派未落地。** 规格里的展开—迁移—收缩之所以分两批，是为了让中间状态也能绿、并先在容易的一半上证明条目形状。实际动手后这条路的中间状态反而更差：40 个工具的元数据必须同时在册（否则工具清单会有两个来源，而票里「参数 schema 内联」与「九项否定条件消失」两项都要求它），于是中间态是「40 条元数据在注册表、20 个执行体在注册表、另 20 个仍在测试控制服务的私有方法里」，加一段回落分派。那个状态本身没错，只是它要多一次搬迁而换不到额外的证据——最终状态已由 1657 条既有断言与逐字节相同的基线钉住。因此本轮把 01 与 02 合成一次落地，两张票的验收项逐条都在最终状态上验证过，代价是没有一个「只迁了一半」的中间提交。

（修正：初版这条 Comment 写成「只能让 20 个工具的实现在同一棵树里各存一份」，说重了。评审核过跨批共用的只有等待类共用的那段游标等待，而它留在测试控制服务里，因此复制执行体并非必然。合并的理由仍是元数据不可半迁，不是重复实现。）

**条目上的元数据全部一次迁完，因此第一批的两项超额完成。** 「参数 schema 内联」与「九项否定条件消失」都要求 40 个工具的元数据同时在册——只迁一半会让工具清单同时有两个来源。这两项因此不可能只做一半，本票里它们是对全部 40 个工具生效的。

**「算不算写操作」落成三态而不是布尔。** 原先那句九项否定条件只覆盖「已经走到那一行」的工具，另有三族工具靠提前返回表达「治理不代它解析空间」。压成布尔会改错误码，三处都有既有断言钉着：`get_test_space`/`fail_test_space` 对已删除或已结束的空间返回 `domain_error`（经空间三态判定会变成 `space_not_found`/`space_unavailable`）；`clear_model_request_records` 对 `{ scope: 'unattributed' }` 返回 `invalid_arguments`（先解析空间会变成 `space_id_required`）。因此字段是 `'none' | 'read' | 'mutation'`，三个取值的理由写在类型文档里。

**「与配额分类不一致的清理类工具」在条目上只剩一个。** `clear_onebot_debug_records` 是调试类（配额档只读）却按写操作解析空间，条目上直接可读。`clear_model_request_records` 同样按写操作解析，但必须先拒绝未归属分类，因此它的解析记为 `none` 并在执行体里自己解析——两者仍都有断言覆盖（`tests/mcp-model-requests.test.ts` 里 `{ scope: 'all' }` 与 `{}` 两种入参对两个工具各断言一次 `space_id_required`）。

**没有别处变红。** 完整测试一次跑绿，`tests/` 下除新增守卫自测外一行未改；三个读取测试控制服务私有字段的断言（确认令牌缓冲区大小）继续通过，未重判。

**证据。** `evidence/baseline.ts` 采集能力目录完整输出、40 个工具的参数 schema 完整 JSON、四种权限范围各自过滤后的清单、六个只读资源，另按非默认幂等窗口再采一份以钉住「读取时注入」。`evidence/01-baseline-head.json` 采于 `b59464e`，`evidence/02-after.json` 采于收尾后，`diff` 无输出。

**验证命令。** `yarn typecheck`、`yarn test`（180 文件 / 1657 断言）、`yarn build` 全部通过；`git diff --stat` 里没有客户端路径。
