# 01 — 预设目录只读一次,展示名称改为解析产物

**What to build:** 打开预设工作台时,每个预设文档只被读取一次、只被解析一次。

现状是每个预设文档被完整读取两次、被解析三次。按目录读取的方法内部对每个 YAML 文件调用一次单文件读取,拿到完整文档后只摘出五个元数据字段返回,把正文与解析结果丢掉;预设服务收到这份摘要后立刻按文件名把同一批文件再读一遍。第三次解析来自展示名称——服务层在呈现文档时又用普通 YAML 解析把同一份正文解析一遍,只为取出核心预设的第一个关键词或角色预设的名称,而完整语法树此刻已经在手上。

按目录读取的方法改为直接返回完整预设文档,并改名为「读取全部」:原来的名字暗示轻量列举,与它实际做的事不符。预设摘要类型删除,五个元数据字段合进预设文档——它存在的唯一理由是让按目录读取返回轻量结果,而唯一的业务消费者拿到后立刻重读同一批文件,轻量这个理由从未成立;留着一个没有消费者的中间类型,读者会以为仍存在一条轻量路径。

展示名称成为文档解析的产物,与模板字段、表达式、诊断并列。核心预设取第一个关键词、角色预设取名称字段,规则不变。

用户观察到的行为完全不变:展示名称的值、列表排序、语法错误预设仍出现在列表里且不显示展示名称、目录中存在符号链接或非常规文件时跳过该文件而不是让整页失败。

三条次数断言是一个整体,必须在本票内一次写完——尤其「目录读取过程中不再运行普通 YAML 解析」这一条,它断言的是某件事不再发生,最容易被漏掉。读取次数属于仓储 interface 而不是实现细节:interface 包含类型签名之外的不变式、错误模式与性能特征,「对每个预设文档只读取一次」正是性能特征。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 按目录读取的方法返回完整预设文档,不再内部调用单文件读取后丢弃结果
- [ ] 该方法改名为「读取全部」,名字说明它读取完整内容
- [ ] 预设摘要类型删除,五个元数据字段合进预设文档,无残留引用
- [ ] 预设服务的目录读取直接消费仓储交出的完整文档,不再按文件名重读
- [ ] 展示名称成为文档解析的产物,与模板字段、表达式、诊断并列
- [ ] 服务层不再独立运行普通 YAML 解析
- [ ] 核心预设的展示名称仍取第一个关键词,角色预设仍取名称字段
- [ ] 「解析失败时没有展示名称」的判定以文档诊断为依据,不存在文档有诊断但展示名称仍被解析出来、或反之的情形
- [ ] N 个预设文档的目录读取恰好触发 N 次文件正文读取
- [ ] 同一次目录读取中,带源码位置映射的语法树解析恰好运行 N 次
- [ ] 目录读取过程中不再运行普通 YAML 解析
- [ ] 列表排序与改动前一致:按文档种类、展示名称、文件名依次比较
- [ ] 没有展示名称的预设仍按文件名排在正确位置
- [ ] 有语法错误的预设仍出现在列表里,且不显示展示名称
- [ ] 目录中存在符号链接或非常规文件时跳过该文件,不让整个目录读取失败
- [ ] 读取保持串行,不改为并发
- [ ] 呈现预设文档时的防御性结构化克隆不变
- [ ] 打开单个预设文档、新建、保存、重命名、删除五条路径的行为不变
- [ ] 现有并发、符号链接与 inode 替换用例继续使用真实文件系统,不引入内存文件系统
- [ ] 不断言具体耗时——次数已覆盖全部承诺,耗时受环境影响会产生不稳定测试
- [ ] 单元测试、类型检查与构建全绿
- [ ] 改动了服务端代码,浏览器验证前完整重启一次项目:确认旧进程与相关子进程已退出、监听端口已释放,重启后确认只有一个实例且加载当前构建产物
- [ ] 浏览器验证:打开预设工作台,核心预设与角色预设的展示名称、列表排序与改动前一致,且一个没有展示名称的预设仍排在正确位置
