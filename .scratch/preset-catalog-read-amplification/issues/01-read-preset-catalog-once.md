# 01 — 预设目录只读一次,展示名称改为解析产物

**What to build:** 打开预设工作台时,每个预设文档只被读取一次、只被解析一次。

现状是每个预设文档被完整读取两次、被解析三次。按目录读取的方法内部对每个 YAML 文件调用一次单文件读取,拿到完整文档后只摘出五个元数据字段返回,把正文与解析结果丢掉;预设服务收到这份摘要后立刻按文件名把同一批文件再读一遍。第三次解析来自展示名称——服务层在呈现文档时又用普通 YAML 解析把同一份正文解析一遍,只为取出核心预设的第一个关键词或角色预设的名称,而完整语法树此刻已经在手上。

按目录读取的方法改为直接返回完整预设文档,并改名为「读取全部」:原来的名字暗示轻量列举,与它实际做的事不符。预设摘要类型删除,五个元数据字段合进预设文档——它存在的唯一理由是让按目录读取返回轻量结果,而唯一的业务消费者拿到后立刻重读同一批文件,轻量这个理由从未成立;留着一个没有消费者的中间类型,读者会以为仍存在一条轻量路径。

展示名称成为文档解析的产物,与模板字段、表达式、诊断并列。核心预设取第一个关键词、角色预设取名称字段,规则不变。

用户观察到的行为完全不变:展示名称的值、列表排序、语法错误预设仍出现在列表里且不显示展示名称、目录中存在符号链接或非常规文件时跳过该文件而不是让整页失败。

三条次数断言是一个整体,必须在本票内一次写完——尤其「目录读取过程中不再运行普通 YAML 解析」这一条,它断言的是某件事不再发生,最容易被漏掉。读取次数属于仓储 interface 而不是实现细节:interface 包含类型签名之外的不变式、错误模式与性能特征,「对每个预设文档只读取一次」正是性能特征。

## Answer

已实现。

- `FileSystemPresetRepository.list()` 改为 `readAll()`（`src/presets/repository.ts`），直接串行读取每个 `.yml`
  正文并交出完整 `PresetFile`，不再内部调用 `read()` 后丢弃结果。`unsafe-file` 继续跳过该文件。
- `PresetSummary` 已删除，五个元数据字段（`kind`/`fileName`/`revision`/`size`/`modifiedAt`）合进 `PresetFile`，
  仓库内无残留引用。
- 展示名称成为 `parsePresetSourceDocument()` 的产物 `PresetSourceDocument.displayName`
  （`src/presets/source-document.ts`、`src/presets/types.ts`）：核心预设取第一个关键词，Character 预设取名称字段。
  「解析失败」只有一套口径——本次解析报出的 `yaml-parse-error` 诊断；模板字段类型诊断不影响展示名称，
  与改动前一致。
- `SandboxPresetService.catalog()` 直接消费 `readAll()` 的完整文档，排序比较器与呈现时的三处
  结构化克隆均未改动；服务层的 `readDisplayName()` 与 `yaml` 导入已删除。

验收测试：`tests/preset-catalog-read-amplification.test.ts`（N 个文档 = N 次正文读取 = N 次带位置映射的语法树解析，
且目录读取过程中普通 YAML 解析次数为 0，另有一条监视手段自检用例）、
`tests/preset-repository.test.ts`（`readAll` 与 `read` 结果等价）、
`tests/preset-service.test.ts`（展示名称排序、缺少展示名称的文件名兜底位置、语法错误预设仍在目录里）、
`tests/preset-source-document.test.ts`（展示名称解析规则与诊断口径）。

真实数据对照：对开发环境真实预设目录分别用改动前后的实现导出 `catalog()` JSON，逐字节一致。
