# 02 — 把工作台内视图返回栈并入证据导航 module

**What to build:** 从轨迹账本进入检查器再返回时,选中行、账本滚动位置、详情面板滚动位置、页签与轨迹模式仍然按离开时的样子恢复;跨请求返回时仍然等目标详情按记录身份真正到达后才恢复,中途的详情变更不会把恢复消费在错误的记录上。用户观察到的行为完全不变。

变化在归属:工作台内视图返回栈的状态与它的一次性触发编号并入证据导航 module,成为第四个编号。返回栈 module 删除。合并后客户端不再有任何位于 module 之外的往返触发编号——四个编号全部由证据导航 module 独家发出,视图与工作台 shell 一个都不持有。

四个编号不合并成一个:工作台内恢复必须等目标详情按记录身份到达,预设工作台原点恢复在视图切换后立即生效,两者的等待条件不同;合并会迫使两个组件观察同一个编号并各自判断这一次轮不到自己。

**Blocked by:** 01 — 建立证据导航 module 并统一进入模型请求视图的路径

**Status:** ready-for-agent

- [ ] 从轨迹账本进入检查器后可以返回轨迹,原选中行被恢复
- [ ] 返回轨迹时账本滚动位置被恢复
- [ ] 返回轨迹时详情面板滚动位置被恢复
- [ ] 返回轨迹时页签与轨迹模式被恢复
- [ ] 跨请求返回时等目标详情按记录身份到达后才恢复视图快照
- [ ] 同时可从轨迹和预设返回时,返回入口指向最近一次离开的位置
- [ ] 自动刷新期间返回状态不被打断,仍然存在的选中行被保留
- [ ] 工作台内视图快照的恢复编号由证据导航 module 发出,成为其第四个编号
- [ ] 四个编号语义互不重叠,各自单调,消费者不需要判断这一次轮不轮到自己
- [ ] 客户端不再有位于证据导航 module 之外的往返触发编号
- [ ] 返回栈 module 删除,无残留引用
- [ ] 返回栈既有断言并入统一测试文件,包含「按记录身份匹配才消费待恢复快照」这条规则
- [ ] 不引入 jsdom、happy-dom 或组件挂载测试
- [ ] 单元测试、类型检查与构建全绿
- [ ] 浏览器验证:轨迹账本到检查器再返回,含选中行、账本滚动、详情滚动与页签恢复
