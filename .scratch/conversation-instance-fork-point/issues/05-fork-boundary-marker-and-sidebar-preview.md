# 05 — 分界标记与侧栏预览

**What to build:** 用户一眼看出分支里哪一段是与原会话共享的对照区、哪一段是自己的实验区，并且刚创建的分支在侧栏里不像个空会话。

分支的消息列表在继承前缀与自有消息之间显示一条分界标记，继承部分视觉上稍作弱化。分界同时承担解释职责：它说明上面那段是与原会话共享的同一份记录，因此右键项变少不再像缺陷。继承部分不折叠、不默认收起——看全上下文正是复盘时要做的事。

侧栏会话实例子项的预览取拼接后的最后一条消息，刚创建的分支因此显示分叉点那条，而不是空白。

完成后单独跑一次浏览器实测：确认分界标记在 Firefox 与 Chrome 下呈现一致、向上加载更早消息能连续跨过分界，并按项目约定关闭本次验证打开的浏览器会话、清理浏览器工具生成的临时目录。

## Comments

### 实现记录

- 判定收进 `client/webqq/fork-boundary.ts`：`isInheritedMessage(message, currentConversationId)` 与 `isForkBoundaryMessage(messages, index, currentConversationId)`。依据只有「消息自己的归属会话」，不需要额外字段——投影已经把拼接结果物化并去掉分叉点。形态照 `message-cluster.ts`：纯函数模块，不是新 seam。
- **分界画在自有消息一侧，不是前缀最后一条上。** 挂在前缀那侧会在「来源被清空或被保留窗口淘汰、整段前缀变空」时连分界一起消失，而分支本身还在；挂在自有消息一侧时那种情况下自然退化为「没有分界」，与根会话同形。
- 03 号票留下的 `isInheritedMessage` 从 `.vue` 里下沉到该模块，`.vue` 只留一个读 props 的包装。原先那条守卫里两条断言函数体文本的断言随之删掉——按 ADR-0073 它们正是「等价重构时变红、真实回归时沉默」的那类；判定现在由 `fork-boundary.test.ts` 逐条执行。三个写入入口接了它的断言保留，那是 `.vue` 里唯一观察不到的接线。
- 弱化用 `opacity: 0.68` 加在消息行上，不动气泡配色：撤回已经占用了「气泡半透明 + 删除线」，继承前缀若也改气泡内部就会与撤回混成一种状态。
- **消息簇不再跨会话合并。**（浏览器实测发现）分叉点那条与分支第一条常常是同一个人连着发的，`isSameClusterSender` 因此把它们并成一簇：第一条自有消息被 `is-merged` 拿掉发送者一行与头像、并用 `margin-top: -14px` 顶到分界上，看起来是上面那条的续写，分界形同不存在。修法是在 `isSameClusterSender` 里加一条 `left.conversationId === right.conversationId`——两条属于不同会话的消息本来就不是一簇，不需要给消息簇模块传当前会话。
- 侧栏预览与「跟随最新一条」不需要改代码：02 已经把 `toSidebarConversation` 的消息列表改成经 `readConversationMessageIds` 读，投影给客户端的实例行就是物化后的拼接结果。本票补的是断言——`webqq-conversation-tree.test.ts` 里刚创建的分支（只有物化前缀）预览是分叉点那条，有了自有消息后跟随最新一条。

### 浏览器实测

完整开发环境（`开发环境/koishi-dev`，portal 到本仓库）先按项目约定整体重启一次：`pkill -f 开发环境/koishi-dev` 后确认 5140/5141 已释放，再 `yarn dev` 起单实例并确认只有一个 worker。在测试群里从中间一条消息右键「创建分支」，实测结论：

- 刚创建的分支侧栏预览是分叉点那条消息（`koishi` / 12:42），不是「开始一段新对话」；消息列表 50 行全部 `is-inherited`、分界数为 0——还没有自有消息就还没有分界。
- 在分支里发一条消息后分界出现且只有一条，DOM 位置正好夹在最后一条继承前缀与第一条自有消息之间；文案「以上是与原会话共享的记录，在这条分支里只读」。
- 点「查看更早消息」后行数 50 → 100、继承行 49 → 99，分界仍然只有一条且仍在倒数第二个位置：向上加载连续跨过分界，不断页也不重复。
- Chrome 与 Firefox 两侧几何与样式一致：继承行 `opacity: 0.68`、分界 `font-size: 11px` 且自身不透明、分界与两侧各留 16px；两边控制台 0 error。
- 收尾：删掉本次创建的测试分支（侧栏恢复为原有两个实例），关闭两个浏览器会话（`playwright-cli list` 显示 no browsers），删除仓库内 `.playwright-cli` 与临时截图。开发环境按约定保持运行。

### 审查后的处理

`/code-review` 两轴各报了两条，处理如下：

- **已改：`gap: 10px` 违反 8px 间距系统。** 改成 8px。
- **已改：测试里那条 import 断言守不住任何东西。** 模块没被引用时 typecheck 直接失败，它只是噪声，删掉。剩下的接线断言（三个写入入口 + `is-inherited` 绑定）确实不在 ADR-0073 的三类例外里，但它们守的是「规则算对了却没渲染／没接上」，在不引入组件挂载的前提下从外观察不到；已在测试里写明它与 03 号票点名的「把权限判定下沉成 `messageList` 投影的能力位」是同一笔债，由那条后续工作一并消化，而不是假装它是例外。分界文案与样式两条属于 ADR-0073 明示的例外。
- **不改：`message-cluster.ts` 那条「跨会话不合并」被判为 scope creep。** 不接受这条判断：没有它，验收 1 与 2 在产品里根本不成立——分叉点那条与分支第一条常是同一个人连着发的，合簇会拿掉第一条自有消息的发送者行与头像，再用 `margin-top: -14px` 把它顶到分界上，分界形同不存在。它也不改动分支以外的任何行为：消息列表按当前会话的消息 ID 集合筛选，相邻两条属于不同会话只可能发生在分支里，而分支混合两个会话正是 02 引入的。移出这条会让本票交付一条肉眼可见失效的分界。
- **不改：验收 3「不折叠、不默认收起」只有 opacity 断言。** 这条验收是「不要造折叠」这种设计约束，正面证据是样式断言（弱化用 opacity 而不是隐藏）加浏览器实测里 49/99 条继承消息全部渲染。为一个从未存在的折叠实现补否定式断言，正是 ADR-0073 点名的那类廉价指标；规格本身也把浏览器实测定为「一次，不是自动化 seam」。
