# 02 — 分叉点取代消息复制

**What to build:** 创建分支瞬间完成，而且不再占用第二份消息额度。用户开多少条对话线，原始对话的早期消息都不会被提前挤掉。

会话实例改为记录「来源会话 ID」与「分叉点消息 ID」两项，不再复制消息。分支的历史 = 来源会话中分叉点及其之前的那一段，加上分支自己的消息，读取时拼接呈现。只存分叉点，不存前缀消息 ID 的快照列表。

来源会话可以是根会话，也可以是另一个会话实例。从一个分支里再分叉时，新分支的来源指向那个分支，读取时沿来源链逐段拼接，因此它能看到上一条分支里已有的那几轮对话，而不是跳回根会话的历史。存储层级仍严格两层——所有实例都挂在同一个根会话下，来源链只在读取时展开。

消息历史分页对拼接后的完整列表操作，游标仍是消息 ID，跨越继承与自有的边界对调用方透明；「还有更早消息」按拼接后的长度判定。消息搜索命中继承前缀时报根会话，不按分支重复报告。场景消息保留窗口的引用摘除不需要改动。

场景里已有的、由复制产生的旧分支没有分叉点，退化为「只有自有消息」，仍可正常打开。不写迁移、不要求重置场景。一次性替换，不保留复制路径。

- [ ] 同一段历史开 N 个分支后，场景消息实体总数不随 N 增长
- [ ] 分支里能看到分叉点及其之前的完整历史，顺序与来源会话一致，分叉点本身包含在内
- [ ] 从一个分支里再分叉时，新分支能看到该分支的自有消息与它继承的历史
- [ ] 向上加载更早消息连续跨过继承与自有的边界，不在分界处断掉
- [ ] 消息搜索命中继承前缀时报根会话
- [ ] 来源会话的消息被清空或被保留窗口淘汰后，分支仍存在且继承部分相应变空

- [ ] 场景中不再存在复制消息的分支实现
