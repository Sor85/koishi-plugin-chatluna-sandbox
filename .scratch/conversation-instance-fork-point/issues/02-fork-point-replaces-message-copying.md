# 02 — 分叉点取代消息复制

**What to build:** 创建分支瞬间完成，而且不再占用第二份消息额度。用户开多少条对话线，原始对话的早期消息都不会被提前挤掉。

会话实例改为记录「来源会话 ID」与「分叉点消息 ID」两项，不再复制消息。分支的历史 = 来源会话中分叉点及其之前的那一段，加上分支自己的消息，读取时拼接呈现。只存分叉点，不存前缀消息 ID 的快照列表。

来源会话可以是根会话，也可以是另一个会话实例。从一个分支里再分叉时，新分支的来源指向那个分支，读取时沿来源链逐段拼接，因此它能看到上一条分支里已有的那几轮对话，而不是跳回根会话的历史。存储层级仍严格两层——所有实例都挂在同一个根会话下，来源链只在读取时展开。

消息历史分页对拼接后的完整列表操作，游标仍是消息 ID，跨越继承与自有的边界对调用方透明；「还有更早消息」按拼接后的长度判定。消息搜索命中继承前缀时报根会话，不按分支重复报告。场景消息保留窗口的引用摘除不需要改动。

场景里已有的、由复制产生的旧分支没有分叉点，退化为「只有自有消息」，仍可正常打开。不写迁移、不要求重置场景。一次性替换，不保留复制路径。

## Comments

### 实现记录

- `SandboxConversationInstance.forkPoint`（`{ conversationId, messageId }`）取代复制；`messageIds` 收窄成「自有消息」。`createConversationInstance` 不再接受预置消息列表——分支不复制消息，自有消息一律靠 `appendConversationMessageId` 得到。
- 拼接是 `readConversationMessageIds` 内部的实现，落在会话解析模块新增的私有 `readRowMessageIds` 上：沿来源链递归展开，分叉点消息本身计入前缀，`indexOf` 落空（来源被清空或分叉点已被淘汰）时整段前缀为空。
- 来源链成环时那一段读作「没有可读的前缀」而不是停在环上继续展开：后者会让同一条消息 ID 在列表里出现两次，比丢掉前缀更糟。环只可能来自被改坏的导入场景。
- **投影必须物化并去掉分叉点。** `truncate` 把拼接结果写进实例行的 `messageIds` 并删掉 `forkPoint`：客户端与 MCP 消费的是投影，若留着分叉点，同一个读取口会拿着已经拼好的列表沿来源链再拼一次，继承前缀因此重复出现。这也顺带给了 05 需要的分界依据——投影出的消息带着自己的 `conversationId`，与当前会话 ID 不同的就是继承前缀，不需要额外字段。
- `trimSnapshotMessages` 之前只替换 `conversations`，实例行留的是权威版本。物化之后这会让空间预览拿着「只有自有消息」的列表去拼一份已经被裁过的来源前缀，因此一并替换成 `trimmed.conversationInstances`。
- `SandboxMessageSearchHit` 新增 `conversationId`，取消息实体自身的会话归属。命中继承前缀时报来源会话（从根会话分叉时就是根会话），一条逻辑消息因此只有一个会话身份。
- 验收清单里的「命中继承前缀时报根会话」按规格的判据「按消息实体自身的会话归属报告结果」实现。从分支里再分叉时前缀跨两段，报的是每条消息各自所属的那一段而不是一律报根会话；这条已用断言钉住，避免以后被读成矛盾。
- 客户端 `loadMessageHistory` 之前只把历史页合并回根会话行，实例行从来没被合并过（01 留下的观察）。现在按会话 ID 同时匹配两个集合：投影出的实例行携带的就是拼接结果，往它前面接一页即可，分支因此翻得动继承的历史。
- `validateSceneConversations` 只校验分叉点的形状，不要求来源会话与分叉点消息仍然存在——来源被删除、清空或淘汰后继承前缀变空而实例仍可用，要求它们存在会让导出再导入的场景炸掉。

### 留给后续票的观察

- 在分支里引用继承前缀回复目前会被 `getMessageContext` 的「被引用消息的会话等于当前会话」拒掉，是本票带来的已知回归，由 03 按规格放宽为「在当前会话里可读」。
- 插件按消息 ID 读继承前缀目前会被 `findAccessibleMessage` 的 `conversationId === channelId` 拒掉，由 04 放宽。
