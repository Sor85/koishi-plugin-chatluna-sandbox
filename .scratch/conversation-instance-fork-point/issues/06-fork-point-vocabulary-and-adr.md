# 06 — 分叉点术语与 ADR

**What to build:** 把「分支只记分叉点、读取时拼接」这件事写进仓库的领域记录，并交代它与上一轮那条 ADR 的关系。

领域词汇新增「分叉点」条目：会话实例记录的来源消息，它界定继承前缀的范围；同时说明应避免的替代叫法（起点、锚点、基线、分支点快照）。

新增一条 ADR 说明分支改为只记分叉点，覆盖三个决定：只存分叉点而不存前缀消息 ID 快照（消息只追加，两者在正常路径上等价，少一份状态就少一处失真）；继承前缀在分支视图里只读但消息实体的生命周期不冻结（区分「用户在对照组里的操作入口」与「消息本身能不能变」）；来源可以是另一个实例、读取时沿来源链拼接而存储仍是两层。

在 ADR-0076 中标注「代价是分支要复制分叉点之前的消息，场景消息保留窗口的预算因此按分支数被摊薄」那一段被本 ADR 取代，不改写 ADR-0076 原文——记录当时为什么接受复制这个取舍本身有价值。

## Comments

### 实现记录

- `CONTEXT.md` 新增两条而不是一条：**分叉点**（来源会话加一条消息，界定继承前缀的范围）与**继承前缀**（读取时拼在自有消息之前的那一段）。两个词在代码、测试名与本轮四张票里都已大量出现且各自指不同的东西——分叉点是记录下来的那一条，继承前缀是它界定出来的那一段；只补前者会让后者继续没有正式条目。`_Avoid_` 分别列出「起点、锚点、基线、分支点快照、复制点」与「复制的历史、共享历史快照、上文副本、父会话消息」。
- 新增 [ADR-0077](../../../docs/adr/0077-record-fork-points-instead-of-copying-messages.md)，四段对应票里点名的三个决定加一段说明为什么取代复制：为什么不存前缀快照（少一份状态就少一处与真相不一致的地方）、只读约束的是分支视图的操作入口而不是消息实体的生命周期（连带交代「会话归属是请求层的边界，写入路径只认消息实体」）、来源链只在读取时展开而存储仍两层（附带拼接只有一处实现、投影必须物化、搜索按消息归属报告）。
- ADR-0076 顶部按 ADR-0042 → 0076 的既有写法加一句取代标注，正文一字未改。
- 规格里唯一与最终实现不一致的表述是搜索那一条：原文「命中继承前缀时报根会话」在「从分支里再分叉」这条链上不成立，实现按规格自己的判据「按消息实体自身的会话归属报告结果」报的是各自所属的那一段。已把该句补全为「报那条消息真正所属的那一段会话」，括注两种情形。02 号票的验收清单沿用原措辞、其实现记录里已交代口径，作为历史记录不改。

### 审查后的处理

- **不改：新增「继承前缀」条目被判为超出清单。** 票只点名「分叉点」，但两个词指的是不同东西——分叉点是记录下来的那一条消息，继承前缀是它界定出来的那一段历史——而后者在四张票、ADR-0077、源码注释与测试名里出现得比前者还密。`docs/agents/domain.md` 要求代码与测试名使用词汇表里的正式术语；只补分叉点会让另一个同等常用的术语继续没有定义，也就守不住它自己的 `_Avoid_` 清单。
- 规格那处修改经审查确认只是把与实现不一致的表述改正，没有放宽要求。
