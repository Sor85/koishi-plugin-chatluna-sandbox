# 前后端 RPC 契约收敛成一份

Status: resolved

## Problem Statement

一个 Console 端点的名字与签名今天要写三遍：服务端的 `ConsoleEventMap`、服务端对 `@koishijs/console` 的 `Events` 模块增强、客户端 `koishi-client-shim.d.ts` 里的一条 `send` 重载。三份都是同一份名单换三种语法，五十多行乘三份，没有任何东西要求它们一致。

名单已经不一致了：`chatluna-sandbox/bot-deliveries` 在服务端两份声明里都有、也真的注册了监听器，但客户端补丁里没有它的 `send` 重载，客户端也没有任何代码调用它。它既不是被客户端用着的端点，也没有被当成服务端自用登记过——它就是漂在那儿，两边都没人报错。

另有两份运行时名单：`registerListener` 的调用点（服务端真相）与三个客户端端口适配器里的 `send('...')`（客户端真相）。声明与它们之间同样没有闸门：注册了但没人声明、声明了但没注册、声明了但没有任何消费方，三种情况都不会有人变红。

广播频道更糟。`chatluna-sandbox/scene-mutated` 只以字符串字面量出现在服务端的 `broadcast` 与客户端的 `receive` 两处，而客户端补丁把 `receive` 声明成 `event: string` 的泛型——频道名拼错、载荷字段改名都要等到运行时才知道，载荷类型 `SceneMutationPayload` 还在 `scene-sync.ts` 里另有一份本地声明。

代价不在于抄三遍累，而在于每加一个端点都要记住抄哪三处；漏掉客户端那处时 TypeScript 只会说「没有匹配的重载」，漏掉服务端那处时连编译都过得去，只在真的调用时才报「未知事件」。

## Solution

端点的名字、入参与出参写一次，三份声明从它派生，两份运行时名单由守卫钉在它上面。

加端点的人只改一处；改错端点名的人在编译期就知道，而不是在运行时看到「未知事件」。声明了却没人注册、注册了却没声明、声明了却没有任何消费方，这三种漂移各有一条断言。

广播频道进入同一份契约，`receive` 因此和 `send` 一样有类型；频道载荷也只有一处定义。

用户看不到任何变化：这次改动不动任何端点的行为、名字和签名。

## User Stories

1. As a 插件维护者, I want 新增一个 Console 端点只改一处声明, so that 我不用记住还要抄到另外两处
2. As a 插件维护者, I want 端点名拼错在编译期就报错, so that 我不必等到运行时看「未知事件」
3. As a 插件维护者, I want 一条断言钉住声明的端点集合与注册的监听器集合相等, so that 声明与实现不会各自漂移
4. As a 插件维护者, I want 声明了却没有任何消费方的端点被报出来, so that `bot-deliveries` 这类漂着的端点要么有主要么被删
5. As a 插件维护者, I want 广播频道的名字与载荷也只有一处定义, so that 改载荷字段时两端一起变红
6. As a 插件维护者, I want `receive` 像 `send` 一样有类型, so that 订阅一个不存在的频道不能通过编译
7. As a 插件维护者, I want 契约本身与端点实现分开, so that 读契约的人不必翻一千行注册代码
8. As a 沙盒用户, I want 这次改动之后界面行为完全不变, so that 一次纯结构性收敛不需要我重新验收功能

## Implementation Decisions

### 契约住在哪

- 新增 `src/console-contract.ts`：只声明端点名到「入参与出参」的映射，以及广播频道名到载荷的映射。不 import 控制服务，不含任何实现，因此客户端补丁引用它不会把服务端运行时拖进前端产物。
- 服务端与客户端共享它，方式与 `src/types.ts`、`src/conversation-resolution.ts` 一致：客户端已经在直接引用 `src/`，不新增跨目录依赖方向。
- 契约按能力分组书写并导出分组，与 ADR-0074 的端口拆分对齐：会话与消息、环境与关系、调试记录、模型请求、预设、MCP 管理、测试空间。分组是给读的人用的，端点集合仍是全体的并集。

### 三份声明如何派生

- `ConsoleEventMap` 直接成为契约类型本身，不再另写一份。
- 服务端对 `@koishijs/console` 的 `Events` 模块增强改成从契约映射派生：`{ [K in keyof SandboxConsoleEvents]: SandboxConsoleEvents[K] }`，属性函数类型对方法签名位置可赋值，不需要逐条重写。
- 客户端补丁里的五十多条 `send` 重载塌成一条泛型签名：`send<K extends keyof SandboxConsoleEvents>(event: K, ...args)`，入参与返回都从契约取。`receive` 同样改成按频道名取载荷的泛型签名。
- 契约里的入参与出参类型仍来自 `src/types.ts` 与各控制服务输入类型，不复制一份形状。

### 端点集合守卫

- 注册集合等于契约集合：既有的假 Console 已经在测试里收集 `registerListener` 的事件名，用它跟契约的键集合比对，两个方向都断言——注册了没声明、声明了没注册各自报出。
- 每个端点都要有消费方。消费方分两类：客户端端口适配器里的 `send` 调用，以及显式登记为「服务端自用或仅供外部工具」的少数端点。登记表带必填理由，形态与客户端架构守卫的豁免清单一致：不是放行，是有主的债务。
- `chatluna-sandbox/bot-deliveries` 按此处理：它今天没有任何客户端消费方。按未发布阶段兼容策略，没人用就删掉；确有保留理由时登记，理由必填。这条决定属于实现，不在本规格里预判。
- 守卫读源码：端点集合与消费方名单没有别的观察面，这是 ADR-0073 明示的架构守卫例外，按规则制写谓词而不是白名单。

### 广播频道

- `scene-mutated` 与 `mcp-activity` 的频道名与载荷进入契约的广播分组，`scene-sync.ts` 里的本地 `SceneMutationPayload` 声明删掉，改为引用契约。
- `mcp-activity` 同时是请求端点与广播频道，这不是错误：一个是「现在跑着吗」的查询，一个是「状态变了」的通知。契约把两者分别登记，不合并成一条。

## Testing Decisions

**本规格不新增 seam，也几乎不新增行为。** 它是一次结构性收敛：三份声明变一份、五十多条重载变一条泛型、加两条守卫。

因此测试重点是「收敛没有改变任何端点的行为」与「守卫真的会因漂移变红」，而不是给每个端点补断言——既有的 Console 适配器测试、各端点测试与客户端端口测试已经覆盖行为，它们必须一条不改地继续通过。

### 测试面

1. **既有测试全绿且未被改写（主要判据）**——`console-adapter.test.ts`、各 `console-*.test.ts`、`koishi-workspace-port.test.ts` 等在收敛前后一字不改地通过。任何一处需要改断言才能通过，都说明这次收敛改变了外部行为，要停下来查。
2. **端点集合守卫（架构守卫例外）**——谓词自测：喂一个「声明了但没注册」的合成契约要报错，喂一个「注册了但没声明」的要报错，喂一个「声明了但没有消费方且未登记」的要报错；移除登记表里任一条目，对应端点必须重新报错。
3. **类型层面的收敛（由 `yarn typecheck` 承担）**——不为类型写运行时断言。泛型 `send` 是否真的把入参与出参对上，由既有客户端端口代码在 typecheck 下的通过与否证明；这正是把五十多条重载塌成一条的收益所在。

## Out of Scope

- **端点的重命名、合并或拆分**。契约收敛不改任何端点的名字与签名；名单是什么样就照抄成一份。
- **MCP 工具契约**。MCP 有自己的工具 schema 契约与守卫，不并入 Console 契约。
- **端点的鉴权级别**。`authority: 4` 仍写在注册点上，不进契约：它是注册时的策略，不是端点的形状。
- **把 Console 端点也派生成外部测试控制端点**。两套面向的调用方不同，ADR-0028 让测试控制 API 独立版本化，本规格不动它。
- **客户端端口接口本身的收敛**。`workspace-port.ts` 这类端口接口是客户端的抽象，不由服务端契约派生。

## Further Notes

- 三份声明的行数今天大致相等，因此「抄三遍」的成本看起来只是行数；真实成本是加端点时的记忆负担与漏抄后的错误形态不一致——漏客户端那处报「没有匹配的重载」，漏服务端那处编译通过而运行时报「未知事件」。
- `bot-deliveries` 这处漂移是写规格时用集合比对发现的，不是读代码猜的：服务端两份声明与注册点都有它，客户端补丁没有，客户端也没有任何调用。实现时应先用一条断言把这个不一致钉红，再决定删还是登记。
