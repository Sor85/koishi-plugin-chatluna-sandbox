# 02 — 修复模型请求变量搜索的两套口径

**What to build:** 在模型请求分析页搜索模型请求变量时,左侧导航与右侧卡片给出一致的结论。

已核实的缺陷:变量搜索目前在两处各自派生一遍搜索文本。左侧导航项的搜索文本在变量状态不是已观察时包含状态说明文案,而右侧卡片的判定在同样情况下用空字符串。因此搜索「歧义」这类状态文案时,左侧导航项会命中并保持高亮,右侧对应卡片却被置灰、也不会被展开——同一个查询词,导航说有、正文说没有。

同一处还有第二份重复:变量状态说明文案有两份不同实现,导航侧是短句、卡片侧是长句。这印证了两侧各自演化过,也是把它们收敛到一处的直接理由。

删掉分析视图里自己重算的那份判定,改用导航项已经算好的搜索文本作为唯一来源;删掉卡片侧那份状态说明文案,改用导航侧那一份。

本票不依赖证据种类 module。它修的是「同一事实在两处各写一遍派生逻辑」,与词汇收敛同源但不共享代码。

**Blocked by:** None — can start immediately

**Status:** ready-for-human

- [x] 搜索一个状态不是已观察的模型请求变量的状态说明文案时,左侧导航项与右侧卡片同时命中
- [x] 搜索一个已观察变量的展开值时,两侧行为一致
- [x] 搜索不命中的词时,两侧同时置灰
- [x] 变量搜索文本只有一处派生,分析视图不再自己重算
- [x] 变量状态说明文案只有一份实现
- [x] 命中时卡片的展开行为与导航项的高亮行为一致
- [x] 新增回归:变量状态不是已观察时,搜索状态说明文案在导航与卡片两侧结论一致
- [x] 其他证据种类的搜索行为不受影响
- [x] 单元测试、类型检查与构建全绿
- [x] 浏览器验证:搜索一个非已观察变量的状态说明文案,确认导航项与右侧卡片同时命中;再搜索一个不存在的词,确认两侧同时置灰

## Comments

搜索文本的唯一来源改为分析导航项：`ModelRequestAnalysisNavigation` 增加 `searchTexts`（导航项 id → 已归一化文本），导航与右侧卡片都经 `matchesAnalysisSearch(navigation, id, query)` 判定。`analysis-view.vue` 里那份 `variableSearchTexts` 已删除。

状态说明文案收敛到 `modelRequestVariableStatusLabel`（`src/model-request-variables.ts`），三处共用：轨迹行预览、导航项搜索文本、右侧卡片正文。原先卡片侧那份长句实现删除，因此搜到的词一定能在正文里看到。

回归用例在 `tests/model-request-analysis.test.ts`：状态为 `ambiguous` 时，「歧义」在导航项与卡片两侧同时命中；已观察变量搜展开值两侧一致，不命中的词两侧同时置灰。

浏览器验证（Chrome + Firefox，记录 0 共 15 个变量）：`groupShutList` → 两侧各 14 项置灰、`歧义` 与不存在的词 → 两侧各 15 项置灰，逐项比对 0 处不一致。该记录的 15 个变量全部是已观察状态，非已观察分支在浏览器里没有真实数据可复现，那一支由上面的回归用例覆盖。
