# 02 — 修复模型请求变量搜索的两套口径

**What to build:** 在模型请求分析页搜索模型请求变量时,左侧导航与右侧卡片给出一致的结论。

已核实的缺陷:变量搜索目前在两处各自派生一遍搜索文本。左侧导航项的搜索文本在变量状态不是已观察时包含状态说明文案,而右侧卡片的判定在同样情况下用空字符串。因此搜索「歧义」这类状态文案时,左侧导航项会命中并保持高亮,右侧对应卡片却被置灰、也不会被展开——同一个查询词,导航说有、正文说没有。

同一处还有第二份重复:变量状态说明文案有两份不同实现,导航侧是短句、卡片侧是长句。这印证了两侧各自演化过,也是把它们收敛到一处的直接理由。

删掉分析视图里自己重算的那份判定,改用导航项已经算好的搜索文本作为唯一来源;删掉卡片侧那份状态说明文案,改用导航侧那一份。

本票不依赖证据种类 module。它修的是「同一事实在两处各写一遍派生逻辑」,与词汇收敛同源但不共享代码。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 搜索一个状态不是已观察的模型请求变量的状态说明文案时,左侧导航项与右侧卡片同时命中
- [ ] 搜索一个已观察变量的展开值时,两侧行为一致
- [ ] 搜索不命中的词时,两侧同时置灰
- [ ] 变量搜索文本只有一处派生,分析视图不再自己重算
- [ ] 变量状态说明文案只有一份实现
- [ ] 命中时卡片的展开行为与导航项的高亮行为一致
- [ ] 新增回归:变量状态不是已观察时,搜索状态说明文案在导航与卡片两侧结论一致
- [ ] 其他证据种类的搜索行为不受影响
- [ ] 单元测试、类型检查与构建全绿
- [ ] 浏览器验证:搜索一个非已观察变量的状态说明文案,确认导航项与右侧卡片同时命中;再搜索一个不存在的词,确认两侧同时置灰
