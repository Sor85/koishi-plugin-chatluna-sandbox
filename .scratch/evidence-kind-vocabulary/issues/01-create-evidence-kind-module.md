# 01 — 建立证据种类 module

**What to build:** 证据分类与它的展示标签有了唯一拥有者。八种基础证据种类、每种的两个标签变体、以及两个具名聚合都可以从一个 interface 观察与断言。

基础证据种类取最细一档,共八种:系统消息、用户消息、助手消息、模型请求变量、工具定义、工具调用、工具结果、模型响应。它们与领域词汇表的词条一一对应。请求边界行不在其中——它是「一次模型请求从这里开始」的结构标记而不是证据,现有测试已经把这条区分钉住。

标签提供两个变体,按排版语境区分:徽标语境全大写,标题与图例语境词首大写。两者成对声明,不会各自漂移。

两个聚合从基础种类派生并显式声明:工具交互包含工具调用与工具结果,供请求组成图按字符占比合并统计;工具分组包含三种工具证据,供分析导航把它们收在一个分组标题下。聚合具名后,「组成图把工具调用与工具结果算作一类」这条规则第一次成为可以断言的事实——它目前只存在于一个条件分支里,没有任何测试。

module 位于服务端目录,是浏览器安全的纯 module,不依赖 Node、Koishi、Vue 或 DOM,以便服务端轨迹派生与客户端视图共用同一实现。这与共享模型证据投影同一形状。

本票是后续三张的 prefactor:纯新增,不改动任何调用点,四张旧标签表与七套旧词汇原样保留并继续工作。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 请求边界行不属于基础证据种类
- [ ] 每种基础证据种类都提供徽标与标题两个标签变体,成对声明
- [ ] 徽标变体为全大写,标题变体为词首大写
- [ ] 工具交互聚合恰好包含工具调用与工具结果两种基础种类
- [ ] 工具分组聚合恰好包含工具定义、工具调用与工具结果三种基础种类
- [ ] 两个聚合各有自己的标签,不与基础种类的标签混用
- [ ] 聚合成员不重复也不遗漏,可从 interface 断言
