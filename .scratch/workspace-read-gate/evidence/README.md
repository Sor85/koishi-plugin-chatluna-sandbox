# 证据：四个工作台模型的完整输出与四个区域视图的 DOM

本轮的主证据是**模型输出**而不是 DOM：进行中与错误本来就是工作台外壳 interface 上的模型字段，
可以直接整体序列化比对；在 DOM 里它们只体现为一个转圈动画。DOM 快照仍跑一次，用来兜住模板绑定
被改坏的情况——模型字段名与形状若在收拢时改动，模型比对看不出来（它比的是模型本身）。

## 脚本

| 文件 | 用途 | 运行方式 |
| --- | --- | --- |
| `model-snapshot.mts` | 五个模型的完整输出，72 个采样点 | `node_modules/.bin/tsx .scratch/workspace-read-gate/evidence/model-snapshot.mts <输出>` |
| `compare.mjs` | 逐采样点、逐模型比对模型输出 | `node compare.mjs <基线> <当前>` |
| `dom-snapshot.mjs` | 四个区域视图的 DOM，6 个采样点 | 仓库外临时目录 `npm i playwright` 后 `node dom-snapshot.mjs <输出> [chromium\|firefox]` |
| `compare-dom.mjs` | 逐采样点比对 DOM、转圈数与错误文本 | `node compare-dom.mjs <基线> <当前>` |

模型快照跑在假工作区端口上，不需要浏览器，也不需要开发环境。
DOM 快照跑在仓库外的完整 Koishi 开发环境（`http://127.0.0.1:5140/chatluna-sandbox`）。

## 确定性

- **模型快照**：固定场景、固定操作序列、按 `rejectNext` 注入固定失败。「调用途中」的采样点靠
  **先发起、不 await、立刻读模型**取得——置进行中与清错误都发生在第一个 `await` 之前，因此这一读
  一定落在调用途中，与假端口是否立即结算无关，可反复运行。
- **DOM 快照**：每次全新浏览器上下文（本地偏好为空，首屏视图固定），按导航按钮的**可见文案**点击
  而不是按序号，固定等待，全程只读不写。时刻、日期、生成 id、内联样式与 `data-v-` 哈希在采样时
  规范化掉。

## 基线取法

`git stash push`（只 stash 已跟踪改动，两个新模块与脚本本身留在工作区不参与）把外壳回到 HEAD，
跑同一份脚本，然后 `git stash pop`。DOM 那次在 stash 后先用 `curl` 确认开发环境的 Vite
已经返回旧源码（`createRegionReadGate` 消失、`debugLoading` 回来）再采样。

## 三处差异：`getForwardMessage` 少了一步清错误

收拢前十五处操作里有十四处在调用前清掉上一次的错误，只有「读取合并转发」漏了这一步。它经错误位
表达后必然获得这一步，因此三个采样点上发送控件的外部错误从「上一条过期报错」变成空串：

| 采样点 | 基线 | 当前 |
| --- | --- | --- |
| 读取合并转发失败 · 调用途中 | `转发目标不存在`（上一次操作留下的） | `` |
| 读取合并转发成功 · 调用途中 | `合并转发不存在` | `` |
| 读取合并转发成功 · 调用结束 | `合并转发不存在`（读取已经成功） | `` |

第三行是用户能真正察觉到的那一处：合并转发读取成功之后，发送控件上仍然挂着上一次失败的报错。
这正是本轮要变成可断言事实的那条不变量的失效形态，因此没有为它在模块里开一条「不清错误」的
后门——那会让模块的唯一一条不变量作废。断言见
`tests/workspace-shell-action-errors.test.ts` 的「成功的操作把上一条过期错误清掉」。
