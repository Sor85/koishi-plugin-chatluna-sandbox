# 02 — 实现分析页 Messages 与 Response 卡片

**What to build:** 让用户在模型请求分析页右侧直接阅读格式化后的请求消息和本次模型响应，包括正文、思考内容、工具交互、结束原因、用量、多模态内容以及未完成或失败状态，而不需要逐项阅读原始 JSON。

**Blocked by:** 01 — 建立模型请求对话归一化与响应证据模型

**Status:** ready-for-agent

- [ ] 右侧内容按 Messages 后接 Response 的顺序展示
- [ ] 请求消息按归一化顺序从 #0 连续编号，本次模型响应使用独立标题且不占请求消息编号
- [ ] system、user、assistant 和 tool 请求消息使用可区分且适配浅色与深色主题的角色样式
- [ ] 请求消息正文去除协议 JSON 外壳，并按原始顺序展示文本与多模态分片
- [ ] assistant 工具调用在所属 assistant 卡片内展示工具名、调用标识和格式化参数
- [ ] 请求体中的工具结果作为独立 tool 请求消息展示
- [ ] 一次请求只生成一张本次响应卡片，并按实际存在的内容划分思考、正文、工具调用、工具结果、结束原因和用量
- [ ] 模型响应只有思考、工具调用或用量而没有正文时仍然显示
- [ ] 请求消息、思考、工具参数、工具结果和响应分区分别应用超过 1200 字符时显示前 600 字符的折叠规则
- [ ] 折叠内容显示渐隐遮罩、字符总数和展开全部按钮，展开后可收起
- [ ] Data URL 和 HTTP/HTTPS 图片自动预览，保持宽高比且最大约 520 × 360 像素
- [ ] 图片加载失败时回退到 URL、类型或摘要文本，HTML 和 SVG 不作为可执行内容呈现
- [ ] 正文按纯文本保留换行和空白，不解析 Markdown，不执行 HTML
- [ ] pending、响应不可用、响应解析失败和完全无可展示内容时均有明确状态
- [ ] 布局在加载和自动刷新期间保持稳定，已有请求消息可以先于响应完成显示
- [ ] 卡片渲染、长文本、多模态、响应分区和状态行为有组件级外部行为测试
