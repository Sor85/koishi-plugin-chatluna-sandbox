# 04 — 将分析页轨迹导航接入模型请求对话视图

**What to build:** 让用户继续使用分析页现有的请求组成图、轨迹控制和事件账本，但把压缩后的事件账本作为左侧分组导航，并让事件点击定位右侧 Messages、Response 或 Tools 的具体内容，而不是在分析页打开旧 JSON 检查器。

**Blocked by:** 02 — 实现分析页 Messages 与 Response 卡片；03 — 实现分析页 Tools 格式化工具列表

**Status:** ready-for-agent

- [ ] 仅模型请求分析页启用显式 analysis 展示模式
- [ ] analysis 模式保留现有全宽请求组成图、请求/工具控制和搜索框
- [ ] analysis 模式下方采用左侧约 260 像素导航和右侧自适应内容布局
- [ ] 可用宽度不足约 760 像素时切换为上下布局，导航限制高度并独立滚动
- [ ] 左侧事件按 System、User、Assistant、Tool、响应真正分组，空分组不显示，分组内部保持原始顺序
- [ ] 每个分组显示 SVG 图标、名称和数量；事件行显示角色标签、连续编号和单行省略摘要
- [ ] 请求边界行保留请求序号、状态、模型、渠道和耗时，超长元信息可通过 Tooltip 完整查看
- [ ] 请求边界点击后定位本次响应卡片
- [ ] SYSTEM、USER、ASSISTANT 和 TOOL RESULT 事件定位对应请求消息卡片或具体分区
- [ ] TOOL DEFS 事件定位右侧 Tools 区域
- [ ] assistant TOOL CALL 事件定位 assistant 卡片内对应工具调用分区
- [ ] 响应事件定位本次响应卡片或对应响应分区
- [ ] 定位折叠内容时自动展开目标分区，平滑滚动后显示约 1.5 秒强调边框
- [ ] 现有搜索同时作用于左侧事件和右侧卡片，覆盖角色、摘要、正文、思考、工具名称、参数、结果、响应、工具描述和 Schema
- [ ] 搜索未命中的事件和卡片保留但降低透明度，命中文字获得高亮
- [ ] 搜索命中折叠内容时自动展开命中的卡片和分区，并定位第一个结果
- [ ] analysis 模式删除右侧旧轨迹 JSON 检查器和相关跨页签返回行为
- [ ] 独立轨迹页面继续保留事件检查器、打开原始请求、返回轨迹、选中状态和滚动位置恢复
- [ ] 分析模式事件定位、搜索和响应式布局有外部行为测试
- [ ] 独立轨迹模式的原始检查能力和状态恢复有回归测试
