# 01 — 插件装配只写一份，端点可用性变成一个值

**What to build:** 测试控制端点起不来的时候，插件走的是同一段装配代码，而不是一份复制品。

端点是否可用先求成一个可空值：拿到了就带着 MCP 服务与监听器，没拿到就是空。装配只写一次——Console 注册照旧按「有没有 MCP 服务」传参，启动与关机各多一次可空调用。十五行重复消失。

部署者看到的东西不变：端点起不来时 WebQQ 照常可用，**两种失败各自的文案与可观察结果一字不变**——构造失败（完全没有 MCP 服务，日志「测试控制端点初始化失败；WebQQ 仍可继续使用」）与监听启动失败（MCP 服务仍然注册给 Console，日志「测试控制端点监听器启动失败；WebQQ 仍可继续使用」）是两件事，不合并。沙盒用户看不到任何变化。

`try` 收窄到只包住两次构造，Console 注册与两个钩子的注册移到它之外单路执行。这一步顺手消掉一个隐患：今天 Console 注册在 `try` 里，它抛出会导致降级分支用与事实不符的文案记日志、并把 Console 入口与全部监听器注册第二遍。

**这里有一处明示的偏离**，不算进纯结构性：收窄之后 Console 注册抛出会直接冒出插件的 apply。依据是今天那个行为本身不成立（文案与事实不符，且会重复注册）。

关机收尾那两行解释「Koishi 的 dispose 不可等待，收尾写入的失败只能进日志」的注释今天只存在于主路径那一份——单路装配之后它必然覆盖两条路。

不新增测试 seam：装配的 seam 是插件 apply，驱动它要一个完整 Koishi Context；把「造端点、失败返回空」提成函数只能断言 `try/catch` 字面上写着的东西。证据换成逐行差异清单加上一次真实的降级执行。

## Comments

### 明示偏离（唯一一处行为可能变化）

Console 注册移出 `try` 之后，它抛出会直接冒出插件的 `apply`。收拢前会被 `catch` 记成「测试控制端点初始化失败；WebQQ 仍可继续使用。」并把 Console 入口与全部监听器注册第二遍。

依据是收拢前那个行为本身不成立：文案与事实不符（端点构造已经成功），且重复注册会让 Console 入口出现两份。这一处不算进「纯结构性」。

浏览器侧同时给出了「不会注册两次」的正面证据：主路径与降级路径下侧栏 `a[href="/chatluna-sandbox"]` 都恰好只有 1 个。

### 差异清单比票上多一项

`.scratch/plugin-assembly-single-path/evidence/01-assembly-diff.md`。实质差异确实只有票上写的三项（Console 注册的 MCP 服务实参、一次启动、一次停止），但只存在于主路径的注释是 **3 行而不是 2 行**：除了关机不可等待那两行，`getChatLunaUsage` 上方「chatluna-usage 位于另一个 loader group」那一行同样只在主路径有。性质与票上那两行相同——两份拷贝之间已经长出的差异，且都是注释先掉队。单路装配之后这 3 行各只剩一份。

### 断言变红情况

零。收拢前后完整测试都是 179 文件 / 1636 用例全绿，没有需要区分真红假红的条目。插件入口 `src/index.ts` 本来就没有测试读它，几个按形状扫描 `src/**` 的架构守卫（会话集合、记录域目录）判定的写法本轮未被触碰。

### 降级路径的首次真实执行

`.scratch/plugin-assembly-single-path/evidence/01-runtime.md` 记了三次真跑的全部观察项。构造失败由「数据目录不可写」强制触发（`mkdirSync` EACCES），日志文案一字不变，61901 未监听，WebQQ 照常收发，控制台 0 error。规格没要求真跑「监听启动失败」那条，顺手也跑了一次（占住 61901 触发 EADDRINUSE）：文案一字不变，而 MCP 能力徽标仍是 40——两种降级模式没被合并，这是正面证据。

### 顺带发现：开发环境自身的崩溃循环

与本轮改动无关，但会挡住任何人重启开发环境：`koishi-plugin-logger-plus` 在 `Math.max(...files[date])` 处展开单日 10 万量级的日志文件索引，直接 `RangeError: Maximum call stack size exceeded`，worker 每 6 秒崩溃重启。经用户确认，把 `koishi-dev/logs` 改名为 `logs-archive-20260901` 并新建空目录后恢复，2.7 GB 历史日志原样保留、`koishi.yml` 未改。若要根治，需要 logger-plus 侧改掉那个展开写法。
