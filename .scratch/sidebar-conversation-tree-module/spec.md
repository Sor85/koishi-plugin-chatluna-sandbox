# 侧栏会话树投影与展开态下沉成模块

Status: ready-for-agent

## Problem Statement

侧栏会话树的两半各自住在一个不该住的地方。

「一个根会话在侧栏里长什么样」——标题取实例名还是联系人名、预览取最后一条消息还是撤回事件文案、时间怎么格式化、头像种类怎么判、实例怎么挂到所属根会话下——是五十多行投影逻辑，埋在一千一百多行的工作台外壳里。外壳同时还在做消息列表投影、输入区投影、详情栏投影、转发目标投影、七八个工作台模型和首屏加载，会话树只是其中一块。它能被测到，因为外壳的 `sidebarModel` 是个 interface；但要测它就得先起一个完整外壳。

展开态住在侧栏组件里，而且一条测试都没有。`expandedConversationIds` 加两个读写函数，再加一条真正有意思的规则：选中一个会话实例时自动展开它所属的那一行。那条规则有它自己的理由——新建与分叉完成后新实例会被自动选中，而展开态是侧栏本地状态，折叠的父行会让侧栏一行都不高亮——理由写在注释里，行为没有任何断言。改坏它的人不会看到红灯，只会在某次分叉后发现侧栏看起来什么都没选中。

`webqq-sidebar.test.ts` 里十五处 `readFileSync` 也说明了同一件事：判定住在 `.vue` 里，从外面观察不到，测试只能退回源码文本断言，而 ADR-0073 说那类断言在等价重构时变红、在真实回归时沉默。

投影还有第二个消费方：转发目标的「最近」一列直接复用会话树的结果。它今天正确，因为两者在同一个闭包里；一旦有人想改会话树的预览口径，得先想清楚会不会顺带改了转发目标那一列。

## Solution

会话树的「长什么样」变成一个可以单独问的纯函数，「展开着哪些」变成一个可以单独驱动的反应式模块。

用户看不到变化：侧栏的排列、预览、时间、展开行为都和今天一样。变的是那条「选中实例就展开父行」的规则第一次有了断言，以及会话树的投影口径不再需要起一个完整工作台才能验证。

下一个改侧栏的人只读两个小模块，而不是在一千一百行外壳里找哪几行是会话树。

## User Stories

1. As a 沙盒用户, I want 侧栏的排列、预览、时间与展开行为完全和今天一样, so that 一次纯结构性下沉不需要我重新验收界面
2. As a 沙盒用户, I want 分叉出新实例后侧栏确实高亮它, so that 我不会以为什么都没选中
3. As a 插件维护者, I want 「选中实例就展开所属那一行」有一条断言, so that 改坏它的人立刻看到红灯而不是等用户发现
4. As a 插件维护者, I want 会话树投影能单独问, so that 验证预览口径不必先起一个完整工作台
5. As a 插件维护者, I want 展开态能单独驱动, so that 展开、收起与自动展开三条行为各自可测
6. As a 插件维护者, I want 侧栏测试里关于这两块的源码文本断言换成行为断言, so that 等价重构不再误报、真实回归不再沉默
7. As a 插件维护者, I want 转发目标那一列与会话树的复用关系显式化, so that 改会话树预览时能看见谁跟着变
8. As a 插件维护者, I want 工作台外壳变短, so that 它回到「把各块投影拼起来」这一件事

## Implementation Decisions

### 两个模块

- `client/webqq/conversation-tree.ts`：纯函数，入参是沙盒场景、可见会话、当前操作者与头像解析函数，出参是侧栏会话树——根会话行加它们的实例子项。先例是 `environment-directory-model.ts` 与 `relationship-directory.ts`：同样是「把场景投影成某个视图要的形状」，同样以函数形态存在、同样接受注入的头像解析。
- `client/webqq/conversation-tree-expansion.ts`：反应式模块，持有展开着的会话 ID 集合，暴露「展开着吗」「切换」以及「按当前选中的会话补齐展开态」。先例是 `composer-draft.ts`、`scroll-restore.ts` 与 `evidence-navigation.ts`（ADR-0065）：都是有状态但与 DOM 无关的行为，住在模块里而不是组件里。
- 两个模块分开而不是合成一个：一个是纯投影、无状态；另一个是本地 UI 状态、有生命周期。合成一个会让「问一次树长什么样」被迫带上一份展开态。

### 自动展开那条规则

- 规则搬进展开态模块，形态从「组件里的 watcher」变成模块上的一个函数：给它当前选中的会话与会话树，它补齐必要的展开态。侧栏组件仍然在选中变化时调它一次。
- 仍然是「写进展开态」而不是「在判定里叠加条件」，理由不变：用户之后仍可手动收起那一行。这条理由从注释升级成断言——收起后不因为仍然选中而被强行展开回去。
- 展开态仍是侧栏本地状态，不进工作区状态、不持久化。它与选中哪个会话不是同一件事：折叠一行不改变选中。

### 会话树的口径

- 投影口径一字不改地搬过去：标题取实例名否则联系人名或群名、预览取拼接后最后一条消息（撤回时取撤回事件文案、没有消息时取「开始一段新对话」）、时间按 `zh-CN` 时分、头像种类按群组与机器人判定、群角色取当前操作者在群里的角色。
- 转发目标的「最近」一列改为显式复用同一个模块的结果，而不是复用外壳里的一个中间变量。复用关系因此写在类型上：改会话树投影时能看见谁跟着变。
- 会话实例挂到所属根会话下的分组规则一并搬走。层级仍严格两层，模块不引入第三层。

## Testing Decisions

**本规格不新增 seam。** 两个模块都落在既有的客户端投影这一面上，形态与 `environment-directory-model.ts`、`composer-draft.ts` 相同；外壳的 `sidebarModel` 仍是原来那个 interface。

这是一次结构性下沉，因此主判据是「既有测试不改也能过」：`webqq-conversation-tree.test.ts` 里那些经外壳观察侧栏树的断言必须一字不改地继续通过。它们今天已经覆盖了标题、预览、时间、分组与实例挂载，因此它们同时就是这次搬迁的回归网。

新增的断言只投向两处今天没有覆盖的地方：展开态的三条行为，以及会话树投影被单独调用时的口径。

### 测试面

1. **既有外壳侧栏断言全绿且未改写（主要判据）**——`webqq-conversation-tree.test.ts` 与 `webqq-sidebar.test.ts` 中与投影相关的断言一字不改地通过。需要改断言才能过就说明口径变了，停下来查。
2. **会话树模块的 interface（新的主要测试面）**——先例是 `environment-directory-model.test.ts`。覆盖：实例挂到所属根会话下、预览取拼接后最后一条、撤回时取撤回事件文案、没有消息时取「开始一段新对话」、头像种类按群组与机器人判定、群角色取当前操作者的角色。
3. **展开态模块的 interface（今天完全没有覆盖）**——覆盖：展开与收起、选中一个实例后其所属那一行被补齐为展开、手动收起后不因仍然选中而被强行展开回去、选中根会话不改变任何展开态、实例被删除后残留的展开态不影响其余行。
4. **侧栏组件里换掉的源码文本断言**——`webqq-sidebar.test.ts` 中针对这两块的源码文本断言删除；组件侧只保留读取模块结果的接线断言与用户可见文案，并按 ADR-0073 注明它属于哪一类。

## Out of Scope

- **侧栏其余部分的下沉**。好友目录、群组目录、通知面板、搜索筛选与顶部导航都留在原处；它们各有自己的来源与测试，混进来会让这次搬迁的回归网失效。
- **展开态持久化**。它仍是会话级的本地状态，刷新后回到全部收起。要不要记住展开过哪些行是另一件事。
- **三层及更深的会话树**。存储仍是根会话加实例两层，模块不为将来可能的层级预留参数。
- **侧栏的视觉调整**。排列、间距、图标与动画一律不动。
- **工作台外壳其余投影的拆分**。消息列表、输入区、详情栏、各工作台模型都留在外壳里。

## Further Notes

- 这次下沉最值得做的不是外壳变短，而是那条自动展开规则终于有了断言：它是「新建或分叉后新实例被自动选中」这条体验的最后一环，坏掉的表现是侧栏看起来什么都没选中，而不是报错。
- 判断这次搬迁是否纯结构性，用 stash 基线的办法：同一份确定性场景跑搬迁后与 `HEAD` 基线，比对侧栏模型的完整输出，而不是只看截图。
- 完成后 `webqq-sidebar.test.ts` 仍会剩下十来处源码文本断言，那些属于侧栏其余部分，不在本规格范围内；不要顺手一起改，那会让这次搬迁的回归网混进无关变更。
