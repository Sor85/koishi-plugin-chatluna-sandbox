# 08 — 消息时间的时区提成显式参数

**What to build:** 消息气泡上的时间在跨日、跨年那一刻显示正确，并且这件事第一次能被测。

消息时间今天用隐式取运行机器时区的方式格式化，而同一个仓库里早已有「显式时区 + 明确格式化器」的形状在用，这一处没接上。表现上的差别在开发机上撞不到——只有当运行环境时区与预期不一致，或恰好跨过午夜与年界时才会显现。

把时区提成显式参数，接上既有形状，并补齐边界断言：跨日、跨年、午夜、非法输入。

**这是本轮唯一的行为变化票。** 其余七张票的验收依据是「DOM 快照与基线逐像素一致」，而这一张会让时间文本在某些时区下变化，因此它不走快照比对，走行为断言——把它和其余票混在一起会逼人在快照 diff 里人工判断「这个差异是不是预期的」，而那正是快照流程要消掉的东西。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 时区成为显式参数，调用方传入而不是由格式化器隐式取
- [ ] 与同仓既有的显式时区格式化形状一致，不新造第二种写法
- [ ] 跨日边界有断言
- [ ] 跨年边界有断言
- [ ] 午夜有断言
- [ ] 非法输入有断言，且呈现是一个明确的缺省符号而不是 NaN 拼接
- [ ] 在与今天等价的时区下，消息时间文本逐字不变
- [ ] 组件的 props、emits、事件名与载荷逐字不变
- [ ] 票内写明这是本轮唯一的行为变化，验收不走 DOM 快照
- [ ] 完整测试、类型检查与构建通过
