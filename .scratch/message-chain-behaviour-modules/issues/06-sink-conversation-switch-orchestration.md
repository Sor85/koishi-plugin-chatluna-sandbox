# 06 — 会话切换编排与加载更早历史下沉

**What to build:** 会话切换那一刻的完整动作顺序，以及加载更早历史时的位置补偿，变成可以单独驱动的编排模块。

**切换顺序**今天写死在三个 watch 里：存下旧会话的滚动状态、结束进行中的恢复、取消贴底追踪、换成新会话的状态键、然后恢复或置底。顺序错一步的表现是「切回去位置不对」或「新消息不再自动跟随」，两者都不报错。快速来回切换时，前一次的排程必须不能污染后一次。

**容器尺寸变化**时是一个二选一：正在恢复则重新排程恢复，否则若处于贴底状态则置底。这个判定今天在一个 `ResizeObserver` 回调里，观察器的建立与断开也在视图里，改为注入。

**加载更早历史**：加载前记下锚点，加载后按锚点补偿滚动位置，使当前这一行不跳走；加载中有闸门防止重复触发；把外发事件包成 Promise 并吞掉拒绝（否则会产生未处理拒绝）。

界面一字不变。

## Comments

### 落地的两个模块

**`client/webqq/message-list-conversation-switch.ts`**（17 条行为断言）

1. `switchMessageListConversation(input, adapter)` —— 五步顺序：存旧 → 结束恢复 → 取消追踪 →
   换键 → 恢复或置底。测试用记录式替身把调用序列比成一串字符串，缺一步、错一步都对不上。
   三条顺序约束各自写明后果：存旧必须在结束恢复之前（否则写回中间读数）、换键必须在恢复之前

2. `routeMessageListContentResize({ restoring, stickingToBottom })` —— 容器尺寸变化的二选一，
   恢复优先于贴底。三条断言覆盖两个分支与「两者都不成立」。
3. `createMessageListContentResizeBinding(adapter)` —— 观察器的建立与断开经注入。八条断言：
   同时观察容器与内容列表、内容列表未渲染时只观察容器、重新绑定先断开上一个、卸载时断开、
   预览态不建立且先断开已有的、容器未挂上时不建立、宿主没有 `ResizeObserver` 时安静降级、
   回调把处置权交回调用方。

### 补偿不自己写 scrollTop，而是交给恢复排程

第一版按「加载前读锚点 → `nextTick` → 读新几何 → 一次性写 `scrollTop`」实现，浏览器实测
**落在半路**：`scrollTop` 从 300 补到 5910，首行换成了另一条消息（偏移 -180）。原因是新插进来的
50 条消息里有媒体与思考面板，它们在 `nextTick` 之后还在继续增高，一次写死的位置随即失效。

改成把补偿目标交给**既有的恢复排程**（`restore.begin(state)` + 分趟 `schedule`）后落点正确。
排程本来就是为「内容还会继续增高」准备的：两趟施加，且容器尺寸变化时按二选一重排。
这条弯路说明补偿的难点不是算术而是**时机**，模块里因此写明了这一点。

顺带定下一条判定：**贴底与锚点补偿互斥**。用户贴在底部时他读的就是底部，把他放回底部才是
「位置没变」；按锚点补偿反而会把他钉在半路，新消息也不再跟随。这条有独立断言。

### DOM 快照（与 `git stash` 回到基线逐项对照）

1. **通用快照**（四个会话 + 气泡菜单 + 头像菜单）—— 与基线**逐字一致**。
2. **滚动专项**（8 个采样点）—— 与基线**逐字一致**：进入群会话 `scrollTop 4715` 贴底、滚到 400、
   切走切回仍是 400 且首行与偏移相同、手动置底后切回仍贴底。
3. **加载更早专项** —— 这是本票要修的既有缺陷，因此**故意与基线不同**：

   | | 基线（票 05 已确认同样发生） | 本票 |
   | --- | --- | --- |
   | 上滑到 300 | `scrollTop 300`，首行「哼，贪心鬼…」偏移 -21 | 同左 |
   | 加载更早后 | `scrollTop 300`，首行换成「这次看清啦…」偏移 -102 | `scrollTop 9076`，首行仍是「哼，贪心鬼…」偏移 -22 |

   DOM 结构一字未变，变的只是滚动位置——正是验收项「加载更早后按锚点补偿位置」。

   滚动专项脚本里最后那个加载更早采样点在基线与本票**同为 13545（贴到底）**。它是脚本自身的
   状态所致：那一步没有派发真实的滚轮意图就直接写 `scrollTop = 200`，列表仍处在「贴底 + 恢复中」
   状态，因此走的是贴底分支而不是补偿分支。真实用户路径由加载更早专项脚本覆盖，那份派发了滚轮。
