# 02 — 消息呈现判定与参与者呈现投影下沉

**What to build:** 「这条消息该怎么显示」与「这个参与者该怎么显示」变成两个可以单独问的模块，不必先起一个组件。

消息呈现判定包括：事件化（事件消息，或撤回且关闭了撤回标记）、思考内容与 Token 用量随撤回标记一同隐藏、正文取值（合并转发卡片返回空串，单媒体且正文恰为标签加文件名时去重）、引用消息与转发预览的查表、消息能力位读取、继承前缀归属、分叉点分界、媒体标签与媒体大小、表情回应的能力位与操作者双闸门。

参与者呈现投影包括：名称、头像、群名片与全局昵称的回退、群身份徽标与专属头衔、群成员菜单与好友菜单的取数，以及「哪六个动作算群管理操作」那张今天内联在视图里、决定群成员子菜单是否出现的表。

顺带收编两处跨文件重复：媒体标签今天有三份逐字节相同的实现（其中一份已经是模块），媒体大小有两份。让另外几处复用既有模块，只收这两个函数，不把转发弹窗的其余行为拉进来。

界面一字不变。这是本轮第一张下沉票，它同时验证「按主题保留用例、类别以块注释标注」这套做法在真实断言上跑得通。

### 别处变红的处置

   把测试里的读取统一成 `readSource(path)` 小工具后，票 01 的规则**整体失效**：它按

   `sandbox-extension-menu`，同样用了读取小工具），一并登记为有主豁免，棘轮 22 → 24。
2. **假红** ×3 — `message-presentation.test.ts` / `participant-presentation.test.ts` /
