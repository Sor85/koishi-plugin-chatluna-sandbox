# 05 — 滚动锚点与单次恢复下沉

**What to build:** 「切回一个会话时滚动位置回到离开时那一行」这件事，第一次能被单独驱动和断言。

四块判定今天全留在视图里：

**锚点选取**——遍历消息行，取第一个底缘越过容器顶缘的那一行作为锚点。这是判定不是机械动作，「哪一行算锚点」改了会静默漂移。DOM 读取按最小结构接口注入。

**恢复的三分支**——贴底时直接置底；有锚点但找不到对应消息时直写滚动位置；找到时走既有的锚点补偿算术（算术已经是模块，分支判定还在视图里）。

**保存的两条边界**——预览态直接短路不保存；**正在恢复时写回待恢复状态而不是当前 DOM 读数**，否则恢复过程中途的滚动位置会把目标覆盖掉。第二条今天只是一句注释。

**分趟排程**——恢复分两趟施加，每趟都要校验当前会话键是否仍是排程时的那个，陈旧排程直接丢弃。帧调度今天直接用全局接口，改为注入。

外加定位揭示：滚到某条消息并高亮（高亮动作本身已是模块，何时滚、何时高亮的编排在视图里）。

## Comments

### 落地的模块

`client/webqq/message-list-scroll-restore.ts`，五块：

1. **锚点选取** `selectMessageListScrollAnchor(containerTop, rows)` —— 纯函数。视图把
   `[data-message-id]` 元素映射成 `{ messageId, top, bottom }`，映射是机械动作，判定在模块里。
2. **恢复的三分支** `resolveMessageListScrollRestore(...)` —— 返回
   `bottom` / `scroll-top` / `anchored` 三种结果，视图只管把结果写进 `scrollTop`。
   锚点补偿算术仍然复用既有的 `calculateAnchoredMessageListScrollTop`。
3. **保存的两条边界** `resolveMessageListScrollSave(...)` —— 预览态短路、正在恢复时写回
   待恢复状态。第二条此前只是一句注释。
4. **分趟排程** `createMessageListScrollRestoreScheduler(adapter)` —— 帧调度、施加与
   「当前活动键」全部注入，两趟各自校验一次键。
5. **定位揭示的编排** `revealMessageListMessage({ stopFollowing, highlight })` —— 只管顺序。

行为断言 23 条。

### 四条今天只写在注释里的规则第一次有了红灯

- 锚点取「第一个**底缘**越过容器顶缘」而不是顶缘：三条断言分别钉住正常情形、恰好贴边不算越过、
  以及第一行就越过时偏移为正。
- 恢复分支的**顺序**：贴底优先于锚点。贴底时保存的 `scrollTop` 属于旧内容高度，直写会落在中间。
- 正在恢复时写回待恢复状态：一条断言直接比对返回的是同一个对象引用（`toBe`），不是等值。
- 陈旧排程丢弃：两条断言分别在第一趟前和第二趟前改键，各自验证丢弃。

### 一个测试脚手架的坑

排程测试的替身最初按 `frames.length` 发帧号，`shift()` 之后号码会重用，导致「重复排程取消
上一次已排的帧」那条断言拿到错的号。改成单调递增计数器。这不是被测代码的问题，是替身的问题——
但它正说明帧号必须是真号，否则取消断言会假绿。

### DOM 快照

两份脚本，都与 `git stash` 回到基线的结果**逐字一致**：

1. 通用快照（四个会话 + 两个右键菜单）——一致。
2. **滚动专项快照**（8 个采样点）——一致。逐点数字：
   - 进入群会话：`scrollTop 4715`（贴底，`scrollHeight 5615 / clientHeight 900`）
   - 滚到 400：首行「Koishi 管理员 哼，贪心鬼…」，偏移 `-121`
   - 切到空会话再切回：`scrollTop 400`，首行与偏移**完全相同** → 锚点恢复生效
   - 手动置底后切走切回：`scrollTop 4715`，贴底判定为真 → 贴底分支生效
   - 加载更早前 `scrollTop 200`；加载更早后 `scrollTop 13545`，首行变了

最后那一条：**加载更早历史后当前这一行跳走了**。基线上完全相同（同样是 200 → 13545、
同样换了首行），因此它是**既有缺陷而不是本票引入的回归**。它正是票 06 的验收项
「加载更早后按锚点补偿位置有断言」要修的东西，采样脚本与基线数字已经留在这里备用。
