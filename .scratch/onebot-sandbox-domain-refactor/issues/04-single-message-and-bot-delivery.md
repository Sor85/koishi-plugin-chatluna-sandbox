# 04 — 实现消息单份存储与机器人事件投递

**What to build:** 让聊天消息在逻辑会话中只保存一次，并将消息存储与机器人事件接收分离。发送者始终是当前操作者，接收机器人根据私聊对端或当前群成员动态推导，同一消息可以独立投递给多个机器人而不复制历史。

**Blocked by:** 02 — 建立稳定私聊与好友关系生命周期；03 — 建立单一群聊与成员关系生命周期

**Status:** ready-for-human

- [x] 文本、媒体、回复和戳一戳消息只记录作者参与者与逻辑会话，不保存消息级机器人归属
- [x] 普通用户或机器人发送消息时，消息作者始终等于 `operatorId`
- [x] 用户向机器人私聊只向对端机器人派发事件，普通用户之间私聊不产生机器人事件
- [x] 群消息向所有符合条件的机器人分别派发，发送机器人不接收自己的入站事件，其他机器人仍正常接收
- [x] 每次事件投递能够通过 `recipientBotId` 区分目标机器人，并与同一个消息 ID 关联
- [x] 消息分页、回复引用、媒体读取和消息方向在单份存储下保持正确

## Answer

- `SandboxMessage` 删除消息级 `botId`，消息本体只保存作者参与者、逻辑会话、内容及回复、媒体或事件数据
- 用户与机器人统一通过 `sendMessage()` / `sendMediaMessage()` 写入消息，作者始终使用当前 `operatorId`
- 私聊按对端参与者动态推导接收机器人；用户之间私聊不投递机器人事件
- 群聊按当前群成员动态推导所有已启用机器人，发送机器人自动排除，其他机器人复用同一消息 ID 独立接收事件
- 新增 `SandboxBotDelivery` 与 `getBotDeliveries()`，使用 `recipientBotId`、`messageId` 和 `conversationId` 记录投递目标，删除消息或会话时同步清理关联记录
- 回复、媒体、戳一戳、分页和消息方向继续基于单份消息数据工作；前端方向只比较 `authorId` 与 `currentOperatorId`
- Standards 审查 0 项问题；Spec 审查 0 项问题。当前会话禁止派生子代理，因此由主线程按同样两个维度核对
- 验证通过：`yarn test`（29 个文件、112 个测试）、`yarn typecheck`、`yarn build`、`git diff --check`；Ego Browser 验证群聊消息只显示一次、操作者切换正常，页面无控制台异常
