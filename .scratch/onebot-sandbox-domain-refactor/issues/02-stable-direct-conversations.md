# 02 — 建立稳定私聊与好友关系生命周期

**What to build:** 让任意两个参与者之间只有一个与观察方向无关的稳定私聊。用户与用户、用户与机器人、机器人与机器人都使用相同会话模型；好友关系只决定当前是否可以访问和发送，不复制或销毁普通关系变更前的历史。

**Blocked by:** 01 — 统一参与者目录与操作者合同

**Status:** ready-for-human

- [x] 私聊由排序后的两个参与者唯一确定，双方观察到相同会话 ID 和同一份消息历史
- [x] 用户与用户、用户与机器人、机器人与机器人三种组合都可以建立和打开私聊
- [x] 删除好友后双方不能继续通过常规工作区读取或发送消息，但底层会话与历史仍保留
- [x] 重新建立好友关系后恢复原有私聊及历史，不创建镜像会话或新历史分支
- [x] 删除参与者会清理与其关联的私聊、消息、关系、申请和媒体引用
- [x] Console、OneBot 私聊入口和 WebQQ 私聊页面均能通过新私聊结构完成端到端验证

## Answer

- 私聊改为 `participantIds` 双端模型，并以排序后的参与者 ID 生成唯一 `private:<id1>:<id2>` 会话 ID
- 好友关系只控制私聊可见性和发送权限；删除关系保留底层会话、消息和媒体，重新加回好友后恢复同一份历史
- 环境创建机器人时会与已有参与者建立测试关系，因此机器人与机器人可以直接进入稳定私聊
- 删除参与者时按 `participantIds` 清理私聊，并继续清理关联消息、好友关系、申请、群组及媒体文件
- Console、OneBot 适配器、WebQQ 工作区选择和好友目录均已迁移到稳定私聊结构
- 验证通过：`yarn typecheck`、`yarn test`（28 个文件、107 个测试）、`yarn build`
