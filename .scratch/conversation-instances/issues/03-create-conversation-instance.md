# 03 — 新建空白会话实例，端到端

**What to build:** 用户在侧栏某个联系人或群组上新建一个会话实例，实例作为该会话的子项出现并被自动选中，在里面发消息，插件收到的是一个独立会话，ChatLuna 对话状态与模型请求记录因此各自归属，两条对话线互不污染。这是本规格的 tracer bullet，后续每张票都是在它之上追加。

会话实例是沙盒场景里的独立集合，只保存所属根会话 ID、自己的消息 ID 列表和标题；参与者对与群号一律从根会话读。层级严格两层，从实例再创建实例时归一化挂到同一个根。可见性完全继承根会话。实例 ID 沿用随机 ID 命名空间。

因为实例不在根会话集合里，既有遍历默认只看到根会话；确实需要全部会话的三处必须显式合并两个集合：消息搜索、场景消息保留窗口裁剪、以及后续票要用的场景导出。保留窗口沿用「共享预算、按时间最旧优先」，并且淘汰掉实例最后一条消息时不删除实例本身。

创建端点返回完整工作区状态外加新会话 ID，与其余变更端点同口径，客户端一次请求完成状态替换与选中。端点补进客户端类型声明，端口适配器不使用强制转换。侧栏会话树重新接线，数据源是「根会话加其实例列表」，创建入口可用，失败时走界面既有的错误展示路径。

## Comments

已完成。会话实例是 `SandboxSnapshot.conversationInstances` 里的独立集合，只保存
`{ id, rootConversationId, title, messageIds }`；参与者对与群号由解析模块从根会话读出。

服务端：解析模块新增实例解析、两层归一化、创建/改名、级联删除、投影与场景校验；控制服务新增
`createConversationInstance`，Console 端点 `chatluna-sandbox/create-conversation-instance`
返回完整工作区状态外加 `conversationId`。

客户端：`SidebarWorkspaceModel`/`ChatWorkspaceModel` 等改吃 `ResolvedConversation`，控制器与
`resolveWorkspaceSelection` 都能寻址实例；工作台外壳按 `kind` 组装「根会话 + 其实例列表」的会话树，
聊天区标题用实例名、副标题指出所属根会话；端口适配器无强制转换，客户端类型声明覆盖新端点。

两处值得记的边界：

1. 实例 ID 由调用方给出而不是解析模块自己生成。模块被客户端一同引用，`import { Random } from 'koishi'`
   会把整个 Koishi 运行时打进前端产物（实测 dist/index.js +460 KB）。已加守卫断言。
2. 快照字段声明为可选并在读取路径规范成 `[]`，与既有 `forwards` 同一处理方式，避免旧夹具与半成品导入炸掉解析。
