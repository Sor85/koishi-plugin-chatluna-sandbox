# 09 — 领域词汇与 ADR

**What to build:** 把「同一联系人下可以有多个会话」这件事写进仓库的领域记录，让后续工作不再用别的名字称呼它，也不再把逻辑会话唯一当作现行约束。

领域词汇新增「会话实例」条目，明确它是根会话下的一条独立对话线、可见性继承根会话、拥有自己的消息与标题，并列出应避免的替代叫法（分支会话、子会话、对话线、镜像会话）。改写「逻辑会话」条目：根会话对每对参与者与每个群组唯一，根会话下可以有多个会话实例。

新增一条 ADR 说明支持同一联系人下的多个会话实例，覆盖三个决定：实例是一等会话因此插件看到独立会话、实例移出根会话集合以换取「既有遍历默认只看根会话」、原始 OneBot action 保持只能寻址根会话并把偏离记成可断言证据。在 ADR-0042 中标注它的唯一性断言被部分取代，不改写 ADR-0042 原文——记录当时要求唯一的理由本身有价值。

**Blocked by:** 06

**Status:** resolved

- [x] 领域词汇的「逻辑会话」条目改写为根会话唯一、其下可有多个实例
- [x] 新增一条 ADR 覆盖上述三个决定
- [x] ADR-0042 标注唯一性断言被部分取代，原文未被改写

## Comments

ADR-0076 三段各承一个决定：实例是一等会话（组合键因此自动分叉，代价是分支复制消息摊薄保留窗口）、
实例移出根会话集合（换来十余处遍历默认只看根会话，需要全部会话的少数路径显式合并）、原始 OneBot
action 保持只能寻址根会话（偏离记成可断言证据而不是警告日志）。ADR-0042 只在标题下加一句部分取代
说明，原文段落逐字保留。

`_Avoid_` 里的「对话线」按「不得用它命名这个概念」执行，不禁止用它描述概念：词汇条目本身按本票的
要求写成「根会话下的一条独立对话线」。据此改掉了唯一一处用它命名概念的用户可见文案——侧栏展开按钮
的无障碍标签从「1 条对话线」改成「1 个会话实例」，并加了一条断言钉住。既有注释与规格里描述性的
「两条对话线互不污染」保持原样。

规格与实现的两处不一致已在规格侧修正：侧栏优化与用户故事 8 去掉「未读」（见票 08 的 Comments），
测试控制端点那条把「显式参数或独立工具」写实成 `list_conversations` 的 `rootConversationId`。

顺带补齐了票 02 只做了一半的架构守卫。规格要求的是「服务端源码不得直接读写会话集合与实例集合」，
而原规则的两条谓词只认 `.conversations`——`.conversations` 后面紧跟的是 `Instances` 而不是访问符，
正则命不中实例集合，实例集合等于没有守卫。补上两条同形状的谓词后规则报出唯一一处真实旁路：
`control-service.ts` 的 `normalizeSceneForwards` 自己给实例集合赋值。那条赋值与解析模块的
`normalizeSceneConversationInstances` 重复，把「非数组也归一成空集合」这个不变量收进模块的唯一读取口
`instanceRows` 之后直接删掉，豁免清单仍然为空。

评审反馈的处理：
- 侧栏 CSS 的纵向定位从「时间锚上沿、展开按钮锚下沿」改成两者都锚上沿，节奏的两个量提成
  `--webqq-session-meta-top` 与 `--webqq-session-meta-line` 写在会话列表上（展开按钮是会话行的兄弟节点、
  实例子项又不在会话行里，只有列表同时是三者的祖先）。这样行高变化不再需要同步两个魔数。已在两个
  浏览器里复测：时间 8–24px、展开按钮 26–52px、行高 58px，两处完全一致。
- 票 08 新增的源码断言里，锁住 `v-if` 写法与 `filteredConversations` computed 写法的三条按 ADR-0073 删掉，
  只留用户可见内容、样式源、否定式已删除守卫与死选择器规则守卫。「展开按钮随实例出现」「切到好友与
  群组页签后会话树消失」改由浏览器实测逐项执行验证，并在测试文件顶部注明。
- 未采纳「新增的间距违反 8px 系统」这条：`docs/webui-spacing.md` 把 8px 节奏限定在 Dialog 与 Popover
  形式的二级菜单，会话列表不在其范围内，且该文件既有的 6/10/12/26/58px 也不按 8px 取值。
