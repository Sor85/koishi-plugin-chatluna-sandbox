# 07 — 场景导出与测试控制端点的会话列表

**What to build:** 让会话实例在场景导出与外部测试控制器面前的呈现是明确的，不多也不少。

场景导出包含会话实例——导出是整份场景，漏掉实例会让导入回来的场景与原场景不等价。导入一份含实例的场景后实例原样保留，用户准备好的分支因此可以作为测试前置条件。

测试控制端点的会话列表默认只返回根会话，避免外部测试控制器把实例误当成新的联系人；需要观察分支时通过显式参数读取某个根会话下的实例。本票不新增「创建实例」或「分叉」这类写工具。

## Comments

导出与导入本身不需要改代码：`export_scene` 导出的就是整份 `getSnapshot()`，会话实例集合是场景的一
部分；`replaceScene` 已经经会话解析模块校验实例归属，且 `listConversationIds` 把实例算进合法会话，
因此实例里的消息不会被判成「引用不存在的会话」。这三条以前没有任何测试覆盖，现在补上了断言。

`list_conversations` 新增 `rootConversationId`：省略时返回根会话，显式传入时返回该根会话下的实例。
传入实例 ID 归一化到它的根会话，与领域模块「层级严格两层」同口径。显式传了非法值（空串、null、
数字）时按 `invalid_arguments` 失败而不是静默按省略处理——两种返回形状相同，静默回落会让调用方
以为自己拿到的是实例列表。不可见的根会话按 `conversation_not_found` 拒绝，不泄露它下面有几条对话线。

`clear_scene` 的空场景字面量补上 `conversationInstances: []`。原先靠读取路径的规范化兜底才为空，
现在清空语义写在调用点上，并由「清空场景后场景确实为空」用例断言。
