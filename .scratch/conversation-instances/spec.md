# 会话实例规格

Status: ready-for-agent

## Problem Statement

WebQQ 工作台里，一个联系人或一个群组只有一条对话线。要验证「同样的历史、换一种问法，插件会怎么答」，用户只能把消息逐条撤回或整段清空，原来的对话就没了；想同时留住原始对话和另一种试法，做不到。

这不只是界面上少一个分栏。ChatLuna 对话状态按虚拟 OneBot 机器人加逻辑会话相关，会话唯一就意味着上下文唯一——同一个联系人下不可能并行存在两条互不干扰的对话，模型请求记录也只能全部归到同一个会话名下。复盘一次长对话时，用户没有任何办法在不破坏原始证据的前提下从中间某条消息往下试。

工作区里已经有一版未完成实现，它把「实例」和「会话」压进同一个会话类型，用一个可缺省的父会话字段区分。已核实的后果是：全仓库十余处按参与者对或群号解析会话的实现对实例视而不见——OneBot 的私聊与群消息发送、消息历史、转发读取、戳一戳都直接拼回根会话的规范 ID；好友动作、群动作、关系目录、客户端可见会话投影都取第一个匹配；机器人的最近联系人列表反过来会把每个实例当成一个独立联系人。这些漂移全部是静默的，没有任何一处会报错。

## Solution

每个联系人或群组下可以有多个**会话实例**，在侧栏里作为该会话的子项展开。用户可以新建一个空白实例，也可以在任意消息上「创建分支」，把该消息及其之前的历史复制进新实例。

会话实例是一等会话。在实例里发消息，插件收到的是一个独立会话，ChatLuna 对话状态与模型请求记录因此各自归属，两条对话线互不污染。实例可以重命名，也可以删除并连带清理它的消息；根会话不能删，因为它的存在由参与者关系决定。

插件用标准 Koishi 路径回复时，回复落在实例里。插件用原始 OneBot action 回复时，回复落到根会话——真实 QQ 的 action 表面确实没有「会话」这一级，沙盒不替插件猜测归位，而是在 OneBot 调试记录里留下一条「回复偏离了事件来源会话」的观察结果，让测试者能够断言被测插件的这个真实行为。

会话解析本身收进一个模块：谁是根会话、某个 ID 指向根还是实例、某个操作者能看到哪些会话、一对参与者的根会话在哪，全部只有一处答案。实例不再混在根会话集合里，因此既有的十余处遍历默认只看到根会话，不需要记住任何新事实。

## User Stories

1. As a 沙盒用户, I want 在某个联系人下新建一个空白会话实例, so that 我可以从零开始试一段对话而不动原来的记录
2. As a 沙盒用户, I want 在任意一条消息上创建分支, so that 我可以保留该消息之前的上下文并从这里换一种问法
3. As a 沙盒用户, I want 分支实例带上分叉点之前的完整历史, so that 插件在新实例里看到的上下文和原会话在该点上一致
4. As a 沙盒用户, I want 侧栏把实例作为所属会话的子项展开, so that 我能一眼看出哪些对话线属于同一个联系人
5. As a 沙盒用户, I want 只有存在实例的会话才显示展开按钮, so that 没有分支的会话不被多出来的控件干扰
6. As a 沙盒用户, I want 展开按钮上显示实例数量, so that 我不必展开就知道这个联系人下有几条对话线
7. As a 沙盒用户, I want 会话行继续显示最后消息时间, so that 会话树没有换掉我原本用来判断新旧的信息
8. As a 沙盒用户, I want 实例子项也显示最后消息时间, so that 子项和父项的信息密度一致
9. As a 沙盒用户, I want 会话树只出现在「最近」页签, so that 好友与群组页签仍然是纯粹的关系目录
10. As a 沙盒用户, I want 给实例重命名, so that 多个自动命名的实例不会变得无法分辨
11. As a 沙盒用户, I want 新建实例有一个默认名, so that 我不必为每次试验先想名字
12. As a 沙盒用户, I want 从消息分叉出来的实例默认名指出它的来源会话, so that 我事后能认出它是从哪里分出来的
13. As a 沙盒用户, I want 删除一个实例并连带删掉它的消息, so that 废弃的试验不会一直占着侧栏和场景体积
14. As a 沙盒用户, I want 根会话不出现删除入口, so that 我不会误以为可以删掉由关系决定的会话
15. As a 沙盒用户, I want 在实例里发消息时插件收到的是一个独立会话, so that ChatLuna 的上下文从分叉点各自演化
16. As a 沙盒用户, I want 插件用标准路径回复时回复出现在我发消息的那个实例里, so that 分支对话读起来是连贯的
17. As a 沙盒用户, I want 插件用原始 OneBot action 回复时能看到「回复偏离了事件来源会话」的记录, so that 我知道回复为什么出现在根会话而不是怀疑沙盒出错
18. As a 沙盒用户, I want 群组的实例在插件那里仍然是群会话, so that 群专属的行为不会因为进了实例而变成私聊行为
19. As a 沙盒用户, I want 实例里的消息也能撤回、贴表情、引用和转发, so that 实例不是一个功能退化的会话
20. As a 沙盒用户, I want 实例里的机器人消息也能跳转到对应的模型请求, so that 分支里的复盘链路和根会话一样完整
21. As a 沙盒用户, I want 切换当前操作者后仍然看到实例, so that 实例不是绑定在某个操作者身上的私有草稿
22. As a 沙盒用户, I want 删除好友或退出群组后实例随根会话一起消失, so that 场景里不留下无主的对话线
23. As a 沙盒用户, I want 新建或分支完成后自动选中新会话, so that 我不必再去侧栏找它
24. As a 沙盒用户, I want 创建实例失败时在界面上看到原因, so that 错误不是只出现在浏览器控制台里
25. As a 沙盒用户, I want 消息搜索能搜到实例里的消息, so that 复盘不必先猜内容在哪条对话线上
26. As a 沙盒用户, I want 场景导出包含实例, so that 导入回来的场景和导出时等价
27. As a 外部测试控制器, I want 会话列表默认只返回根会话, so that 我不会把实例误当成新的联系人
28. As a 外部测试控制器, I want 可以显式地列出某个根会话下的实例, so that 需要时我仍然能观察到分支
29. As a 外部测试控制器, I want 导入一份含实例的场景后实例原样保留, so that 用户准备好的分支能作为测试前置条件
30. As a 插件维护者, I want 会话解析只有一处实现, so that 新增功能不会再长出一处「取第一个匹配」
31. As a 插件维护者, I want 一条架构守卫阻止绕过会话解析直接读写会话集合, so that 这次收敛不会在下一个功能里退化
32. As a 插件维护者, I want channel 类型来自解析出的会话而不是 ID 前缀, so that 群实例不会被当成私聊 channel
33. As a 插件维护者, I want 创建与分支两个 Console 端点返回完整工作区状态, so that 客户端不必为一次变更发两次请求
34. As a 插件维护者, I want 客户端类型声明覆盖这两个端点, so that 这条 RPC 链路不再靠强制转换绕过类型检查
35. As a 插件维护者, I want 会话实例作为领域术语写进领域词汇, so that 后续工作不会再把它叫成子会话或镜像会话
36. As a 插件维护者, I want 一条 ADR 说明为什么逻辑会话不再唯一, so that 原来要求唯一的理由和现状同时留在记录里

## Implementation Decisions

### 领域模型

- 层级严格两层：根会话加会话实例。从实例再创建分支时，新实例归一化挂到同一个根会话，不产生第三层。
- 会话实例移出根会话集合，成为沙盒场景里的独立集合。这是本规格最主要的一条决定：既有十余处遍历根会话集合的实现因此默认只看到根会话，不需要逐处加判断；确实需要全部会话的地方（消息搜索、场景消息保留窗口裁剪、场景导出）显式合并两个集合。
- 会话实例只保存所属根会话 ID、自己的消息 ID 列表和标题。参与者对与群号一律从根会话读，不复制。工作区里现有实现给根会话类型加的父会话字段与标题字段一并撤掉。
- 会话实例 ID 沿用随机 ID 命名空间，与根会话派生自参与者对或群号的规范 ID 天然区分。
- 消息只有一个会话身份：消息上的会话 ID 直接指向所属实例，不再额外冗余一个根会话 ID。「这条消息属于哪个根会话」由会话解析得出。
- 可见性完全继承根会话：根会话对某个操作者可见，其全部实例即可见。实例不引入所有权或创建者维度。
- 空实例是合法状态。保留窗口淘汰掉实例最后一条消息时，实例本身不被删除。
- 场景消息保留窗口沿用现策略：实例与根会话共享同一份条数与字节预算，按时间最旧优先淘汰，不引入按会话种类的优先级。
- 根会话不可删除，因为它的存在由参与者关系与群组决定；实例可删除并连带清理其消息、失去引用的合并转发资源与媒体。删除参与者、解除好友或解散群组导致根会话消失时，其实例连带清理。

### 会话解析 module

- 新增一个服务端领域模块，形态是一组接收沙盒场景的纯函数，与领域类型文件里已有的纯函数一脉。不是持有场景引用的类。
- 该模块同时拥有解析与实例的变更操作（创建、删除、连带清理）。实例集合的全部不变量与解析同处一个实现，避免「解析只有一处、谁能写实例又散开」。控制服务只负责提交场景变更（版本号递增、保留窗口裁剪、持久化、通知）与事件派发。
- 解析返回一个统一的解析结果类型，包含会话 ID、是根还是实例、所属根会话 ID、私聊还是群聊、参与者对或群号、消息 ID 列表。调用方一律吃这个结果，不再区分两种存储形态。这是该模块 depth 的来源。
- 收进该模块的既有实现：按参与者对确保私聊根会话、按群号确保群会话、按 ID 取可见会话、可见性判定、好友动作与群动作在缺少会话 ID 时的会话查找、事件投递时的会话标识构造、机器人最近联系人列表的会话来源。
- 虚拟 OneBot 机器人推断 channel 类型的方式从「解析会话 ID 前缀」改为「读解析结果」。这是必须一起修的缺陷：实例 ID 没有群前缀，群实例会被判成私聊 channel。
- 新增一条架构守卫规则：除该模块外，服务端源码不得直接读写会话集合与实例集合。已知违规按现有守卫的形状登记为显式豁免，理由与负责消化它的后续工作均为必填。

### OneBot 与 Koishi 表面

- 标准 Koishi 发送路径已经按 channel ID 解析会话，实例天然可达，不需要改动寻址方式。
- 原始 OneBot action 保持只能寻址根会话。真实 QQ 的 action 表面没有会话这一级，沙盒不按「最近一次事件」或异步上下文替插件归位——那会让沙盒行为与真实环境分叉。
- 当一次 OneBot action 落到根会话、而触发它的入站事件来自某个实例时，在 OneBot 调试记录里记录一条「回复偏离了事件来源会话」的观察结果，包含事件来源会话与实际落点。它是可断言的证据，而不是警告日志。
- 入站事件构造不变：Koishi channel ID 就是会话 ID，因此 ChatLuna 对话状态的组合键（机器人参与者 ID 加会话 ID）自动按实例分叉，模型请求记录的会话归属同样自动分开。ADR-0010 不需要修改。

### 测试控制端点与场景导出

- 场景导出包含会话实例；导出是整份场景，漏掉实例会让导入后的场景与原场景不等价。
- 测试控制端点的会话列表默认只返回根会话，实例通过 `list_conversations` 的显式 `rootConversationId` 参数读取，避免外部测试控制器把实例误当成新联系人。
- 本规格不给外部测试控制器新增「创建实例」或「分叉」这类写工具。按 ADR-0017 只暴露稳定的领域测试能力，会话实例目前是人工复盘手段。
- 默认场景不生成实例。

### Console RPC 与客户端

- 创建会话与创建分支两个端点改为返回完整工作区状态外加新会话 ID，与其余变更端点同口径。客户端因此一次请求完成状态替换与选中，不再紧跟一次工作区读取。
- 这两个端点补进客户端的 Koishi 客户端类型声明，并删掉客户端工作区端口适配器里的强制类型转换。同一个文件内控制台事件表与模块声明增强之间已存在的返回类型分叉一并对齐。
- 客户端保留现有的侧栏会话树、消息右键「创建分支」入口与样式，只更换数据源：树形从「根会话集合加父字段」改为「根会话加其实例列表」。
- 侧栏投影仍留在工作台外壳里，本规格不把它下沉成独立模块。
- 侧栏四处优化：会话行恢复最后消息时间；展开按钮只在存在实例时出现并显示实例数；实例子项补齐最后消息时间；「创建新会话」不再常驻子项末尾。同时清掉一个没有对应 class 的死样式选择器。未读不在本规格内——仓库里不存在已读位点这个概念，会话行自己也没有未读徽标，补上它是独立一轮工作。
- 会话树只出现在「最近」页签；好友与群组页签保持关系目录语义。
- 实例标题保留自动命名作为默认值（新建与从消息分叉各有默认文案），并新增重命名出口——当前实现只能在创建时给定标题，重复的自动名无法分辨。
- 创建实例的错误走界面既有的错误展示路径，与分支操作一致，不落进浏览器控制台。

### 文档与领域词汇

- 领域词汇新增「会话实例」条目（Avoid：分支会话、子会话、对话线、镜像会话），并改写「逻辑会话」条目：根会话对每对参与者与每个群组唯一，根会话下可以有多个会话实例。
- 新增一条 ADR 说明支持同一联系人下的多个会话实例，并在 ADR-0042 中标注它的唯一性断言被部分取代。不改写 ADR-0042 原文——记录当时的理由本身有价值。
- 未发布阶段兼容策略适用：直接删除被推翻的字段与实现，不保留过渡形态。

## Testing Decisions

好的测试断言从 interface 观察到的外部行为，不断言实现写法。按 ADR-0073，源码文本断言只在架构守卫、样式与用户可见文案三类例外中使用；数量断言不能替代逐个执行的覆盖。测试面优先复用既有 seam，本规格只新增一个 seam，就是会话解析模块自身的 interface。

### 测试面

1. **会话解析模块的 interface（新增 seam，主要测试面）**——纯函数，输入沙盒场景。覆盖：ID 指向根还是实例的解析、实例继承根会话可见性、根会话不存在时的错误、两层归一化（从实例分叉挂到同一根）、创建与删除实例的连带清理、空实例合法、全部会话的显式合并。这是唯一的新 seam，因为解析是这次改动的全部价值所在。
2. **控制服务的公开方法（既有 seam）**——先例是现有的控制服务测试与场景消息保留测试。覆盖：在实例里发消息、实例消息进入搜索结果、保留窗口按时间淘汰实例与根会话的消息且不删空实例、删除参与者与解散群组时实例连带清理。
3. **虚拟 OneBot 机器人的两个表面（既有 seam）**——先例是现有的消息投递测试与 OneBot 桥接测试，两者已经断言 channel 标识。覆盖：实例内发消息时插件收到的 channel 是实例 ID、标准 Koishi 发送路径回到同一实例、群实例的 channel 类型仍是群聊、原始 OneBot action 落到根会话并产生「回复偏离事件来源会话」的调试记录。
4. **Console RPC listener（既有 seam）**——先例是现有的控制台适配器测试。覆盖：两个端点返回完整工作区状态且包含新会话 ID。
5. **客户端工作区端口与控制器（既有 seam）**——先例是现有的工作区控制器测试与内存假端口。覆盖：一次请求完成状态替换与新会话选中、失败时的错误归一化。
6. **侧栏投影（既有 seam）**——先例是现有的侧栏测试与关系目录测试。覆盖：实例作为子项出现在所属会话下、无实例时不出现展开控件、实例数、好友与群组页签不含实例。
7. **架构守卫（既有 seam）**——先例是现有的客户端架构守卫测试。新增规则对服务端源码全量生效，并保持「移除任一豁免后对应文件重新报错」这条自检。

### 不用测试覆盖的部分

ChatLuna 对话状态与模型请求记录按实例分叉是既有组合键的自然结果，不新增针对性断言，只在实例往返测试里顺带确认状态键不同。UI 的四处布局优化按 ADR-0073 属于样式与文案范畴，用现有的样式与文案断言覆盖，不引入组件挂载测试。

## Out of Scope

- **分支不再复制消息**。本规格的分支仍然复制分叉点之前的消息，因此单份消息存储不成立，场景消息保留窗口的预算按分支数被摊薄。把分支改为只记录分叉点、读取时拼接根会话前缀是独立一轮工作，它会改动消息存储与消息历史分页的验证面。
- **Console RPC 契约派生成单一类型**。同一份端点契约目前有三份声明（控制台事件表、模块声明增强、客户端类型声明），本规格只把新端点补齐并删掉强制转换，不做派生与端点集合守卫。
- **侧栏投影下沉成独立模块**。会话树投影与展开态仍留在工作台外壳与侧栏组件里。
- **实例的 MCP 写工具**。外部测试控制器本轮只能读，不能创建或分叉实例。
- **三层及更深的会话树**。归一化为两层，不支持嵌套分支。
- **实例私有化**。不引入创建者或所有权维度，实例对根会话的全部可见参与者可见。
- **跨实例的对比视图**。并排比较两条对话线不在本规格内。
- **浏览器实测**。UI 换数据源与四处优化完成后单独跑一次，不与领域改动混在同一轮归因。

- 工作区里已有的未完成实现按「保留界面、回退领域与 RPC」处理：侧栏会话树、消息右键入口与样式保留并改数据源；根会话类型上的父会话与标题字段、分支复制消息的实现、两个端点的返回形状、客户端适配器的强制转换全部按本规格重写。这会丢弃一部分已写代码，是有意的——逐步改造会留下过渡形态。

- 侧栏子项右键现在的「删除会话」实际发的是客户端最近会话隐藏标记，实例会在下次刷新后回来、消息永远留在场景里。本规格把它改成真正的领域删除，这是一个既有的假按钮，不是新功能。
