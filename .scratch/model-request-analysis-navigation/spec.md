# 模型请求分析导航滚动行为

## Problem

模型请求分析页在原左侧导航离开视口后会创建一份 fixed 导航副本。滚动到边界时用户会看到第二套分类列表，且副本与原导航使用两套折叠状态。

## Solution

分析页只保留一份左侧分类导航。导航在模型请求详情滚动容器内吸顶；右侧阅读探针进入新分类时，左侧自动折叠已经越过的分组，当前分类及尚未读到的分组保持展开。向上滚动时按当前分类重新展开后续分组。左侧顺序对齐右侧阅读顺序，将 Variables 放在 User 后、Response 放在 Variables 后。阅读探针还会追踪具体卡片，自动高亮并滚动左侧对应条目；滚动保留上下安全间距，确保当前条目完整可见。分类标题仍可手动切换折叠状态。

## Acceptance Criteria

- 页面不存在额外的 fixed/fallback 分类列表
- 左侧单一导航在详情滚动期间保持可见
- 从 system 进入 user 时只折叠 system
- 继续进入后续分类时依次折叠已经越过的分类
- 向上滚动时按当前分类恢复当前及后续分组
- 左侧顺序为 System、User、Variables、Response、Assistant、Tool（隐藏空分组）
- 右侧滚动到具体卡片时，左侧对应条目高亮并自动进入可视区
- 当前条目上下保留安全间距，列表末端也能完整显示
- 分类标题点击仍可独立展开或折叠
