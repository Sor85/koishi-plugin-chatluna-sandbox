# 为场景消息设定保留上限

沙盒场景的消息不再无限增长。每个环境（主环境与每个 AI 测试空间各自独立）同时受消息条数上限和场景 JSON 字节上限约束，达到任一上限后从最旧消息开始淘汰，并级联清理会话的 `messageIds`、因此变成孤儿的合并转发资源，以及不再被任何引用持有的媒体文件。

这么做是因为场景是整块落盘的：每次领域变更都会把完整场景写一遍，没有上限时写入规模随累积消息数线性增长，长时间运行的环境会退化成每条新消息都重写数 MB。上限把单次写入钉在恒定上界，代价是复盘窗口有限——超出上限的历史消息会真正丢弃，不做归档。

保留上限与 OneBot 调试记录、模型请求记录采用同一套「条数 + 字节双上限、淘汰最旧」策略，但三者的配额彼此独立：调试证据的价值随时间衰减得比聊天上下文更慢，不应共享同一份预算。消息淘汰只影响持久化与展示，不改变 ADR 0042 的单份消息存储模型，也不改变会话实体本身的生命周期。
