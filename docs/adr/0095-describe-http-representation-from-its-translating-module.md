# HTTP 表述的自述由翻译它的模块给出

环境管理里的「HTTP 能力」页读一个服务端自述：路由清单、路径前缀与版本段、可拨通的基址、请求体上限，以及全部稳定错误码到 HTTP 状态码的映射。这份自述由 `src/mcp/http-api.ts` 产出——那正是解析路径、判定动词、映射状态码和限制请求体的同一个模块，因此页面上的每一行都直接取自生效中的实现，而不是另抄一份。自述里每条路由带上与解析器同名的路由种类，守卫测试把自述的动词与请求目标喂回解析器逐条比对，改了路由却忘记改自述会当场变红。

监听地址、端口、TLS 与两个总开关归插件配置所有，因此自述在插件入口按当前配置派生一次，与监听器读同一份值，随测试控制服务一起作为一个整体的可空值交给 Console 注册；端点没造出来时这个页面表现为不可用，与 MCP 能力页一致。通配监听地址在基址里换成回环地址：`0.0.0.0` 与 `::` 是「监听所有网卡」而不是目的地，原样给出会得到一个看着像地址却未必连得上的示例。

不把工具清单再放一份到这个页面：工具、资源与权限范围由两种表述共用，已经由 MCP 能力页按服务端权威定义展示，HTTP 页只回答「同一批能力怎么用普通 HTTP 调到」。承载两种表述的决定见 ADR-0081，错误码清单的单一来源见 ADR-0027。
