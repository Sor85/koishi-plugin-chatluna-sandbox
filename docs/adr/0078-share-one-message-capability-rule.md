# 消息能力判据共享一份，强制仍在服务端

「这条消息在这个会话里对这个操作者能做什么」收成一份判据，服务端与客户端都问它。写这条 ADR 之前两边各推导一遍，而没有任何东西把它们绑在一起，本轮实测出三处已经漂了：客户端不在事件消息上显示「贴表情」，服务端却会给一条戳一戳事件挂上表情回应；客户端不在事件消息上显示「创建分支」，服务端却接受从事件消息分叉；客户端不在已撤回消息上显示「回复」，服务端却接受引用一条已撤回的消息。三条都能经 Console 端点直接达到，挡住它们的只有客户端那份推导。撤回的群角色阶梯是第四种情形：服务端与客户端各写了一遍，今天答案一致，但没有任何测试要求它们保持一致，改任一边都不会有人变红。分开判会静默漂移，这不是假设。

漂移的方向也重要。真实 QQ 里没有「给系统提示贴表情」这回事，也不能引用一条已经撤回的消息。沙盒的全部价值在于对它做出的断言能反映真实环境，因此实测出的三处都按客户端本来的严格程度收紧到服务端，而不是反过来放宽客户端；此外「引用一条系统提示」按同一条依据一并收紧，理由见末段。界面行为因此不变，变的是 Console 端点、外部测试控制器与未来的 MCP 工具这些别的入口。

**强制仍在服务端，客户端的答案只用来渲染菜单。** 这两句和「判据只有一份」不矛盾：前者说的是那份判据在客户端的运行结果不构成授权，客户端的答案永远可以被绕过，因此服务端的写入路径照旧自己问一遍再拒绝。判据共享消除的是口径的第二份实现，不是那一层强制。相应地，判据是一个不持有场景的纯函数模块（`src/message-capabilities.ts`，形态与 `conversation-resolution.ts` 一致），放在 `src/` 而不是 `client/`——客户端已经直接引用 `src/types.ts` 与 `src/conversation-resolution.ts`，放到 `client/` 会让服务端反向依赖客户端目录。判据本身不做可见性校验：「这个操作者看不看得见这个会话」是另一个问题，由各入口既有的可见性校验负责。

**能力位不进快照载荷。** 判据共享后客户端自己就能算，没有理由让每条消息在 RPC 上多带五个布尔值；能力位随当前操作者与群身份变化，放进载荷还会让它成为一份需要跟着失效的派生状态。客户端在工作台外壳的 `messageList` 投影里按每条消息算一份，判定因此从 `.vue` 里搬到能从 `chatPaneModel` 的 interface 上观察到的地方——这也是右键权限第一次能用行为断言而不是源码文本守住，[ADR-0073](./0073-assert-interfaces-and-guard-by-rule.md) 点名的那类肯定式接线断言因此可以删掉。同一条规则制守卫钉住「客户端不自己判定消息能力」，读取投影的模块是唯一合法持有者。

能力集合限定在五项：撤回、贴表情（含切换一条已有回应）、回复、创建分支、合并转发多选。继承前缀在会话实例视图里的只读约束是其中一部分而不是另一处判断，[ADR-0077](./0077-record-fork-points-instead-of-copying-messages.md) 里「只读约束的是用户在分支视图里的操作入口」因此在本文里落成两个能力位，那条决定本身不变。群成员菜单与好友菜单的权限不并入：它们回答「一个成员能对另一个成员做什么」，与「一条消息能做什么」不是同一个问题，撤回的群角色阶梯与群成员管理的 `assertCanManageMember` 因此各自成立，收成一处指的是撤回那条阶梯只有一份实现。「跳转到对应请求」也不并入，它不是能力而是有没有证据可跳。

事件消息在五项上一条都做不到。真实 QQ 里戳一戳这类事件是通知而不是消息，它压根没有消息编号可供引用、贴表情或分叉；沙盒把它存成一条带 ID 的消息只是为了让 WebQQ 能在时间线上如实呈现它，那个 ID 不代表它变成了可操作的对象。因此除了实测出分歧的贴表情与创建分支两项，引用回复也一并关闭——它与另外两项同源，留着会让「系统提示不是可操作的消息」这句话只成立三分之二。被测插件因此在引用一条系统提示时收到明确拒绝，而不是在沙盒里成功、到真实环境再失败。
