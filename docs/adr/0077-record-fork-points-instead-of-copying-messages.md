# 分支只记分叉点，读取时拼接继承前缀

会话实例只记下「来源会话加分叉点消息」，一条消息都不复制；它的历史在读取时由来源会话中分叉点及其之前的那一段拼上自有消息得到。这取代 [ADR-0076](./0076-support-multiple-conversation-instances-per-contact.md) 里「代价是分支要复制分叉点之前的消息，场景消息保留窗口的预算因此按分支数被摊薄」那一段；该文原文不改写，当时接受复制这个取舍的理由本身有价值。复制让同一段历史按分支数占用多份消息额度，而沙盒的场景消息双上限一到就从最旧的开始真正丢弃：分支的用途恰恰是留住原始记录作为对照，它却在消耗原始记录的存活空间。复制还让同一条逻辑消息有了两个身份，表情回应、思考内容与 Token 用量因此各有一套副本。只记分叉点把 ADR-0042 的单份消息存储恢复成字面意义上的一份，创建分支也因此与历史长短无关。

只存分叉点，不额外存一份前缀消息 ID 的快照。消息只追加不插入，因此「来源会话当前列表到分叉点为止」与「分叉时刻的前缀」在正常路径上等价；两者只在来源会话被清空或被保留窗口淘汰时不同，而那两种情况下消息正文本身已经不存在，多存一份 ID 列表也救不回来——它只会变成一份与真相不一致的状态。继承前缀因此随来源变化：来源里那条消息被撤回，分支里如实显示已撤回；来源被清空，分支分界线以上变空而分支仍在，这与「更早的消息已不在保留窗口内」是同一种事实。

继承前缀在分支视图里只读，但消息实体的生命周期不冻结。这两句容易读成矛盾，区分点是约束的对象：只读约束的是**用户在分支视图里的操作入口**，防的是用户在对照组里误改原始记录，因此不能撤回、不能贴表情、清空分支时它不受影响，但可以引用它继续追问——「在分叉点那句话上换一种问法」正是分支最自然的用法。消息本身能不能变则是另一回事：被测插件通过原始 OneBot 撤回或贴表情作用到一条继承前缀时允许执行，它寻址的是根会话里的一条普通消息，拒绝会让沙盒表现出真实环境不存在的错误。相应地，判定会话归属是请求层的边界，写入路径只认消息实体：请求声明了会话就要求它等于消息自身的归属，省略会话则按归属执行，插件通道走的正是后者。

来源会话可以是根会话，也可以是另一个会话实例；从分支里再分叉时读取沿来源链逐段拼接，因此新分支看到的是上一条分支里那几轮对话，而不是跳回根会话的历史。存储层级仍严格两层——所有实例都挂在同一个根会话下，链只在读取时展开，ADR-0076 里「实例下不再有实例」因此不变。拼接是「读某个会话的消息列表」这一个函数内部的实现，所有需要会话消息的路径都经它，规则只有一处；投影必须把拼接结果物化进实例行并同时去掉分叉点，否则客户端与 MCP 这些消费投影的一方会拿着已经拼好的列表沿来源链再拼一次。消息搜索按消息实体自身的会话归属报告命中，命中继承前缀时报它真正所属的那一段：一条逻辑消息只有一个会话身份，按分支重复报告会让结果数随分支数膨胀。
