# 一个工具的全部事实住在注册表的一条条目上

测试控制端点对外提供的 40 个工具，每一个的全部事实住在 `src/mcp/tool-registry.ts` 里的一条条目上：名字、能力范围、说明、参数 schema、配额与并发分类、显式空间标识的解析方式、要不要幂等、要不要版本绑定的一次性确认令牌，以及它的执行体。加一个工具从「在五处各写一次」变成「注册一条」，而**「声明了工具但没有分派」这个状态不可表达**——条目自带执行体，没有条目就没有工具。它此前的失败形态是工具出现在 `tools/list` 里、AI 客户端发现并调用、拿回「工具不存在」，发现得晚且发现者是消费者。这条从「需要断言的规则」变成「不可能发生的状态」，因此不为它补断言。

真正的收益不是少一条 43 分支的条件链，而是三件事第一次成为条目上可读的字段。**配额分类与并发分类是同一个字段**：两者原先各写一句内联表达式，逐项比对后只有一处不同——只读档不占并发闸门——因此条目上只放一个分类，那一处差异写成调用治理里的一行，而不是每个工具的第二个字段。**参数 schema 内联到条目上**：原先工具声明与 schema 是两张按名字连接的表，连接写法是「按名字取，取不到就给一个空 schema」，一个打错的键会静默产出空 schema，而 schema 是 AI 消费者唯一能学到参数契约的地方（`tools/list` 之外没有别处）；内联之后这个连接不存在了，也就没有静默失败的余地。**显式空间标识的解析方式是独立字段，不能从配额分类推导**：清理 OneBot 调试记录的能力范围是调试类（配额档因此是只读），却按写操作解析空间——一个凭证不得省略 spaceId 就抹掉主环境的证据。这正是原先那句九项否定条件藏住的东西。

解析方式是三态而不是布尔，因为原先的九项否定条件只覆盖了「已经走到那一行」的工具，另有三族工具靠提前返回表达「治理不代它解析」，硬压成两态会改错误码：没有空间参数的（服务自述、空间清单、测试调用记录）无从解析；空间生命周期那五个由测试空间服务自己校验状态，经空间三态判定会把「空间当前不可修改：failed」这类领域拒绝改写成空间不可用；模型请求记录那三个的记录域由 `scope` 参数决定而不是 spaceId 单独决定（[ADR-0083](./0083-own-the-set-of-record-scopes.md)），清理那一个还必须先拒绝未归属分类，否则一次 `{ scope: 'unattributed' }` 调用会报成「必须显式指定空间」而真正的原因是这个分类根本不允许经测试控制端点清理。

**幂等与确认令牌是两个独立标记**，不是一个三态枚举。十一个工具要幂等，四个要确认令牌，上传媒体与准备确认令牌两个都不带。今天没有工具同时命中两者，因此组合顺序在治理里定死一次（确认在外、幂等在内）并注明「今天不可观察」——合成枚举等于替一种不存在的状态建模，真出现同时命中的工具时改治理里那一处即可。

注册表必须是**模块级常量**。幂等键的说明文案由实例配置决定（窗口时长与保留条数），由读取工具声明的那一处统一注入；所有对外读取声明的路径（`listTools`、`getCapabilityCatalog`、`chatluna-sandbox://guide`）都经同一处，声明因此不可能与实际配置漂移。注册表变成实例构造的东西就要重写这条保证。执行体相应是**自由函数**，签名收一份窄的调用运行时（已解析的控制服务、追加事件、当前游标、要求测试空间、要求未归属记录库、按显式空间另取控制服务、上传媒体缓存、登记确认令牌、测试调用记录读写），不注入服务实例，也不用方法名字符串转发——后者会让类型检查失效，写错一个名字要等到真的调用那个工具才发现。

调用治理随之变成一条直线：查注册表、校权限范围、扣配额、过并发闸门、按标记包幂等或确认令牌、执行、写测试调用记录、归一化错误并回填场景版本。**一次工具调用仍然只有一个外部编排入口**，两种协议表述落到同一次调用上的权限、配额、幂等、确认令牌与测试调用记录不存在第二份实现，治理不得下沉到某一个表述里（[ADR-0081](./0081-serve-http-test-api-beside-mcp.md)）；两个协议适配器本轮一行未改，仍然只把工具名原样透传。

一条守卫规则拦住下一个特例：服务端源码里工具名不得与字符串字面量比较，谓词按标识符名判定——工具名标识符与字面量的相等或不等比较，以及在这类标识符上调前缀判定并传字面量。刻意不用宽松的「某个名字等于字面量」形状，那个形状在模型证据那一族里有一处合法命中会变成误报；`typeof` 的操作数先被抹掉，因为 `typeof args.tool === 'string'` 比较的是类型名。规则跑遍服务端源码、不列文件白名单，落地后**零违规、零豁免，也不需要持有者**——注册表条目里工具名是属性值而不是比较，谓词命不中它（[ADR-0073](./0073-assert-interfaces-and-guard-by-rule.md)）。

本轮只收 implementation，一条既有决定都不推翻：ADR-0081 的两种表述并列且治理只有一份、[ADR-0027](./0027-return-stable-structured-mcp-errors.md) 的三类错误归一化、[ADR-0020](./0020-require-explicit-user-identity-in-mcp-tools.md) 的测试端点保持显式范围、[ADR-0028](./0028-version-the-test-control-api-independently.md) 的测试 API 版本推进都保持原样。对外一字不变，且有两份不来自实现的契约测试钉着：一份是测试侧独立书写的工具目录，一份逐工具断言顶层参数名集合，两份一字未改地通过；能力目录完整输出与 40 个工具的参数 schema 完整 JSON 与收拢前的基线逐字节相同。报告同时提出的另外两个候选——事件等待（游标、静默期等待、纪元轮转）成为内部 module、凭证持久化成为 adapter——各自自洽且与注册表无依赖，留作后续；把调用治理搬进单独的文件不是一个独立动作，治理变窄是注册表落地后的结果。
