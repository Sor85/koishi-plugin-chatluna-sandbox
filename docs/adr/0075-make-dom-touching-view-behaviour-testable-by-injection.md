# 触碰 DOM 的视图行为靠注入最小结构接口取得可执行 interface

不引入 jsdom 或 happy-dom，也不引入组件挂载测试。要让触碰 DOM 的视图行为可断言，办法是把判定与 DOM 机械动作拆开：判定进 module，DOM 动作留在视图里由参数注入。判定是「什么时候降级到同步复制」「位移多少才算拖动」「缩放锚点算在哪里」这类会回归的东西；DOM 机械动作是「造一个离屏 textarea 再执行复制命令」「造一个 a 元素点一下」这类写完就不再变的东西。前者需要测试，后者需要的是一次人工验证。

注入的形状取最小结构接口而不是 DOM 类型。请求组成图的拖动只需要视图口的 `scrollLeft`、`clientWidth`、左边界与三个指针捕获方法，因此接口就声明这六项，`HTMLElement` 天然满足，测试写一个内存替身即可。事件同理：滚轮判定只读 `ctrlKey`、`deltaY`、`clientX` 与 `preventDefault`，`WheelEvent` 结构上满足这四项。声明成 DOM 类型会把整个 DOM 拖进测试环境，而声明成自定义 DTO 又要在视图里写一层转换。

时间与时区是同一类问题的另一种形态。原先的记录时间格式化直接读 `Date` 的本地字段，于是「同一时刻算哪一天」取决于跑测试的机器，跨日、跨年与午夜这三个边界根本没法断言。改成 `Intl.DateTimeFormat` 加显式 `timeZone` 参数后，不传参仍按浏览器本地时区渲染，用户看到的结果不变，而测试可以指名时区去断言边界。凡是判定依赖环境隐式提供的东西——时区、当前时间、剪贴板可用性、动画帧——都把它提成参数，默认值指向真实环境。

状态机以 Vue 的 `ref` 形式住在 module 里，而不是纯状态对象加视图侧的 `computed` 包装。视图从 module 解构出来的 `ref` 在模板里照常双向绑定，模板不必知道状态住在哪里；测试则直接读写 `.value` 驱动转换。纯状态对象那条路也可行且更轻，适合没有生命周期的选择态；一旦转换涉及多个字段必须同拍变化，命名转换比逐字段赋值更值得，因为漏掉其中一个赋值不会报错，只会表现为「返回后落回分析页」这类偶发错位。
