# 用一个 module 拥有证据分类与展示标签

模型请求证据的分类及其展示标签由位于 `src` 的浏览器安全纯证据种类 module 独占，不进共享模型证据投影：投影只理解协议结构，它的消息角色与响应事件种类描述「从原始模型证据能证明什么」，而徽标文案、标题文案与大小写是展示概念，塞进投影会让协议识别开始承担排版职责。证据种类 module 拥有三件事——八种基础证据种类的全集、每种成对声明的徽标与标题标签、以及若干具名聚合；服务端轨迹派生与客户端四处视图共同消费它，视图不再各自持有分类词汇或标签表。

多档粒度保留，但聚合关系显式声明而不是藏在条件分支里。请求组成图把工具调用与工具结果合并为工具交互，因为它按字符占比统计而这两者在请求消息里成对出现；分析导航把三种工具证据收在一个工具分组下，因为分组标题下要挂多个条目。聚合具名后，「组成图把工具调用与工具结果算作一类」第一次成为可以断言的事实。每个视图从基础种类取自己需要的子集或聚合，这是显式选择：过滤开关取八种中的七种而不暴露模型响应，因此模型响应分组不参与种类过滤——这是一个被记录下来的显式缺口，不是遗漏。

两个标签变体按排版语境区分而不是统一成一种：轨迹账本的种类列与过滤开关是徽标（有背景色、内边距与固定高度），组成图图例与导航分组标题是标题，全大写与词首大写因此是常规排版惯例带来的有依据的区分，统一成一种反而会让其中一处显得突兀。徽标变体恒等于标题变体的全大写形式，成对声明保证两者不会各自漂移，同一种证据也不会在两种语境下叫法不一致。

轨迹行的种类随之压成一维基础证据种类，工具事件副字段删除：判断一行是工具定义、工具调用还是工具结果不再需要读第二个字段，取标签从两个参数变成一个。请求边界继续作为轨迹账本特有的行类型存在，标签留在视图侧。这是 Console RPC 可见的形状变更，依未发布阶段兼容策略直接变更，不加兼容层也不并行两套字段。
