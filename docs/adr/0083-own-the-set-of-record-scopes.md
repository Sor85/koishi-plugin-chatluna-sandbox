# 记录域目录拥有全部记录域

证据记录按记录域归属：主模拟 QQ 环境、每个 AI 测试空间，以及无法安全归属的未归属记录。「谁是全部记录域」由一个服务端 module 唯一持有，它提供三种跨记录域的行为——联邦读取一页、按顺序查找第一个命中、逐个记录域各执行一次供调用方汇总——而不是让每个调用点自己枚举测试空间。记录域清单的顺序是接口的一部分而不是实现细节：主模拟 QQ 环境在前、AI 测试空间按创建序、未归属在末尾，「先查主环境再逐个找」这一语义由该顺序表达，调用方不再各自声明一次。未归属只有模型请求库、没有沙盒场景，因此它永不参与联邦读取，必须显式指定范围才能读到；这条规则由该 module 拥有，而不是由每个调用点各写一次过滤。测试空间服务与未归属记录库在插件入口是必定存在的，可选只服务于测试，因此判空在构造记录域目录时被吸收一次——缺席就是清单里少一个成员，之后的代码里不再出现判空。

联邦页只要求四个字段：记录数组、是否还有更多、当前最早游标、容量摘要。这四个字段在 OneBot 调试记录页与模型请求记录页上同名同义，容量摘要的四个子项也一致，因此合并可以直接相加。两种页的实质差异只有两处，都由调用方声明而不是写进该 module：第二排序键（模型请求用记录标识，调试记录用序号）以 `createdAt` 相同时的破平函数表达；续页游标只在第二排序键跨记录域全局可比时提供——模型请求的时间与标识组合全局可比，WebQQ 的「加载更多」正在使用，而调试记录的序号是每个记录域各自独立的计数，跨记录域比较没有意义，因此调试记录的联邦页没有续页游标，精确游标分页必须带显式范围。每页条数的上限由调用方按自己的记录种类先夹紧再传入，避免某一种记录的上限被强加给另一种。

联邦读取与查找在读取前等待全部成员的场景就绪。记录库自身的读取路径已经各自等过自己的就绪，这里额外等到的是场景就绪与场景待写队列；此前只有调试记录那条路等、模型请求那条完全不等，两条路统一向保守的方向对齐，因为多等一次已就绪的 Promise 成本接近零，而漏等的后果是静默返回空列表。查找的未命中用返回空值表达而不是抛错：原先的实现用 try/catch 遍历，把「这个记录域里没有这条记录」与「这个记录域的持久化坏了」混成同一件事，一次真实故障会被当成未命中静默跳过，现在故障照原样抛出。逐个记录域执行只负责遍历，「这个操作要不要先接管空间」是注册时的权限策略，留在调用点显式书写，不进该 module。

测试控制端点保持单个记录域的门禁，不因收拢而获得联邦能力：清理类工具继续要求显式指定范围，因为联邦清理意味着一个测试凭证一次抹掉主模拟 QQ 环境与全部 AI 测试空间的证据。只有模型请求详情读取补齐了跨记录域查找——它无副作用，记录标识本身唯一，要求外部测试控制器先知道记录属于哪个空间说不通。这处能力不对等是刻意的，不是遗漏。

记录域的两支都带自己的模型请求库：未归属那一支从一开始就只有记录库，场景那一支在控制服务之外也带上它。跨记录域读一条记录因此从「取记录域 → 取控制服务 → 取记录库」变成「取记录域 → 取记录库」，控制服务上取得记录库的入口只留给装配。「按记录域标识取模型请求库」也归该 module 一处提供，三种来路（主模拟 QQ 环境、AI 测试空间、未归属）在调用点收敛成一次查询，而不是按来路嵌套的条件表达式；标识不属于任何记录域时返回空值，与查找未命中同一口径。可辨识联合不变：未归属仍然没有沙盒场景、仍然不参与联邦读取，`control` 仍然只在场景那一支上，读取之外的事（等就绪、清场景）仍归它。

「谁是全部记录域」的唯一性由一条规则制架构守卫钉住：空间清单枚举与按标识取控制服务出现在同一段表达式里即报，记录域目录自身是规则的持有者。谓词按写法形状判定而不是按文件名列白名单——白名单只约束名单内的文件，会随文件数增长自动失效。纯粹把清单列给用户或外部测试控制器看（只取清单不取控制服务）与带显式范围的单记录域解析（不枚举）都不命中。

不改变 ADR-0002 的服务端状态所有权，也不改变 ADR-0043 对 AI 测试空间的隔离：该 module 不持有第二份场景，只持有「谁是全部记录域」这一答案。ADR-0074 让客户端按能力拆分端口，方向与本条相反但不矛盾——客户端始终带显式范围，联邦是服务端把多个记录域揉成一页之后才发给前端的。测试控制端点保持显式范围的依据见 ADR-0020，测试 API 的版本推进见 ADR-0028。
