# 事件类型是封闭词汇

事件流上可能出现的事件类型收成一份常量清单，它同时是 `SandboxMcpEvent.type` 的类型、`appendEvent` 的形参类型、`wait_for_event` 的取值集合，以及 `chatluna-sandbox://events` 只读资源的内容。

此前 `type` 是自由字符串，全集散在测试控制服务与工具注册表两处的 `appendEvent` 调用点上，对外只有工具描述里举的三个例子。写错一个名字既不报错也匹配不上，只能等到超时返回 `matched: false`——那与「游标之后真的没有这个事件」的观察结果完全一样，消费者据此得出的是错的结论而不是一次可重试的失败。等待类工具的默认超时是 30 秒，因此一次拼错要挂满半分钟才给出一个误导的答案。

实现侧不需要守卫扫描源码：`appendEvent` 的形参就是这个联合类型，追加未登记的类型过不了类型检查。这比稳定错误码那条守卫更强——那里的抛出点是分散的构造调用，只能靠扫描源码比对，而事件类型有唯一入口。代价是模板拼接的类型必须自己收窄：空间生命周期事件此前写成 `` `test-space.${space.status}` ``，而空间状态还有「运行中」与「用户接管」两个取值，拼出来的名字落在词汇之外，因此改成按本次调用的意图给出类型。

清单本身是对外声明的顺序，因此新增事件类型要放进它所属的那一组而不是数组末尾。与只读资源对称是刻意的：错误码与事件类型都是封闭词汇，消费者都只能从对外声明学到全集，两者因此各有一条资源路径。

封闭意味着追加一个事件类型是一次对外声明变更（`wait_for_event` 的 enum 会变）。这是可接受的代价：开放的自由字符串换来的「加事件类型不用改声明」，实际效果是消费者永远不知道有哪些类型可等。
