# HTTP 测试接口与 MCP 并列承载

测试控制端点在同一个监听器上并列提供两种协议表述：MCP Streamable HTTP 供外部 AI 客户端自动发现工具与 Schema，HTTP 测试接口供 Shell 脚本与 CI 直接调用。HTTP 表述只做协议翻译——去掉 JSON-RPC 信封与 `Accept` 协商、把稳定错误码映射成真实 HTTP 状态码、把错误信封平铺到响应体顶层，随后原样调用同一个测试控制服务，因此权限、配额、幂等、确认令牌与测试调用记录不存在第二份实现。两种表述共用监听地址、TLS、来源与 Origin 白名单及测试凭证，各自只有独立的总开关与路径；测试调用记录以协议表述字段标注来路，使同一凭证在两种表述下的调用仍可分别复盘。

插件配置页把分组的描述渲染成标题、把字段的描述渲染成字段说明，并按声明顺序渲染，因此配置面按展示分工划成三个子分组：两个端点各自只有总开关与路径，共用的门禁与配额自成一组并排在它们之后，避免共用字段视觉上挂进某一个端点的标题里。标题只写名字，「这个端点给谁用、开关控制什么」写在字段说明里，并使用用户视角的措辞而不是领域词汇。监听器接口按自己需要的字段扁平声明，与配置面的分组在插件入口处对接。

取代 ADR-0013 中「CLI 和普通 REST 暂不实现」的结论，并放宽 ADR-0030 中「监听器只提供 MCP Streamable HTTP」的限定。两种表述的默认开启状态见 ADR-0029。
